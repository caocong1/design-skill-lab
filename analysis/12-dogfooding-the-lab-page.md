# 第一次实战：用套件给自己做页面（十种方向，第二轮扩到十五种）

> 分析版本：1.1 ｜ 最后更新：2026-09-22 ｜ 覆盖来源：本仓库自身（实战记录，非来源分析）；产物为 `docs/index.html`、`docs/base.css`、`docs/app.js` 与 `docs/styles/` 下的风格文件 ｜ 版本见 `analysis/SOURCE_INDEX.md`

`analysis/11-distilled-skill-design.md` 记下的第一条自我违反是"这套 skill 从没在真实任务上跑过"。这一篇是第一条真实记录：用户要求用套件自己的方法，给仓库做一个适合自己的页面，能切换至少九种风格。它不是评测（没有对照组、评审者就是作者），但它是第一份可以核对的过程证据。

## 过程（按套件自己的流程）

**Design read**：这是一个被反复打开、用来快速找到某个设计资源的工作索引，外加一段套件导览。读者是维护者本人和来访的开发者、设计师。密集列表优先于卡片；内容在所有风格里完全相同。

**硬约束**：静态页面、无构建、离线可用；**不能用 Web 字体**——字体 CDN 在维护者的网络下不可靠，所以每一种字体气质都必须从系统字体栈里做出来；600 行的列表在每种风格下都必须可用；文字对比度达到 WCAG AA。

**选轴**（`explore-design-directions` 第 2 步）：字体气质、色彩策略、版式语法、密度、形状、层次。刻意不把"配色"单列为轴——只换配色正是套件自己禁止的"换皮方案"。

**取材**：方向不是从"流行风格列表"里挑的，而是从这个主题的世界里找的——设计参考资料馆会让人想到什么：色卡本、瑞士海报、目录学的书目、终端（skill 活在终端里）、工程蓝图、图书馆卡片柜、美术馆展签、机房控制台、贴纸墙，以及"什么都不设计"的素页。

每个方向在页面里都带一张说明卡：概念一句话、各轴取值、**以及它会在哪里失败**——这是方案板纪律的直接落地（"没有稻草人方案，但每个方案都要坦白自己的弱点"）。

**实现方式**：一套 DOM，`html[data-style]` 作用域下重写 token 并重排布局。版式差异全部用 CSS 完成（网格重排、`order`、`writing-mode`、`columns` 式卡片网格），没有为任何风格改 DOM。档位标记在不同风格里变成：方块字母、红色印章"甲乙丙"、`[S]`、零件序号圈、三点、三段电平表、圆形贴纸、纯文字。

## 渲染查看抓到了什么

全部十种风格都在 1280 宽下渲染查看；瑞士、书目、贴纸加看了 390 宽；最后做了一张缩略图拼版。看图发现并修掉的问题：

1. **贴纸风格"全部"按钮白底白字**——`li:first-child button` 的优先级压过了按下态。只读 CSS 很难发现，一看图就发现。
2. **卡片柜的蓝色横线穿过卡片标题**——重复渐变向上平铺。加了一层卡纸色的标题带盖住。
3. **切换器半透明，底下的筛选下拉框透上来像"幽灵按钮"**——改为不透明。
4. **页眉各行被说明卡的高度撑开，行距忽大忽小**——网格行改为 `auto auto auto 1fr auto`，多余高度只落在最后一行。
5. **授权信息里的长字符串不换行、被视口裁掉**（上一轮已修）。
6. 两个截图工具陷阱：无头 Chrome 继承系统深色模式；窗口宽度下限 500 px（上一轮已修进 `shot.sh`）。

机械检查：十种风格的每一对文字/背景颜色都用 `color_tools.py` 算过，全部 ≥ 4.5:1（最低的一对是终端的弱文字 5.19:1 与瑞士红 5.21:1）。

**缩略图测试**：把十张截图缩到 640 px 宽拼在一起看。如果两张缩略图分不清，它们就是同一个方向。十张一眼可辨——差异来自版式与字体，而不只是颜色。

## 套件缺了什么（已补）

- `explore-design-directions` 说方案板是"一个自包含的 HTML，token 按 `[data-direction]` 作用域"，但没说当交付物本身就是页面时，**最强的方案板就是页面自己加一个实时切换器**，也没有"缩略图测试"这个检验手段。已补。
- `typography.md` 反复说"别用默认字体"，但没给"不能用 Web 字体时怎么办"。这次实际用到了按气质分类的系统字体栈（含中文：宋体、楷体、圆体、等宽的搭配）。已补一节。
- 反套路清单提醒了我两次：首版每行的侧边色条（上一轮改掉）；以及这次刻意没有做"米色底 + 衬线 + 赤陶色"和"近黑 + 荧光绿"——书目用的是纸色 + 朱红，但它有目录学这个主题依据、有竖排题名和印章这些只属于它的东西；终端选了琥珀而不是荧光绿。是否真的躲开了套路，应该由别人来判断。

## 注意（如实记录的局限）

- **自评**：评审者就是作者，违反了套件自己"新眼光评审"的要求。没有派独立的评审上下文——上一次滥用子 agent 的教训还在，而且这一步的成本收益需要用户来定。
- **字体只在 macOS 上看过**。Windows 会落到宋体 / 楷体 / 微软雅黑 / Consolas 等，气质相近但字形不同；没有验证。
- **没有可用性验证**：十种风格里哪一种真的更好找东西，没有数据。按 design read，日常使用应该是"色卡"或"控制台"，其余更像是方向展示。
- 贴纸与控制台离各自的"套路"都只有一步（新粗野、深色发光大屏），说明卡里已经坦白。
- 同一份 DOM 限制了版式差异的上限：没有哪个方向能改变信息架构本身。

## 第二轮（2026-09-22）：两个 bug 报告与五个新方向

用户在线上看到两件事：贴纸风格的入场动画"会重复两遍"；贴纸里的中文"有的文字上下、粗细不一样"，并问这是不是故意的显示效果。两个都是真 bug，都不是效果；两个都值得记，因为它们各揭示了一个套件里没写的陷阱。

**动画播两遍。** 先按直觉查：是不是 `mount` 跑了两次、是不是两个 IntersectionObserver 观察了同一批元素（确实有——目录区被观察了两遍，但两个回调在同一个任务里触发，不会重播）。数 `animationstart` 次数：每个元素只有一次。于是改用 rAF 逐帧记录一张贴纸的计算不透明度，结果是 0 → 1 → **0** → 1：关键帧 `st-slam` 的 100% 一帧没写 `opacity`，浏览器把它从 60% 的 1 插值回元素的底层值——等待态 `.st-await` 的 `opacity: 0`——然后脚本在 `animationend` 里摘掉类名，元素再跳回 1。落地、消失、重现，肉眼就是"播了两遍"。同一处还有两个同源毛病：关键帧在 `transform` 里旋转，元素又设了 `rotate` 属性，两者叠加，落地角度是两倍再猛地弹回；hover 抖动用第二个类顶掉 `animation` 简写，抖完把 `st-slam` 露出来就等于从头重播。教训：**"看"要看对的东西**——数事件数不出插值问题，逐帧看属性值才行；这个判断已写进 `design-motion` 的反模式。

**中文字形不一致。** 圆体字体栈把 `Hiragino Maru Gothic ProN`（macOS 上的日文圆体）放在所有中文字体前面。字体按字符回落：它有的汉字全用日文字形排出来（单一字重被合成加粗），它没有的简体字（设、认、这……）漏给下一款 `Yuanti SC` / `PingFang SC`，真字重、不同基线——一行字里两种字形、两种粗细、两个基线。而这个栈正是 `typography.md`"按气质选系统字体栈"表里圆体那一行给的。教训：套件自己的参考表带着陷阱，dogfooding 抓到了它；表已改，并加了"日文字体不要排在中文伴随字体之前"的说明。

**五个新方向。** 用户要求"充分分析利用本项目的内容再多加几个奇特有意思有代表性的风格，可以单独加一个 admin 后台类的样式"。取材仍是"这个主题的世界"，但这次从**套件自己要做的事**里找：

| # | 方向 | 取材 | 字体气质 | 色彩策略 | 版式语法 | 记忆点 |
| --- | --- | --- | --- | --- | --- | --- |
| 11 | 后台 | `design-product-ui` 要设计的后台 | 系统 UI | 浅灰工作区 + 白面板 + 单一蓝 | 侧栏导航树 + 顶栏面包屑 + 数据表 | 可排序、可翻页的表；按 brief 要求做熟悉的东西并做好 |
| 12 | 画板 | 设计工具本身 | 系统 UI 11–12px | 深灰工具栏 + 浅灰点阵画布 + 选区蓝 | 图层面板 + 画布 + 属性检查器 | 蓝色选框、四角把手、尺寸标注 |
| 13 | 对话 | skill 住在对话框里；`analysis/09` 的 AI 界面模式 | 系统 UI 15px | 近白 + 一支墨绿 | 单栏线程 + 固定底部输入 | 资源成为回答里的引注 [n]，输入即搜索 |
| 14 | 字样 | `typography.md` 的字体栈表 | 十二种系统字体气质并置 | 纸白 + 墨黑 | 样张行 + 字号瀑布 | 样字 Aa/永 带度量线、轮换字体 |
| 15 | 线路图 | 导视系统；`design-graphics` | 导视人文无衬线 | 白底 + 十二条线路色 | SVG 线路图 + 竖向站点条 | 十二条线从"目录"扇出，S 首选是换乘站，列车行驶 |

后台是唯一"按要求做常规样子"的方向——`anti-slop.md` 第 6 条说 brief 要熟悉的东西时就交出它最好的版本；它的说明卡坦白"长得像每一个后台是有意的"。其余四个各自的失败点也写在卡上：画板像某个具体产品、对话找东西比列表慢、字样在字体少的系统上会有几行落到同一款、线路图是拉伸了的比喻。

**渲染查看抓到的问题（第二轮）**：后台的表头用了 `position: sticky`，但外层 `overflow-x: auto` 包裹让它以包裹层为参照，表头压住了第一行；对话里档位标签作为纵向 flex 的直接子项被拉成整行；字样的样字与度量线标签互相遮挡；线路图的列车在 `animateMotion` 开始前停在 SVG 原点，左上角多出一个黑点。机械检查：五个新方向的文字/背景对初稿有五对低于 4.5:1（画布灰底上的次级文字、选区蓝底上的白字、深色工具栏里的灰字等），全部改色后重算通过。十五个方向用同一脚本逐个挂载、进域、搜索、按 `]` 轮换，无脚本错误。

**外壳的边界**：数字键只有十个。前十个方向仍绑 1–9、0，`[` `]` 前后切换全部；此前几处直接打印 `num % 10` 的入口在编号超过十时会显示 1、2、3，已改。这是"十种方向"这个假设写死在三处的代价。
