One write, three steps, every device.

No request waits on the network. The write lands locally, Driftless merges it with whatever happened elsewhere, and the sync server passes it on.

1Your app writes to its local database.

The query commits on the device and db.watch re-renders the screen straight away, online or not.

3The sync server relays it to every device that holds the row.

Each device syncs a shape: only the rows its filter selects. Rows outside a device’s shape never reach it.

SQL you already write

An embedded database with a SQLite-compatible dialect. Most SQLite SQL runs unchanged.

Reactive queries

You don’t need Cloud to use Driftless. Cloud is the managed version of the same open-source sync server.

The catch, and other fair questions.

What to know before you move data onto the device.

Is it SQLite?

The storage engine is a fork of SQLite 3.46 with sync metadata; most SQLite SQL runs unchanged. Extensions that change the file format are not supported.

Do I need Driftless Cloud?

No. The sync server is a single open-source binary, backed by Postgres or SQLite, that you can run anywhere. Cloud is the managed version.

How big can a local database get?

Browser storage limits apply, usually a share of free disk. On native platforms the tested limit is 50 GB.

How much does it add to a web bundle?

The browser bundle is 690 KB gzipped, including the WebAssembly build that shrank by 30% in 1.4.

What happens when two people edit the same row offline?

Each column merges by hybrid logical clock. Register custom merge functions for counters, lists and rich text.

Who can read which rows?

Bring your own JWT. The sync server checks row-level rules, and each device’s shape decides which rows it syncs.

Put the database in your app.

Install the client for your platform, open a database, and point it at a sync server when you’re ready.
