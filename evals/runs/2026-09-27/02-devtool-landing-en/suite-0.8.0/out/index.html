Your app's data lives on the device first.

Driftless is an open-source SQL database that runs inside your app, in the browser, on the phone, the desktop or the server. Reads and writes are instant and work offline. Driftless keeps every copy in sync.

How a write travels

Every device holds a real copy of the rows it needs. The network is only used to keep those copies agreeing.

  1. 1

    Your app writes to its local database.The write commits on the device. No request, no spinner.

  2. 2

    Driftless records the change and merges concurrent edits per column.Merges are ordered by hybrid logical clocks.

  3. 3

    The sync server relays it to every other device that holds matching rows.Run the open-source sync server yourself, or use Driftless Cloud.

What changes when the database moves into the app

Compared with the usual setup: a server that owns the data and a cache on the client.

Server-first + cacheDriftless
ReadsServer-firstA network round trip, or a possibly stale cacheDriftlessLocal, sub-millisecond
Offline writesServer-firstUsually blocked, or a custom queue you maintainDriftlessBuilt in; pending changes survive restarts
ConflictsServer-firstHand-writtenDriftlessAutomatic per column, customisable

What you get

Runs where your app runs

An embedded database with a SQLite-compatible dialect.

  • Browser: WebAssembly + OPFS
  • iOS, Android: native library
  • Electron, Tauri
  • Node, Bun, Deno

Reactive queries

db.watch re-runs a query whenever matching rows change, whether the change was made locally or arrived through sync.

Partial sync with shapes

Each user syncs only the rows a filter selects, for example WHERE team_id = ?. Generally available in 1.4.

Your auth, your rules

Bring your own JWT. Row-level rules are checked by the sync server.

Offline is the normal case

The app keeps working without a connection, and pending changes survive restarts.

Sync you can host yourself

The Driftless Sync Server is open source: one binary, backed by Postgres or SQLite. Or let Driftless Cloud run it.

Benchmarks

An indexed read from the local database takes 0.2 ms at p50, a local write 0.8 ms. Ten thousand row changes reach a second device over throttled 4G in 1.9 s.

Setup: M3 MacBook Air, Chrome 140, OPFS; the second-device test uses a throttled 4G network profile. From the project's published benchmark page.

Questions developers ask first

Is it SQLite?

The storage engine is a fork of SQLite 3.46 with sync metadata. Most SQLite SQL runs unchanged.

Do I need Driftless Cloud?

No. The sync server is a single open-source binary you can run anywhere; Cloud is the managed version.

What happens when two people edit the same row offline?

Each column merges by hybrid logical clock. Register custom merge functions for counters, lists and rich text.

How big can a local database get?

Browser storage limits apply, usually a share of free disk. On native platforms the tested limit is 50 GB.

Before you adopt it

The trade-offs worth knowing up front.

  • 690 KB gzippedThe size of the browser bundle your users download.
  • No file-format extensionsSQLite extensions that change the file format are not supported.
  • Browser storage quotasIn the browser, the local database lives within the storage the browser grants.
