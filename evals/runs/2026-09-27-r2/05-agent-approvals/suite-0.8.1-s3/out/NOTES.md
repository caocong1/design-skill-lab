# Notes and assumptions (one per line)

- Layout: the run is a full page inside the Fernhill frame. The dark left navigation (Assistant current) and the top bar stay visible on every screen. A 332 px right rail holds run facts, permissions and the activity log.
- Order on every screen: header (request, status pill with icon and word) → the block that needs Dana (approval, error or outcome) → the 5-step plan → rail. Moment 1 has no decision, so the plan comes first, with step 3 expanded in place.
- Approval: the decision panel sits beside the payment table inside one card, so all four choices are visible in the first 900 px next to the facts they act on.
- Approval: "Approve without Oakridge" is the filled primary button and comes first; "Approve and schedule all 7" is equal size but outlined. The reason is the changed-bank-details warning. The brief's choice order was changed (reordering copy is allowed). No button is labelled "recommended".
- Approval: "Wed 30 Sep" arrival is the weekday derived from the brief's date (28 Sep 2026 is a Monday). Nothing else is computed. For example, there is no post-payment balance.
- Approval: the "Who is being asked" copy ("the run waits; it will not pay on its own if no one answers") shows the rule that no approval means nothing is paid. The brief gives no timeout, so none is shown.
- Error (separate run): step 1 is shown as done but without counts. The brief gives no step 1 numbers for that run, and repeating the other run's 52/49 would be invented.
- Error: the start time of the separate run is not given, so only "paused since 10:00:47" is shown.
- Error "Stop the run" consequence ("no matching, no payment batch, no summary") comes from the brief's statement that steps 3–5 are waiting.
- Progress: the activity log uses step labels instead of clock times because the brief gives durations, not timestamps, for steps 1–2.
- Result: per-flag action buttons (Request corrected invoice / Draft $252.00 payment, Review refund email, Mark as matched / Keep flagged, Mark as paid / Draft payment) are the brief's suggested actions turned into verbs. "Open vendor record", "View batch", "Cancel batch" and "Open audit log" are assumed standard app actions.
- Result: "Cancel batch" is shown because the brief says payments can be cancelled until 5:00 pm ET on 29 Sep.
- Disclosure: a persistent "AI" mark next to "Fernhill Assistant" in every header, plus one line in the rail. The result carries a "Prepared by Fernhill Assistant (AI)" line.
- State never relies on colour alone: each step has a distinct mark shape (filled check, ring with dot, pause bars, cross, dashed circle) and a state word. Flags carry a warning icon and a label.
- Streaming is shown as a static "Now" line with a solid caret. Nothing animates, so the static renders match.
- Type: IBM Plex Sans / IBM Plex Mono (SIL OFL) from Google Fonts, chosen for tabular figures; amounts use tabular-nums and are right-aligned. Icons are hand-drawn inline SVG (no licence needed). The Fernhill mark is a placeholder drawn for this mock.
- Colour: neutral greens for the Fernhill brand. Amber = needs you, blue = running, red = failed, green = done. Every text pair was computed at WCAG AA or better; lint.mjs floor passes (contrast, overflow, accessible names) at 1440×900 on all four files.
- Source: out/*.html are generated by src/build.mjs; PNGs by src/render.mjs (Playwright, Chrome, 1440×900, DPR 1, full page).
- Not attempted: dark theme, narrow widths, keyboard/focus states, the Edit batch flow.
- Result: the flag actions that would move money read "Draft … payment" and carry a lock icon, so they go through approval rather than paying in one click.
- Result: once step 4 is done, it shows "Approved by Dana Whitlock, 10:05:40" in place of the approval-needed tag.
- Review: a fresh critic subagent reviewed the renders and found no P0. Its one P1 (the one-click pay buttons) and five of its six P2s were fixed; the undo "where to cancel" suggestion was not taken because the brief doesn't say where cancelling happens.
