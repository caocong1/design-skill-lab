How it works

The network is off the critical path.

Your UI never waits on a round trip. Sync runs in the background.

  1. Your app writes to its local database.

    An embedded SQL database with a SQLite-compatible dialect, running inside your app. The write is local, online or not.

  2. Driftless records the change and merges concurrent edits per column.

    Concurrent edits merge column by column using hybrid logical clocks, so edits to different columns of the same row both survive. Pending changes survive restarts.

  3. The sync server relays changes to every other device that holds matching rows.

    Self-host the open-source Driftless Sync Server or use Driftless Cloud. Row-level rules are checked there against your own JWT.

FAQ

Questions, and the fine print.

Is it SQLite?

The storage engine is a fork of SQLite 3.46 with sync metadata; most SQLite SQL runs unchanged. Extensions that change the file format are not supported.

Do I need Driftless Cloud?

No. The sync server is a single open-source binary you can run anywhere; Cloud is the managed version.

How big can a local database get?

Browser storage limits apply (usually a share of free disk). On native platforms the tested limit is 50 GB.

What happens when two people edit the same row offline?

Each column merges by hybrid logical clock. Register custom merge functions for counters, lists and rich text.

Stop waiting on the network.

Install the client, open a database, write a row. Sync comes along when you connect a server.
