Your app’s data lives on the device first.

How it works

Your app never waits on the network. It talks to a real SQL database on the device; Driftless handles the rest in the background.

1

Your app writes to its local database

Reads and writes are local. The app keeps working offline, and pending changes survive restarts.

2

Driftless records and merges the change

Each change is stamped with a hybrid logical clock, so concurrent edits merge per column.

3

The sync server relays it to other devices

Only devices that hold matching rows receive the change. Run the open-source server yourself, or use Driftless Cloud.

Two people edit the same row offline. Nothing is lost.

Conflicts merge automatically per column, ordered by hybrid logical clocks. You do not hand-write conflict code.

For counters, lists and rich text, register a custom merge function.

The catch, answered

Is it SQLite?

The storage engine is a fork of SQLite 3.46 with sync metadata; most SQLite SQL runs unchanged. Extensions that change the file format are not supported.

Do I need Driftless Cloud?

No. The sync server is a single open-source binary you can run anywhere; Cloud is the managed version.

How big can a local database get?

Browser storage limits apply (usually a share of free disk). On native platforms the tested limit is 50 GB.

What happens when two people edit the same row offline?

Each column merges by hybrid logical clock; register custom merge functions for counters, lists and rich text.
