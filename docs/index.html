    skill 套件

    套件的角色是设计师：决定、出图、写规格、交接、验收；在 Flutter、鸿蒙、小程序、Tauri 等目标技术栈里实现是 coding agent 的事。画图的媒介永远是 HTML / CSS / SVG，目标平台只改变画框与惯例。入口 skill 读懂任务并路由到最少的子 skill；共享的排版、色彩、布局、反套路、渲染查看、评分量表与授权参考放在入口 skill 下。

    安装

    子 skill 之间用相对路径互相引用，所以要装就装整套。

    git clone https://github.com/caocong1/design-skill-lab
cd design-skill-lab
for d in skills/*/; do
  ln -sfn "$PWD/$d" "$HOME/.claude/skills/$(basename "$d")"
done   # Codex 用 ~/.codex/skills

    然后直接说需求

    • "用 design-studio 给设备运维后台出一套完整设计，先给三个方向让我选。"
    • "这是我们的官网，用 find-design-inspiration 找参考，告诉我首屏和导航怎么改。"
    • "给 Flutter 巡检 App 设计设备列表页，手机和平板各一版，再用 handoff-design 打包给开发。"
    • "用 critique-design 走查这个页面，给带证据和优先级的评审报告。"

    随套件附带的脚本

    color_tools.py contrast "#6b7280" "#fff"   # WCAG 比值 + APCA

    方法与局限

    目录怎么来的

    用户提供的样例站点加上按学科的调研，逐条写明"适合查什么、怎么直达、授权、档位"。存活与 agent 可达性由脚本机械核验：一次全量验链约两分钟，不消耗模型额度；重定向到其他主机会被单独列出，用来发现并购与改名。

    三个支点

    • 渲染并查看：没看过的设计只是猜测，没验证的要如实说。
    • 能算的不估：对比度与色阶由脚本计算。
    • 耐久与易腐分开：平台规格、库 API、尺寸表、"生成感"清单都带复核日期。

    已知局限

    • 这套 skill 还没有被系统评测过；这个页面是它第一次用在真实任务上。
    • 证据等级不均：排版、色彩、动效、token、图标有一手摘要；平台规范、品牌、平面、数据大屏主要来自通识。
    • 档位是单人判断；标为"未能核验"的站点是维护者网络不可达，不代表站点已下线。

    关于这十种风格

    同一份内容、同一套 DOM，十个方向在字体气质、色彩策略、版式语法、密度、形状、层次上拉开，而不是换配色。全部只用系统字体，离线和字体 CDN 不可用的网络下都能正常显示。页眉里的说明卡就是"方案板"上每个方向该带的那张卡：概念、各轴取值、以及它会在哪里失败。
