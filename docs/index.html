    skill做什么

    方法与局限

    目录怎么来的

    用户提供的样例站点加上按学科的调研，逐条写明"适合查什么、怎么直达、授权、档位"。存活与 agent 可达性由脚本机械核验：一次全量验链约两分钟，不消耗模型额度；重定向到其他主机会被单独列出，用来发现并购与改名。

    三个支点

    • 渲染并查看：没看过的设计只是猜测，没验证的要如实说。
    • 能算的不估：对比度与色阶由脚本计算。
    • 耐久与易腐分开：平台规格、库 API、尺寸表、"生成感"清单都带复核日期。

    已知局限

    • 这套 skill 还没有被评测过，没有验证集。
    • 证据等级不均：排版、色彩、动效、token、图标有一手摘要；平台规范、品牌、平面、数据大屏主要来自通识。
    • 档位是单人判断；标为"未能核验"的站点是维护者网络不可达，不代表站点已下线。
