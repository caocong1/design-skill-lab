# 08 AI 产品体验

> 元数据：更新于 2026-09-27 · 依据：shape-of-ai、openai-apps-sdk-ui、mcp-apps、a2ui、ai-labelling-law；另读 Apple HIG「Generative AI」页（https://developer.apple.com/design/human-interface-guidelines/generative-ai ，DocC JSON，2026-09-27 读取，页内变更日志最新为 2026-06-08；尚无 source 摘要）· 复核期限：2026-12-02（欧盟 AI 法案第 50(2) 条宽限期结束；欧盟指南正式通过或 A2UI v1.0 定稿时提前复核）

一句话：AI 界面的设计问题分三层——用户怎么和它打交道（交互模式），用户怎么管住它（agent 控制），它的界面由谁画、画在哪（宿主 UI 与生成式 UI）；三层之上还压着一条 2025–2026 年落地的法律义务：告诉用户这是 AI，并把生成内容标出来。

## 当前结论

1. **先选承载面，再谈模式。** 承载面有七种：行内动作（在已有内容上改写、总结、填充）、侧边副驾、完整会话、agent 运行视图（计划 → 执行 → 报告）、环境式自动（分类、排序、建议）、宿主内应用（在 Claude、ChatGPT、VS Code 等宿主里以卡片 / 全屏 / 画中画出现）、后台长任务（跑几分钟到几小时，完成后通知）。聊天不是默认答案：任务已有归属界面、输入输出已知时，表单加一个 AI 步骤胜过对话。依据：shape-of-ai #2（行内动作、自动填充等模式）、openai-apps-sdk-ui #20（“知道 / 做到 / 展示”，是对话中途进入的能力而非目的地）。业内共识 + 一手资料。
2. **六个问题比几十个模式耐久。** Shape of AI 的六族对应六个稳定问题：我怎么开始（引导，8 个模式）、我能让它做什么（提示动作，14）、我怎么调（调节，10）、我怎么保持控制（治理，13）、我凭什么信它（信任，7）、哪个是 AI（标识，5），2026-09-27 共 57 个模式。模式名与范例产品按季度变化，问题不变。依据：shape-of-ai #1–6。一手资料。
3. **缺的第七问：“它能自己做多少？”** 委托级别与渐进授权（审批历史扩大权限、后台运行、可恢复的长任务）在 Shape of AI 里只以“验证”一个模式出现。宿主协议已把“暂停 / 批准 / 取消”做成一等状态：AG-UI 有 interrupt，MCP Apps 有 `tool-cancelled`，ChatGPT 在用户批准前不把工具参数交给组件。依据：shape-of-ai #4、a2ui #16、mcp-apps #13、openai-apps-sdk-ui #16。一手资料（机制）+ 推论（第七问）。
4. **agent 控制链：计划 → 批准 → 观察 → 打断 → 撤销。** 依据：shape-of-ai #7；Apple HIG Generative AI「Inputs」节。一手资料 + 业内共识。
   - 计划：分“建议性”（写在思维流里，不打断）与“契约性”（执行前必须确认），按成本与风险选；能就地编辑而不整体重来；熟手可折叠或跳过；计划与执行必须一致，偏离了要更新或解释。
   - 批准：用用户的语言展示“将发生什么”（diff、预览、收件人、金额），不只给原始工具调用；不可逆与对外动作总是要问（Apple 同样要求避免自动执行删除、代为购买等难以撤销的动作）；超时或审批人不在即视为未批准。
   - 观察与打断：可折叠的活动行（“正在检索 3 个来源…”），随时暂停或停止；完成后报告做了什么并给结果链接，能撤销的给撤销。
5. **输出侧的 2026 更新（Apple HIG，2026-06-08）。** 在生成内容旁放编辑、撤销、重试、调整，并在用户修正生效时给出明确信号；生成过程中给具体的进度文案（“正在汇总笔记中的主要主题”，而不是“处理中…”）；可以给几个真正不同的版本供选；尽量保留不用 AI 也能完成任务的路径；反馈自愿、不打断；出错时用平实语言说明并给下一步。依据：Apple HIG Generative AI「Outputs」「Best practices」节。一手资料。
6. **宿主内 UI 已经标准化：MCP Apps。** 2026-01-26 作为首个官方 MCP 扩展稳定发布；客户端矩阵（社区维护）含 Claude、ChatGPT、VS Code Copilot、M365 Copilot、Cursor、Goose 等。依据：mcp-apps #1–15。一手资料。
   - 渲染：工具声明 `ui://` HTML 资源，宿主在沙箱 iframe 里渲染；宿主应标明沙箱界面的边界。
   - 展示模式：inline（默认）/ fullscreen / pip；组件请求模式后必须能处理宿主给回的不同模式；全屏时去掉外层圆角。
   - 尺寸：容器每个轴是固定、限高（flexible）或不限（unbounded）三种之一。
   - 主题：76 个标准 CSS 变量；`prefersBorder` 决定宿主是否画边框与背景（不写则由宿主决定，各家默认不同）。
   - 环境：要响应 `safeAreaInsets`、`platform`、`hover / touch`；默认 CSP 下远程字体、图片、脚本一律不出现，除非声明来源。
7. **ChatGPT 宿主的硬约束。** 旧称 Apps SDK，现归入“plugins”，UI 跑在 MCP Apps 桥上。依据：openai-apps-sdk-ui #1–18。一手资料。
   - inline 卡片：底部最多 2 个动作（1 主 1 次）；不做 tab、深层导航、多视图；不嵌套滚动；不复刻宿主输入框。
   - 轮播：3–8 项，每项必须有图，最多 1 个 CTA，元数据按 2 行设计（页面同时写了“2 行”和“最多 3 行”）。
   - 全屏：宿主输入框始终覆盖在上；画中画在移动端可能以全屏呈现。
   - 视觉：只用系统字体（全屏也不许自定义字体）；品牌色只上主按钮、徽标、图标；不许自定义渐变或纹样；组件里不放 logo（宿主会自动加名称与图标）；图标用单色线性。
   - 其他：状态文案 ≤ 64 字符；审批门控期间要有待定态；数字商品不得在内置界面里卖订阅或做升级引导。
8. **生成式 UI：A2UI 把交付物从“屏幕”改成“组件目录”。** v0.9.1 为当前生产版，v1.0 为候选版。依据：a2ui #1–13。一手资料。
   - 机制：agent 只发声明式 JSON，只能用客户端预先登记的组件目录（catalog），样式完全由渲染端的设计系统决定。
   - 渲染：界面树以邻接表流式到达，`root` 到达前什么都不渲染，之后渐进渲染并为未到的子节点显示占位。
   - 交付物：组件目录 + 语义变体 + 允许的父子组合 + 文案规则（v1.0 的 `instructions` 字段）+ 校验文案 + 降级态（未知组件的安全回退、整面失败时“此界面无法显示”）。
   - 归属：每个 surface 带来源名字与图标，由编排方覆盖以防冒充。
9. **选型规则。** 宿主要跨多个 agent 保持同一设计系统 → A2UI（宿主渲染，继承宿主设计系统）；服务端需要自己掌控的定制界面 → MCP Apps（iframe，代价是设计系统冲突与多余滚动条）；无论哪种，纯文本回退都必须可用（MCP Apps 协商失败时回退到工具的文本结果，OpenAI 要求“没有组件工具也要有用”）。依据：a2ui #15、mcp-apps #1、openai-apps-sdk-ui #1。一手资料 + 推论。
10. **披露是法律义务（欧盟）。** AI 法案第 50 条自 2026-08-02 适用。依据：ai-labelling-law #1–8。一手资料。
    - 义务：直接与人交互的系统要告知对方在和 AI 交互（普通人一看便知的除外），最迟在首次交互时，清晰可辨且无障碍；被问到时必须承认是 AI。
    - 不算披露：只写在条款、URL 或文档里；只有隐形水印或元数据；“助手”这类含糊称呼；可能误导的拟人形象；全站一句“本网站使用 AI”。
    - 需要周期性提醒：长会话、儿童与老人、情感陪伴、金融 / 法律 / 健康建议、**代用户行事的 agent**。
    - 日期与罚则：罚款最高 1500 万欧元或全球年营业额 3%；第 50(2) 条的机器可读标记，对 2026-08-02 前已上市的生成系统宽限至 2026-12-02；配套指南内容 2026-07-20 已批准，要等各语言版本齐备、正式通过后才适用。
11. **欧盟行为准则给出了标签的样子。** 2026-06-10 定稿、自愿签署。依据：ai-labelling-law #5、#9–13。一手资料。
    - 内容标签：主元素是大写 “AI”，可加 “generated / modified” 第二层；官方图标三种（AI、AI + GENERATED、AI + MODIFIED）× 四种变体（黑、白、50% 黑、50% 白）；带文字的图标在用户测试中表现更好。
    - 位置：图像与视频标在无遮挡处（例如右上角），转发、下载后仍可见；聊天机器人可用首轮声明、贴近输入 / 输出框的常驻徽标；只有提示音不够。
12. **中国：显式标识 + 隐式标识，2025-09-01 起施行。** 《人工智能生成合成内容标识办法》与强制性国标 GB 45438-2025。依据：ai-labelling-law #14–22。一手资料。
    - 文字要素：须含“人工智能”或“AI”，并含“生成”和 / 或“合成”。
    - 按媒介：图像在边缘或角落，文字高度 ≥ 画面最短边 5%；视频片头显示 ≥ 2 秒；语音可用“短长 短短”节奏（摩尔斯码 AI）。
    - 交互界面：在内容附近持续显示，和 / 或在界面顶部、底部、背景持续显示；附录示例是把“AI生成”（原文无空格）放在气泡脚注、在输入框下方写“以上内容由人工智能生成合成”。
    - 保留与元数据：下载、复制、导出必须保留显式标识；隐式标识是元数据里名称含 “AIGC” 的字段；用户协议要写明标识方式；应用商店上架时核验标识材料。
    - 执法：2025-11-25 已有 App 因缺标识被约谈、下架。
13. **法律压过模式库。** Shape of AI 说“AI 原生产品可能不需要标签”；但欧盟只在“显而易见”时豁免，中国对可能引起公众混淆的服务要求交互界面持续标识。因此“披露与标识规格”是 AI 产品与生成媒体的必交付物，不是可选的诚信条款。一套能同时满足两地的默认做法：输入框附近的常驻 AI 标识 + 每条生成内容的“AI 生成”脚注 + 导出文件带标识与元数据。依据：shape-of-ai #8、ai-labelling-law #1、#5、#15、#20。一手资料 + 推论。
14. **标识元素要克制。** 闪光图标与紫色渐变已是这个品类的默认，要有意选择；标识要“说出动作而不只是功能”（“已用 AI 改写”），人工接手后身份仍要延续；AI 内容可保留专用样式；拟人化头像不仅俗套，还可能被欧盟指南视为误导，不能当作披露。依据：shape-of-ai #8、ai-labelling-law #6；品类默认审美为本仓库既有观察。一手资料（披露部分）/ 业内共识（审美部分）。
15. **会话机制（保留旧结论）。** 流式输出进稳定布局，只在用户停在底部时跟随滚动并提供“回到最新”；不逐字动画；发送键在生成时变停止；失败时保留草稿；用 polite live region 分块播报，不抢焦点；区分拒答、工具失败、网络失败、限流、上下文超限，说清发生了什么、用户能做什么；原型里的示例对话用真实领域内容，并包含一条不完美的回答和一个错误态。“约 100 ms 内给出活动反馈”来自通用反馈时限，不是 AI 领域的一手资料。依据：旧分析 09 与旧 ai-ux.md（审计列为应保留项）。业内共识。

## 论证

**为什么分三层。** 交互模式回答“怎么用”，agent 控制回答“怎么管”，宿主与生成式 UI 回答“谁来画”。旧文只有第一层；而维护者做的恰恰是会执行动作的助手（网页端、桌面端、法律领域 agent），第二层是信任的来源，第三层决定了交付物的形态。把三层分开，才能在一次设计里分别检查：模式选对了吗？控制链闭合了吗？在宿主的约束里画了吗？

**宿主 UI 的状态矩阵。** 把 MCP Apps 与 ChatGPT 的消息映射成可以画出来的状态：预载 → 参数流入（只用于骨架预览）→ 结果 → 被取消（用户、错误或分类器）→ 待审批 / 被拒 → 拆除（组件应先保存）。`ui/update-model-context` 对用户不可见，所以任何会影响后续回答的选择也要在界面上可见。生成式 UI 另有“部分渲染”与“未知组件回退”两态。这些状态不画，实现者就会各自发挥。

**品牌在宿主里去哪了。** ChatGPT 禁止自定义字体、渐变与组件内 logo，MCP Apps 让宿主下发主题变量，A2UI v1.0 干脆删掉了 agent 侧的 `theme`。这与苹果“品牌色移进内容层”的规则是同一趋势：控件层归平台或宿主，品牌只能通过内容、插图、文案、数据呈现来表达。对设计师的含义是：给宿主画稿，先按宿主变量出一版“无品牌”基线，再看品牌能在哪些允许的位置出现（主按钮、徽标、图像）。

**张力与取舍。**
- 确认会增加摩擦。Shape of AI 明确把“何时阻断”当作需要校准的取舍：低风险、可撤销的动作用建议性计划，高成本、对外、不可逆的用契约性计划；“本次会话批准同类动作”只给低风险类别。
- 欧盟要求“首次交互时告知 + 对 agent 周期提醒”，又警告“横幅盲区”；中国要求“持续显示”。常驻的小标识 + 关键节点的明确提醒，比每次弹窗更能同时满足两边。
- A2UI 与 MCP Apps 并非二选一：Google 与 MCP Apps 作者 2026-06-17 的联名文章给了三种组合（MCP 服务器输出 A2UI、A2UI 组件里嵌 MCP App、MCP App 里跑 A2UI 渲染器）。设计上只需判断“样式归谁”。
- 生成式 UI 让“每一屏都精确设计”失去意义，但没有降低设计要求：约束（目录、变体、组合规则、校验、降级）要比固定屏幕写得更严，因为没有设计师在场兜底。

**相对 2026-09-21 旧文（分析 09）改了什么、为什么旧说法错。**
- 旧文把“标注生成内容”列为耐久的诚信规则，技能里也只是可选的诚实条款。**在写作当天这已经不对**：中国的标识办法与 GB 45438-2025 自 2025-09-01 施行，欧盟第 50 条在 2026-08-02 生效（旧文写于其后）。错因是只读了一个来源（Shape of AI 索引页），没有检索法规。
- 旧文没有宿主内 UI 与生成式 UI 这一层。MCP Apps 自 2026-01-26 稳定，OpenAI 的界面规则已迁到 MCP Apps 之上，A2UI 已到 v0.9.1；这些都早于旧文。
- 审计报告写“约 80 个宿主 CSS 变量”，规范原文正好 76 个；A2UI 当时记作“v0.9 为当前版”，现为 v0.9.1 生产版、v1.0 候选版，仓库迁到 `a2ui-project/a2ui`；OpenAI 的旧文档地址 `/apps-sdk/concepts/design-guidelines` 已 301 到 `/plugins/concepts/ui-guidelines`。
- 模式数量：审计报告写 61 个，本次按索引页链接计数为 57 个。以本次一手计数为准，数量本身易腐。
- 旧文仍然正确、予以保留的：先选承载面；六个问题；聊天不是默认；治理族对 agent 产品最要紧；审批用用户的语言、超时即未批准；流式与无障碍机制；原型用真实内容并含错误态。

## 未决问题

- Claude、ChatGPT、VS Code 的实际容器宽高未测，规范里的 `{width: 400, maxHeight: 600}` 只是示例；各宿主实际下发 76 个变量中的哪些未抓取；ChatGPT 的图片比例“强制执行”但未公布。
- MCP Apps 草案版新增的采样、`ui/download-file`、组件发起的拆除，哪些宿主已支持，未查。
- A2UI v1.0 的定稿日期，以及删除 `theme` 是否原样保留。
- 欧盟指南正式通过的日期；修订后的第 50 条原文（Regulation (EU) 2026/1744）未读到；欧盟官方图标的几何与最小尺寸未下载核对（准则未设最小像素）。
- GB 45438 的适用范围取决于“可能导致公众混淆或误认”，企业内部工具、法律 agent 是否落入，需要法律判断；设计默认按需要标识处理。
- 后台 / 长时 agent 的模式缺一手来源：Google PAIR Guidebook、Microsoft HAX Toolkit 未摘要；Apple HIG Generative AI 尚无 source 摘要（建议新增 id `apple-hig-generative-ai`）；Ant Design X（中文 AI 交互范式）、Vercel AI Elements、Carbon for AI 未摘要。
- Fluent 2 的 Copilot 交接模式（“创建 / 打开于 / 在…中继续 / 在…中试用”等 CTA 词汇）只见于审计报告，fluent-2 摘要未复读。
- “100 ms 活动反馈”需要 NN/g 响应时间阈值作一手来源。

## 对 skill 的约束

- `skills/design-studio/references/disciplines/ai-experience.md`（AI 体验的唯一所有者）按三层组织：
  - 承载面表（含宿主内应用与后台长任务两行）与“聊天不是默认”；
  - 六个问题 + 第七问（委托级别）作为检查清单；只复述族名与问题，不大段转述 Shape of AI（CC BY-NC-SA，本仓库是 MIT）；
  - agent 控制链与审批规则（建议性 / 契约性计划、就地编辑、计划与执行一致、用户语言、超时即未批准）；
  - 输出侧控制与具体进度文案（Apple 2026-06-08）；
  - 宿主 UI 状态矩阵与生成式 UI 的交付物清单；A2UI / MCP Apps / 纯文本的选型规则；
  - “披露与标识规格”作为 AI 产品的必交付物：欧盟首轮声明 + 常驻徽标 + 对 agent 的提醒；中国“AI 生成”类文字贴近每条输出或在界面常驻，导出保留；被问即承认；拟人形象不算披露。
