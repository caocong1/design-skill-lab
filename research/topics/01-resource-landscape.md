# 01 资源版图与目录方法

> 元数据：更新于 2026-09-27 · 依据：ui-ux-pro-max、design-md-spec、cjk-font-licensing、accessibility-law、mcp-apps、openai-apps-sdk-ui；实测：2026-09-21 两次全量验链、2026-09-27 两次独立全量探测（目录审计与候选资源调研）、2026-09-27 缩略图重拍 · 复核期限：2026-12-26

本篇回答两件事：设计师在用哪几类外部资源，每类的偏差是什么；一份给 agent 用的资源目录应该怎样建模，又怎样知道它现在还是对的。条目和计数以 `catalog/` 与生成视图为准，本文只写方法和判断。文中出现的数字都是某一天的测量，都带着日期。

## 当前结论

1. **选源的第一条轴是粒度，不是学科。** 整站气质看精选画廊，页面叙事看落地页库，单个区块看区块库，组件解剖看组件库与规范，一段流程看真实产品截图库，微交互看录屏库。粒度选错，参考再好也用不上。（业内共识；本仓库目录自 2026-09-21 起按此组织）
2. **第二条轴是真实度，第三条是易腐度。** 画廊展示设计师欣赏什么，真实产品库展示实际上线了什么，研究型来源展示被证明有效的东西，三者的结论经常相反，所以每次至少混用两类。趋势聚合以月为单位过时，档案和标准几乎不过时。（业内共识）
3. **目录是分层的数据，不是链接清单。** v2 拆成四份文件：手写事实 `resources.jsonl`、分类法 `taxonomy.json`、机器观测 `observed.jsonl`、缩略图清单 `docs/assets/thumbs/manifest.json`。`build-catalog.py` 把四份连起来，生成全部视图。脚本只写观测文件，从不改手写文件。（实测：v1 的 `check-links.py --write` 直接改写事实源，观测也没有日期；ui-ux-pro-max 的来源记录和风格生命周期是同一思路的旁证）
4. **分类法从"单亲树"改成"域 + 节 + `also` 多归属 + region/lang 维度"。** 新增 `dataviz`、`ai`、`a11y` 三个域，因为它们在 v1 里被拆散了：数据可视化散在 4 个域，无障碍散在 7 个节，AI 相关条目分在产品界面、设计工程、阅读三个域（`app-ui/ai-ux`、`code/ai-design-skills`、`reading/ai-design`）。"中文"不再是小节，改为 region 维度。（实测：2026-09-27 目录审计；accessibility-law 说明国内的适老化和无障碍是合规要求，不是可选偏好）
5. **分级 S/A/B 是维护者的判断，所以要加机械约束。** 每个域 S 档不超过 15%。S 行必须 agent 能直接抓取（`static`），或者带有 agent 能用的 `entry_points` / `api`。v1 的 S 档占 21.8%，其中 13 条 agent 打不开。（实测，2026-09-27）
6. **agent 可达性是一次观测，不是站点属性。** 每条观测都要记 `checked_at`、`http`、`final_url`。不可达不等于站点已死；被拦截也不等于可以绕过，被拦时换一个来源，或者把链接交给用户。（实测：2026-09-21 同一天跑两次，因为网络波动，不可达从 19 条涨到 48 条；到 2026-09-27，这 48 条里 43 条又能访问了）
7. **腐烂主要发生在深链和事实上，主链接还活着。** 2026-09-27 全量探测：主链接硬失效约 0.5%（3/601），抽查的深链有 3/25 返回 404。另外发现一个编造的 URL slug、一条写错的许可证（写 MIT，实为 Unlicense）、一条指向维基百科的"书"。这说明条目是凭记忆写的。修法是改结构：深链放进 `entry_points` 并逐条探测，而不是再加几条散文规则。（实测）
8. **检测器本身会误报，要当作被测对象来对待。** v1 的反爬正则把 Cloudflare 往普通页面里注入的被动脚本当成了挑战页，结果 Simple Icons（S 档、CC0、自带 CDN）被标成 `blocked`，agent 因此被告知"别去抓"。（实测）
9. **缩略图是证据，不是装饰，也要质检。** v1 的 601 条里有 104 条（17%）没有可用的缩略图：62 条没拍到，42 张拍到的是空白页、骨架屏、验证页或错误页；其中 53 条的 og:image 当天可以直接取回。v2 的顺序是：GitHub 仓库用它的社交卡；其余先截图，截图要过像素 QA（灰度标准差、边缘密度、主色占比）；截图不合格就用 og:image，og:image 也要过 QA；两者都不合格时显示设计过的占位卡。宁可不出图，也不出一张验证页。（实测）
10. **对 agent 最有价值的是"怎么直达"。** 2026-09-27 实测，以下机器端点全部可用：jsDelivr 上各图标库的原始 SVG、Iconify API、Simple Icons CDN、svgl API、Fontsource API、WebAIM 对比度 API。W3C 主站对脚本返回 403，但 `w3c.github.io` 上的 WCAG、APG、clreq 镜像返回 200。这些地址应该写进 `api` 和 `entry_points`，不该埋在 `how_to_use` 的散文里。（实测）
11. **agent 通过查询脚本加精简投影使用目录，不整份读 Markdown。** v1 为了找三四行，要读一个 1.3k 到 6k token 的域文件，而表格里恰好没有 skill 要求 agent 使用的 `kind` 列。v2 提供 `catalog.py find / show / route / recipes`，默认先按档位、再按可达性排序。UUPM 的查询纪律值得借：一个意图、2 到 5 个词、最多重试一次、查不到就直说。但它不做中文分词，本目录需要按 CJK 二元组匹配。（实测 + ui-ux-pro-max 事实 10、13）
12. **2026 年版图最大的变化，是出现了专门给 agent 用的资源。** 设计工具可以被 agent 读写（Figma MCP 的写画布功能处于 beta）；DESIGN.md 成了事实上的格式（design-md-spec）；宿主内 UI 有了标准（mcp-apps、openai-apps-sdk-ui）；参考库开始提供 MCP（Mobbin、Refero，这一点只核实到搜索结果层面）。因此 `ai` 域分三块：AI 交互模式、AI 设计工具与生成器、面向 agent 的 skill / MCP / 格式；`kind` 枚举增加 `mcp`、`skill`、`api`。（一手资料为主，参考库 MCP 未核实）
13. **授权信息必须写进条目，而且要预期它会变。** Remix Icon 在 2026-01 改了许可证。厂商的"免费商用"中文字体不是开源许可证：禁止修改，也禁止单独分发，所以子集化有风险（cjk-font-licensing 事实 10–15）。awesome-design-md 收录的品牌 DESIGN.md 是从网站提取的，知识产权仍归品牌方（design-md-spec 事实 31）。（一手资料）

## 论证

### 三条轴为什么仍然成立

v1 首版的核心判断（旧分析 01，2026-09-21）是"粒度 × 真实度 × 易腐度"，这一点经受住了审计。审计列出的 v1 结构问题也都能用这三条轴解释：数据可视化散落在 4 个域，本质是按学科分家而不是按粒度；`reading`、`general` 这两个域是按媒介划分的，同一个排版问题因此有两个去处；趋势类条目的描述里写着"now""since January 2026"之类的话，却没有日期，这是忽略了易腐度。三条轴决定了"去哪里找"。v2 的分类法和字段决定"能不能找到、能不能用"。

### v1 做对了一半：数据有了，观测没有日期

v1 的主干设计是对的：单一事实源，生成视图，再用 `--check` 挡住过期视图，v2 原样保留。问题出在"标记"这一层，判断和观测混在一起写：

- `agent_access` 和手写字段放在同一个文件里，而且没有观测日期。2026-09-21 第二次运行时，失败的抓取被写成 `unknown`，覆盖了上一次的有效观测。当天改成"抓取失败不算观测，保留上次所见"，并恢复了 34 条。原则是对的，但没有 `checked_at`，保留下来的旧值看起来就和新观测一样。审计的结论是：当天有 48 条不可达，只有 14 条标成了 `unknown`，另外 34 条保留的值并不是那天看到的。
- 中文说明放在规划目录下的批次 JSON 里（0.8.0 已删除），经由 `docs/catalog-zh.js` 进页面，没有生成脚本，也不受校验。新增一条资源，页面上就会悄悄缺中文。v2 要求每行都有 `zh`。
- `kind` 混了媒介（article、book）和用途（tool、library）两个维度；`tags` 有 665 个，其中 433 个只出现过一次，等于没有受控词表；`tier_reason` 在从调研稿迁入目录时丢了，131 个 S 档判断没有留下理由。

结论：只说"带标记的数据"还不够，**要写清楚每个字段由谁写、什么时候写的**。

### 可达性的认识论

一条可达性记录，完整的意思是：某天，从某个网络，用某种方法，看到了某个结果。本机把所有域名都解析到 198.18.0.0/15（fake-IP 代理），所以这里的"不可达"说的是代理的状态，不是站点的状态。由此得出四条规矩：

1. 失败的抓取不算观测，旧值保留，但要带上它自己的观测日期。
2. 重定向到另一个主机，是站点被收购或改名的信号，要人工看一眼。例子：Godly 跳到 Recent Design，2026-09-21 发现，2026-09-27 复核仍然成立。
3. 检测规则本身要回归测试，准备好已知的正例和反例。第 8 条结论里的误报就是教训。
4. 同一天的两次独立探测结果也不一样：目录审计记到 26 条与存量值不符，候选资源调研记到 32 条。差异来自分类器，不是来自站点。所以可达性应当看作"在某个分类器下的观测"，改分类器就要重跑全量。

截至本文写作时，`catalog/observed.jsonl` 的 601 行全部是从 v1 迁过来的值（`checked_at: 2026-09-21`，`note: migrated from v1`）。要等 v2 分类器全量跑一次，"S 档必须可达"这条校验才有资格从警告升级成错误。

### 分级要对 agent 诚实

v1 的档位不考虑可达性，生成表又只按档位排序，结果 agent 在 `web.md` 最先看到的几行都用不了。按域统计（2026-09-27）：S 档里能直接抓取的比例，`app-ui` 是 9/18，`web` 5/8，`type` 10/18，而 `reading` 14/15、`motion` 13/14。所以 v1 说"高价值来源恰恰集中在不可达的两类"，只在产品界面、网站、字体这几个域成立，不是普遍规律。付费经典书（Bringhurst、Tufte 等）是"必读"，却不是 agent 能查阅的来源。v2 给 S 档加了"agent 可用"这个门槛：书可以留在目录里，但很难再当 S。审计提过另一个方案，按"学科 × 任务"分别排档（`rank.scope`），v2 没有采用，因为按域设配额已经够用，也更简单。如果 `catalog.py route` 的黄金查询排序出错，再回头考虑。

### 缩略图：宁缺毋滥

v1 截图用的是 `waitUntil: 'commit'` 加固定等待 3.5 秒，JS 应用还没绘制就拍了；墙检测只在截图前读一次 `innerText`；不检查 HTTP 状态，所以 405、404 页面也被存了下来。v2 的采集流程（实现见 `skills/design-studio/scripts/lib/capture-core.mjs`）：先检查 HTTP 状态，再等加载、字体和懒加载图片，判断两帧是否稳定；自动处理 cookie 同意弹窗；用多个信号识别墙；在浏览器内做像素 QA，并编码为 WebP。单个站点的特殊修正记作数据，放在 `catalog/shot-overrides.json`，不写成代码分支。例如：隐藏 GoodUI 每次访问都会出现的订阅面板；tldraw 改拍 SDK 站点，因为主站打开是一张空画布；Logopedia 隐藏顶部广告位。

这条采集核心和 skill 里的 `capture.mjs` 共用一个实现（`scripts/lib/capture-core.mjs`）。给目录拍缩略图，和设计时截参考站、截宿主应用，踩的是同一批陷阱：同意弹窗、墙、懒加载、字体、状态码。维护一份实现，就只需要修一次。

### 覆盖缺口与偏差

目录审计和候选资源调研（2026-09-27）一致认为，缺口集中在以下几块：

- 中文生态：蓝湖、iconfont、MasterGo、即时设计、Pixso、墨刀；适老化与 GB/T 37668；钉钉、飞书、抖音的设计规范。
- 日韩：5 条 `ja`，0 条 `ko`；缺 jlreq 和各国公共设计系统。
- 数据可视化：缺语法库和官方风格指南（Vega-Lite、Observable Plot、Urban Institute）。
- 无障碍：没有任何测试工具（axe、WAVE、Accessibility Insights）。
- 设计工程：缺 MDN、Can I use、Storybook。
- 开放授权图像：缺 Openverse、Met Open Access API。

调研一共核实了 144 条候选，另有 41 条列为 B 名单；合并工作由目录工作流完成。有一条旧断言要降级：v1 说"国内设计导航多数是 SEO / 推广农场"，当时没有任何数据支撑，现在只算印象。

### 与同类的对照

UUPM 给风格表加了 active / supplemental / deprecated 三种状态，弃用条目附替代 id，新鲜度规则是人工核验 365 天、待复核 90 天，这支持本目录采用 `status` 和 `review_by`。但它的来源记录只覆盖 51 条，其中不少是"derived"，即引用同仓库里的另一张表，这不能算证据（ui-ux-pro-max 事实 4、8）。在设计 skill 这个领域，逐条公布"agent 能不能抓到"的目录，目前只有本仓库一家（全面审计的机制矩阵，2026-09-27）。这个字段有没有价值，完全取决于观测是否诚实。

### 2026-09-21 以来改了什么，旧观点错在哪里

- 正文里手写的计数（599、131/599、72%），不到一周就和实际数据对不上了。改为由数据生成，本文只引用带日期的测量值。
- "S 不超过总量的四分之一左右"定得太松，而且没有强制执行。改为每个域 ≤ 15%，并加上可达性门槛。
- "不可达标记为 `unknown`，不删除"：想法对，但实现会悄悄保留过期值。改为观测单独成文件，每条带日期。
- 深链写在散文里，6 天后抽查就有 12% 失效。改为结构化的 `entry_points`，逐条探测。
- 缩略图默认只拍 S 档，也不做质检。改为全部档位都拍，每张记录来源和 QA 结论。

## 未决问题

- **只有一个探测位置。** 设想过用 GitHub Actions 每周从美国再探测一次，与本地结果合并，两边的差异就是"中国大陆可用性"。这还没有实现。Google Fonts、Unsplash 这类站点在大陆是否稳定，目前没有字段表达：`region` 表示内容出自哪里，不表示在哪里能用。
- **档位理由缺失。** S 档的判断仍是一个人做的，没有写理由，也没有使用反馈。要不要给 S 行加一个 `why` 字段，没有定。
- **MCP 可达没有位置。** `agent_access` 只有 `static|js|blocked|unknown` 四个值，"通过 MCP 可达"（Mobbin MCP、Refero MCP、Figma MCP）无处表达。要不要加 `mcp` 这个值，没有定；这两个参考库 MCP 本身也只核实到搜索结果层面。
- **深链失效率只来自 25 条抽样。** 要等 `entry_points` 全部结构化、全量探测之后，才有可信的比率。
- **关系与许可证结构。** v2 没有 `relations` 字段（parent、mirror_of、supersedes），同一产品拆成多行的情况（Ant Design、ECharts、Rive 等约 12 组）只能手工合并。许可证仍是自由文本，没有 SPDX 代码，也没有"可商用 / 需署名"之类的标记，无法筛选。
- **缩略图的权利边界。** 缩略图是第三方页面缩到 800×500 的截图，只用来识别资源。站点如果要求不被截取，目前没有退出机制；要不要建，没有定。

## 对 skill 的约束

- `skills/design-studio/references/process/research.md`：写清楚以下几点。
  - 按粒度选源的对照表。
  - 真实度的四类来源（画廊、真实产品、研究、规范）至少取两类。
  - 用 `scripts/catalog.py` 查目录，不要整份读 `references/catalog/*.md`。
  - 流程是 harvest → `capture.mjs` 截参考 → contact sheet，**看过截图**再解构。
  - 遇到 `blocked` 就换源，或者把链接交给用户，不要绕过。
  - 产出是"动作 + 出处"，不是一串链接。
  - "不可达 ≠ 已死"。
- `skills/design-studio/scripts/catalog.py`：
  - 默认排序：先档位，再按可达性 `static > js > blocked > unknown`。
  - 支持 CJK 二元组匹配；查不到时明确输出"没有核实过的匹配"。
  - `recipes` 子命令列出全部机器端点，每个附一条示例请求。
- `skills/design-studio/references/catalog/README.md`（由 `build-catalog.py` 生成）：图例只写一次；说明 `agent_access` 是带日期的观测，`tier` 是维护者的判断，`status` 表示生命周期。
- `skills/design-studio/references/fundamentals/licensing.md`：条目里的 `license` / `caveats` 只是起点，交付前要回到许可证原文核对；中文字体按 cjk-font-licensing 分成三类：OFL、厂商免费商用、商业字库。
- `skills/design-studio/scripts/lib/capture-core.mjs` 与 `references/process/render-and-look.md`：缩略图和设计截图共用一套就绪判断、同意弹窗处理、墙检测和像素 QA；截到墙、空白页或错误页时，退出码必须非零。
- `.claude/skills/iterate-design-lab/SKILL.md`：
  - `add-resource`：先抓取再写。按页面实际内容写 `best_for` 和 `zh`；许可证取自许可证页面；`entry_points` 逐条探测。
  - `check-links`：只写 `observed.jsonl`；重定向到其他主机时，列出来给人工复核。
  - S 档配额和可达性由 build 校验，不靠自觉。
- `scripts/build-catalog.py`（目录工作流）：校验未知的域、节、`kind`、`status`、`region`，缺 `zh`，重复 id 或重复的规范化 URL，以及 S 档配额；"S 行没有 agent 可用路径" 这一项，在 v2 全量探测之前只报警告。
- `docs/`：页面上的计数一律从 `docs/data/catalog.json` 读取，不手写。
