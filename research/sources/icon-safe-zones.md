# Icon safe zones: Android adaptive icons, Google Play icon, W3C manifest maskable icons, HTML rel=icon, Apple touch icon

## Key facts
1. **Android adaptive icons**: "Size all layers to 108x108 dp."; "Use a logo that's at least 48x48 dp. It must not exceed 66x66 dp, because the inner 66x66 dp of the icon appears within the masked viewport."; "The outer 18 dp on each of the four sides of the layers is reserved for masking and to create visual effects such as parallax or pulsing."; "The 66x66 safe zone depicted is the area that is never clipped by a shaped mask defined by an OEM."; "The layers must not have masks or background shadows around the outline of the icon."
2. **Android theming**: "starting with Android 13 (API level 33), users can theme their adaptive icons … for apps that have a monochrome layer"; "Starting with Android 16 QPR 2, Android automatically themes app icons for apps that don't provide their own." Declared with `<adaptive-icon>` holding `<background>`, `<foreground>` and `<monochrome>`; `android:roundIcon` for launchers that apply a circular mask. The page has no legacy size table.
3. **Google Play store icon**: "Final size: 512px x 512px · Format: 32-bit PNG · Color space: sRGB · Max file size: 1024KB · Shape: Full square – Google Play dynamically handles masking. Radius will be equivalent to 30% of icon size. · Shadow: None"; legacy assets are "scaled down 75% to the keyline grid size (512 * 0.75 = 384px)".
4. **W3C manifest maskable safe zone**: "The safe zone is the area within a maskable icon which is guaranteed to always be visible… a circle with center point in the center of the icon and with a radius of 2/5 (40%) of the icon size, which means the smaller of the icon width and height"; "The user agent MUST NOT make any pixel within the safe zone transparent."; "If the icon contains transparent pixels, the user agent MUST composite the icon onto a solid fill (e.g., white)"; note: "most icons will have around 10% padding on the top, bottom, right and left". Purposes « "monochrome", "maskable", "any" », `any` the default; monochrome: "only the alpha data is used."
5. **HTML rel=icon**: "sizes keywords represent icon sizes in raw pixels (as opposed to CSS pixels)"; "The any keyword represents that the resource contains a scalable icon, e.g. as provided by an SVG image."; among equally appropriate icons "user agents must use the last one declared in tree order"; absent any icon link, user agents "may" fetch "/favicon.ico"; "shortcut icon" is historical only. **No standard prescribes a minimal set.**
6. **Apple touch icon** (archived 2016 doc): `apple-touch-icon` sizes `152x152` (iPad), `180x180` (iPhone retina), `167x167` (iPad retina); "the smallest icon larger than the recommended size is used. If there are no icons larger… the largest icon is used."
7. Secondhand, for context only: web.dev maskable article (2019-12-19) "radius equal to 40% of the icon width. The outer 10% edge might be cropped"; web.dev install criteria (2024-09-19) say Chromium requires "a 192px and a 512px icon" (a browser policy, not a standard); MDN rel (modified 2026-10-07): iOS "does not use this link type, nor the sizes attribute".
