## Key facts - the essays
1. **Great Animations**: motion should feel natural (springs recommended; an interactive stiffness/damping/mass visualiser is on the page); be fast - `ease-out`, "usually shorter than 300ms"; have a purpose (state change, explanation; consider how often it is seen); **never animate keyboard-initiated actions** (Raycast has no open animation "and it feels right"); animate `transform` and `opacity` (composite only) and use CSS or WAAPI when the main thread is busy (rAF-based Framer Motion drops frames; Vercel's dashboard tab fix was moving to CSS); be interruptible (CSS transitions retarget, keyframes do not); honour `prefers-reduced-motion` (keep an opacity-only variant); fit the product (Sonner is "a bit slower than usual" and uses `ease` for elegance); review the next day with fresh eyes.
2. **7 Practical Animation Tips**: (1) `scale(0.97)` on `:active`; (2) never animate from `scale(0)` - start at 0.9+ (demo uses 0.93) with opacity; (3) delay the first tooltip, then open neighbours with no delay and no animation (Base UI `[data-instant] { transition-duration: 0ms }`; demo tooltip 125 ms `ease-out`, start scale 0.97); (4) `ease-out` for elements entering/exiting; `ease-in` is "not made for UI" (same 300 ms feels slower); built-in CSS curves are too weak - use custom ones (easings.co); (5) origin-aware popovers - `transform-origin` from the trigger (`var(--radix-dropdown-menu-content-transform-origin)`, Base UI `var(--transform-origin)`); (6) keep it fast - 180 ms select beats 400 ms; under 300 ms; remove animation from things seen tens or hundreds of times a day; (7) last resort: `filter: blur(2px)` bridges an awkward crossfade.
3. **You Don't Need Animations**: purpose first (explain a feature - Linear's Product Intelligence animation; feedback - press scale; spatial consistency - Sonner enters and leaves the same edge so swipe-to-dismiss feels natural; delight only for rarely seen moments such as a morphing feedback button); frequency decides (hover effects on a list used all day: probably none); "sometimes the best animation is no animation".
4. **Agents with Taste**: package each "taste" decision as an explicit rule with its reason, give it to agents as a skill (he uses Anthropic's skill-creator). Its sample duration table (micro-interactions 100-150 ms, standard UI 150-250 ms, modals/drawers 200-300 ms; exits ~20 % faster than entrances; larger elements and longer travel animate slower) and sample typography rules (body ≈ 65ch, `tabular-nums` for prices, `…` character, looser tracking on uppercase labels, metric-matched fallback stack, underline only links, bold not italic for UI emphasis) are **older excerpts** - the shipped skill now says modals/drawers 200-500 ms (fact 7).

## Key facts - the skills (repo@d16ebe6)
5. **Decision order** (`animate` § The Build Sequence; `emil-design-eng` § The Animation Decision Framework): should it animate → purpose → cheapest tool → properties → easing/duration or spring → interruption and exit → reduced motion and pointer gating.
6. **Frequency gate** (`STANDARDS.md` § Should it animate): 100+ times/day (shortcuts, command palette) - no animation, ever; tens of times/day (hover, list navigation) - remove or drastically reduce; occasional (modals, drawers, toasts) - standard; rare/first-time (onboarding, celebrations) - may add delight. Valid purposes: spatial consistency, state indication, explanation, feedback, preventing a jarring change; delight only in the rare tier (`find-animation-opportunities` § The Gate). "It looks cool" is not a purpose.
7. **Durations** (`STANDARDS.md` § Duration): button press 100-160 ms; tooltips/small popovers 125-200 ms; dropdowns/selects 150-250 ms; modals/drawers 200-500 ms; marketing/explanatory can be longer; UI under 300 ms.
8. **Easing decision** (`STANDARDS.md` § Easing): entering/exiting → `ease-out`; moving/morphing on screen → `ease-in-out`; hover/colour → `ease`; constant motion (marquee, progress) → `linear`; default `ease-out`; never `ease-in` on UI. Custom curves: `--ease-out: cubic-bezier(0.23, 1, 0.32, 1)`; `--ease-in-out: cubic-bezier(0.77, 0, 0.175, 1)`; `--ease-drawer: cubic-bezier(0.32, 0.72, 0, 1)` (iOS-like, from Ionic). Take other curves from easing.dev / easings.co rather than hand-rolling.
9. **Physicality** (`STANDARDS.md` § Physicality): enter from `scale(0.9-0.97)` + `opacity: 0`, never `scale(0)`; press feedback `scale(0.97)` with `transition: transform 160ms ease-out` (range 0.95-0.98); popovers scale from the trigger, **modals are exempt** (stay centred).
10. **Springs** (`STANDARDS.md` § Springs): for drag with momentum, "alive" elements, interruptible gestures, decorative pointer-following; Apple-style `{ duration, bounce }` is easier to reason about than mass/stiffness/damping; keep bounce 0.1-0.3 and avoid it in most UI (drag-to-dismiss and playful moments only); springs keep velocity when interrupted.
11. **Tool ladder** (`animate` § 3): CSS transition (state you control) → CSS `@starting-style` (entry without JS) → CSS animation (predetermined, must stay smooth under load) → WAAPI (programmatic, CSS performance) → Motion (springs, layout, exit, gesture-driven values). A toast/drawer/command menu is a component, not an animation: use a library (`pick-ui-library`).
12. **Properties and performance** (`animate` § 4, `STANDARDS.md` § Performance): `transform` and `opacity` only; `clip-path` is the sanctioned fourth; `height` tolerated only for accordions; `translate` percentages are relative to the element; Motion `x`/`y`/`scale` shorthands are not hardware-accelerated - use a full `transform` string; never drive child transforms through a CSS variable on the parent (restyles every child); blur under 20 px (expensive in Safari).
13. **Interruptibility and timing** (`STANDARDS.md`): transitions over keyframes for anything triggered rapidly; `@starting-style` for entry (fallback: `data-mounted` after mount); asymmetric timing - slow where the user decides (hold-to-delete 2 s `linear`), fast where the system responds (release 200 ms `ease-out`); stagger 30-80 ms between items, never block interaction during a stagger.
14. **Gestures** (`STANDARDS.md` § Gestures & drag): dismiss on velocity (`|distance| / ms > ~0.11`), not only distance; damping and friction past boundaries instead of hard stops; pointer capture once dragging; ignore extra touch points mid-drag.
15. **Accessibility and pointer gating** (`STANDARDS.md` § Accessibility): reduced motion means fewer and gentler animations, not zero - keep opacity/colour, drop movement; gate hover motion behind `@media (hover: hover) and (pointer: fine)`.
16. **Review format** (`emil-design-eng` § Review Format (Required)): findings are one markdown table `| Before | After | Why |`, never "Before:/After:" lists. `review-animations` "defaults to flagging; approval is earned" and is `disable-model-invocation: true` (manual only).
17. **Agent-workflow patterns**: `improve-animations` is read-only - recon → parallel audit → vet/prioritise → self-contained plans other (cheaper) agents execute; `find-animation-opportunities` must also report **rejected candidates**; `prototype` builds 3-5 variants that each differ on a **named axis** (layout, density, personality, motion, interaction model), every variant fully works with realistic content, the picker chrome is copied verbatim and is "not a contestant", production code is untouched until one is promoted, then the prototype surface is deleted; `animation-vocabulary` is a reverse glossary from a felt description to a term ("the bouncy thing when a popover opens" → Pop in).
18. **Adjacent skills** (headings only): `apple-design` (WWDC-derived: response, 1:1 direct manipulation, interruptibility, velocity hand-off, momentum projection, rubber-banding; quick-reference default UI spring = damping 1.0, response 0.3-0.4 s); `mobile-native` (web-on-phone fixes: sticky hover → hover media query, tap flash, `100dvh`/`100svh`, inputs ≥ 16 px to stop zoom, `touch-action: manipulation`, `overscroll-behavior`, `viewport-fit=cover` + safe-area insets, per-scheme `theme-color`, test on real hardware).

## What it changes for the skills
- skills/design-studio/references/disciplines/motion.md: adopt the frequency gate and the purpose list as step 1-2 of any motion decision; never animate keyboard-initiated or 100+/day actions; reduced motion = fewer/gentler, not none; gate hover motion to fine pointers.
- skills/design-studio/references/disciplines/motion-tokens.md: carry the duration table (fact 7) and the three custom curves as the brand-neutral web defaults, labelled "Emil Kowalski skills @d16ebe6"; state the exit-faster rule; bounce 0.1-0.3 only for drag/playful moments (contrast with Material's expressive scheme in `material-motion-tokens`).
- skills/critique-design/references/heuristics.md and templates/critique-report.md: the Before | After | Why table is the review row format; `transition: all`, `scale(0)` entries, `ease-in` on UI, centre-origin popovers, >300 ms UI motion, keyframes on rapidly triggered elements are checkable items.
- skills/design-studio/scripts/lint.mjs: `transition: all`, `scale(0)` keyframes, `ease-in` on enter/exit, animated `width/height/top/left/margin/padding`, hover rules outside a hover/pointer media query are detectable in CSS.
- skills/design-studio/references/process/directions.md: the prototype rules (named axis per variant, every variant works, neutral picker chrome, delete after promotion) fit a live options board.
- skills/implement-design/references/stacks.md: tool ladder (fact 11) and the Motion full-transform-string caveat.
