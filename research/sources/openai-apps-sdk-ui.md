## Key facts
1. **Renaming.** The docs now live under "Plugins" (skills + MCP server + optional UI) and one directory is shared by ChatGPT and Codex; "Apps SDK" survives in package names and image paths. UI is explicitly optional: "Keep the MCP tools useful without a component" (chatgpt-ui.md#overview).
2. **UI runs on the open MCP Apps standard.** ChatGPT renders the component in an iframe and talks to it over the MCP Apps `ui/*` JSON-RPC bridge; `window.openai` is now only for ChatGPT-only extras (checkout, file upload/select, host modals, widget state) plus legacy compatibility aliases (`toolInput`, `toolOutput`, `callTool`, `sendFollowUpMessage`) kept for existing integrations. New UI should use `_meta.ui.resourceUri`, not the legacy alias `_meta["openai/outputTemplate"]` (chatgpt-ui.md#prefer-shared-fields-and-methods). See digest `mcp-apps`.
3. **Four display modes** (ui-guidelines.md#display-modes): inline card, inline carousel, fullscreen, picture-in-picture (PiP). "Every app initially appears inline"; inline surfaces "currently always appear before the generated model response". Inline anatomy = app name + icon label → widget → short model follow-up that should not repeat the card.
4. **Inline card** (#inline-card): single action/decision, small structured data, or a self-contained widget. Parts: optional title, Expand (to fullscreen), Show more, edit controls, **primary actions limited to two, placed at the bottom** — "one primary CTA and one optional secondary CTA"; each action performs a conversation turn or a tool call. Height may grow to fit content "up to the height of the mobile display area". Edits persist.
5. **Inline card prohibitions** (#rules-of-thumb): no deep navigation, tabs, multiple drill-ins or multiple views inside a card; **no nested scrolling** (cards auto-fit, no internal scroll); **no duplicate inputs** ("Don't replicate ChatGPT features in a card"; a card-internal chat composer is the obvious case, though the page does not name it).
6. **Inline carousel** (#inline-carousel): **3–8 items**; every item has an image or visual; title usually; metadata limited — the layout list says "Avoid showing more than two lines of text", the rules-of-thumb say "three lines max" (the page contradicts itself; design for 2); optional badge; **at most one optional CTA per item** (e.g. "Book", "Play"); consistent hierarchy across cards.
7. **Fullscreen** (#fullscreen): for rich multi-step tasks (map with pins, editing canvas, interactive diagram, detailed browsing). Chrome = system close + content + **ChatGPT's own composer, always overlaid**; the composer "shimmers" while a response streams; a truncated response snippet appears above the composer and opens the chat sheet. Rule: design the UX to work with the system composer. Existing editors/admin UIs may be embedded only under the iframe policy (#8 below).
8. **PiP** (#picture-in-picture-pip): persistent floating window for parallel/live activity (game, quiz, live collaboration, video). On scroll it sticks to the top of the display area; stays until dismissed or the session ends, then returns inline and scrolls away. Rules: must react to composer input; close automatically when the session ends; do not overload with controls or static content. Reference: "On mobile, picture-in-picture may be presented as fullscreen" (reference.md#request-another-presentation-mode).
9. **Colour** (#color): system colours for text, icons, dividers; brand accents (logos, icons, badges) must not override backgrounds or text colours; **no custom gradients or patterns**; brand accent colour is allowed on **primary buttons** inside display modes; do not colour text-area backgrounds.
10. **Typography** (#typography): inherit the platform system stack ("SF Pro on iOS, a sans-serif font on Android"); **"Don't use custom fonts, even in full screen modes"**; bold/italic/highlight only inside content, never for structural UI; limit size variation, prefer body and body-small.
11. **Spacing, icons, imagery** (#spacing--layout, #icons--imagery): system grid spacing for cards/collections/inspector panels; consistent padding, no edge-to-edge text; respect system corner radii; hierarchy = headline → supporting text → CTA. Icons: system icons or custom icons that are **monochromatic and outlined**. **Do not put your logo in the response** — ChatGPT always prepends logo + app name. Images must follow enforced aspect ratios (no ratios are published).
12. **Accessibility** (#accessibility): WCAG AA contrast, alt text on every image, layouts survive text resizing.
13. **Host signals the UI can read** (reference.md#capabilities): `theme`, `displayMode`, `maxHeight`, `safeArea`, `view`, `userAgent`, `locale`; `notifyIntrinsicHeight` reports height "to avoid scroll clipping"; `requestDisplayMode`, `requestModal` (host-owned modal), `requestClose`, `setOpenInAppUrl` (target of fullscreen's open-in-app). Host mirrors locale to `document.documentElement.lang` (chatgpt-ui.md#widget-localization). Host mirrors iframe navigation history into its own controls (reference.md#host-backed-navigation).
14. **Declared modes**: `_meta["openai/ui"].availableDisplayModes` ∈ `inline | fullscreen | pip` on the resource lets a fullscreen-only component open directly "without showing an inline loading state first" (reference.md#declare-display-modes-before-the-ui-loads).
15. **Status copy limits**: `openai/toolInvocation/invoking` and `.../invoked` strings **≤ 64 chars** (e.g. "Searching…" / "Results ready") (reference.md tool `_meta` table).
16. **Approval-gated tools**: tool arguments are not delivered to the widget until the user approves; design an empty/pending state for that gap (reference.md#windowopenai-component-bridge).
17. **Iframe / CSP policy** (app-guidelines.md#iframes-and-embedded-pages; chatgpt-ui.md#content-security-policy-csp): nested frames blocked by default; pages from the MCP server's own registrable domain (e.g. `app.example.com` for a server at `api.example.com`) may be framed, including full editors/admin UIs; separate tenants on a shared host count as different domains; third-party frames "should be limited to cases where the embedded experience is essential". Every frame origin is declared in `_meta.ui.csp.frameDomains` (legacy `_meta["openai/widgetCSP"].frame_domains`) and needs a written justification at submission; sharing the server's domain does not guarantee approval. `connectDomains` / `resourceDomains` must list exact origins. `_meta.ui.domain` (dedicated origin) is required for submission.
18. **Commerce and content policy that shapes screens** (app-guidelines.md#commerce-and-monetization): physical goods only; no subscription plans, upgrade prompts or links that start checkout for digital goods (may explain a feature is unavailable on the user's plan and link to an informational page); **no advertisements**; external checkout on the merchant's own domain is "the required approach" (Instant Checkout is a beta limited to select marketplace partners; no other third-party checkout may be embedded); audience must be suitable for 13–17. Destructive/write tools need confirmation friction.
19. **State placement** (chatgpt-ui.md#manage-state): business data on the server; ephemeral UI state (selection, expanded panel, sort) in the widget; durable preferences on your server. Avoid `localStorage` for core state. Treat the resource URI as a cache key — breaking UI change = new URI; a backward-compatible content update may be served from the same URI without resubmission, but "ChatGPT may continue serving cached resource contents for up to one hour" (deploy/app-review.md).
20. **Product framing** (blog): a ChatGPT app is a capability entered mid-conversation, not a destination — "know / do / show"; pick a few "specific powers" instead of porting screens; checklist includes handling vague and specific prompts and showing value on the first turn.
21. **`@openai/apps-sdk-ui` tokens** (repo@0f00143): type scale heading-5xl 72/72 … heading-lg 24/28, heading-md 20/26, heading-sm 18/26, heading-xs 16/24 (weight 600); text-lg 18/29, **text-md 16/24, text-sm 14/20**, text-xs 12/18, text-2xs 10/14, text-3xs 8/12 (weight 400). Radii 2, 4, 6, 8, 10, 12, 16, 20, 24 px + full. Spacing unit 4 px. Control sizes 22–48 px (md 32, 2xl 44). Font stack starts `ui-sans-serif, -apple-system, system-ui, "Segoe UI", "Noto Sans"`. Breakpoints xs 380, sm 576, md 768, lg 1024, xl 1280, 2xl 1536 (mobile-first). Dark mode via `data-theme` on `<html>`, nestable. Requires React 18/19 + Tailwind 4; built on Radix. A Figma community library exists (file 1625636989296445101).

## What it changes for the skills
- skills/design-studio/references/platforms/embedded-hosts.md: add a "ChatGPT (plugins UI)" host row: 4 modes with their limits (≤2 bottom actions per card, 3–8 carousel items, ≤1 CTA per item, 2-line metadata, no nested scroll, no tabs/drill-ins, no duplicate composer), composer always overlaid in fullscreen, PiP behaviour, system font only, brand colour only on primary buttons/badges/logos, no gradients, no logo in the widget, monochrome outlined icons.
- skills/design-studio/references/disciplines/ai-experience.md: hosted-UI surface = "capability entered mid-conversation" (know/do/show); pending state for approval-gated tool input; follow-up text must not duplicate the card; status strings ≤64 chars.
- skills/design-studio/references/process/system.md: when targeting ChatGPT, the system of record is the host (inherit tokens); the 4 px unit, radius and type scale above are the reference values for mockups; `data-theme` light/dark.
- skills/design-studio/assets/mockup-kit/kit.json: ChatGPT inline card / carousel / fullscreen-with-composer frames using the sourced type scale and breakpoints.
- skills/design-studio/references/process/handoff.md: hosted-widget handoff lists display modes, CSP domains, resource URI version, and which tools are render vs data tools.
- skills/critique-design/references/heuristics.md: mechanical checks for hosted widgets (action count, carousel count, internal scroll, custom font, logo in widget, gradient use).
- skills/implement-design/references/stacks.md: implement against the MCP Apps bridge first; `window.openai` only behind feature detection.
