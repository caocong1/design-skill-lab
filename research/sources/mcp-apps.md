## Key facts
1. **Status and lineage.** "MCP Apps is now live as the first official MCP extension" (blog, 2026-01-26), built with MCP-UI and OpenAI (Apps SDK) maintainers; the spec says both "significantly informed the design". Extension id `io.modelcontextprotocol/ui`; `ui://` scheme reserved (apps.mdx#reservations-in-mcp). Optional; negotiated per connection; hosts without it fall back to the tool's text result (apps.mdx#resource-discovery).
2. **Declaration.** A tool points to its UI with `_meta.ui.resourceUri: "ui://..."`; the resource is served by `resources/read` with MIME **`text/html;profile=mcp-app`** as a valid HTML5 document (`text` or base64 `blob`) (apps.mdx#ui-resource-format). Resources are predeclared (not inlined in tool results) so hosts can prefetch, cache and review them (apps.mdx#1-predeclared-resources-vs-inline-embedding). Flat `_meta["ui/resourceUri"]` is deprecated.
3. **Tool visibility.** `_meta.ui.visibility` defaults to `["model","app"]`; `["app"]` hides a tool from the model (e.g. a Refresh button's tool); app-only tools cannot be called across servers (apps.mdx#visibility).
4. **Resource `_meta.ui` fields**: `csp` {`connectDomains`, `resourceDomains` (wildcard subdomains allowed), `frameDomains`, `baseUriDomains`}; `permissions` {`camera`, `microphone`, `geolocation`, `clipboardWrite`} (hosts MAY grant; apps must feature-detect); `domain` (dedicated sandbox origin, host-specific format, e.g. `{hash}.claudemcpcontent.com`, `www-example-com.oaiusercontent.com`); **`prefersBorder`** — `true` = host draws visible border + background, `false` = none, omitted = host decides ("hosts' defaults may vary", so set it explicitly).
5. **Default CSP if none declared** (apps.mdx#host-behavior): `default-src 'none'; script-src 'self' 'unsafe-inline'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; media-src 'self' data:; connect-src 'none'`. Hosts must not loosen it; nested iframes `frame-src 'none'` unless declared; `object-src 'none'` always. Design consequence: remote fonts, images and CDN scripts appear only if their origins are declared.
6. **Sandbox.** All views render in sandboxed iframes; web hosts must use a separate-origin sandbox proxy (double iframe) with `allow-scripts` + `allow-same-origin` (apps.mdx#sandbox-proxy). The draft spec states direct downloads are blocked in the iframe (`allow-downloads` not set) and adds host-mediated `ui/download-file` (host SHOULD confirm); the stable text does not mention downloads.
7. **Host context** delivered on `ui/initialize` (apps.mdx#host-context-in-mcpuiinitializeresult): `theme` (`light|dark`), `styles.variables`, `styles.css.fonts`, `displayMode`, `availableDisplayModes`, `containerDimensions`, `locale` (BCP 47), `timeZone` (IANA), `userAgent`, `platform` (`web|desktop|mobile`), `deviceCapabilities` {`touch`, `hover`}, `safeAreaInsets` {top, right, bottom, left} px, `toolInfo`. Changes arrive as partial `ui/notifications/host-context-changed` (theme toggle, mode change, orientation, panel resize).
8. **Container dimensions** (apps.mdx#container-dimensions): each axis is **fixed** (`height`/`width` → fill it), **flexible** (`maxHeight`/`maxWidth` → content decides up to the max) or **unbounded** (omitted). Example host value: `{ "width": 400, "maxHeight": 600 }` (an example, not a norm). Flexible hosts MUST resize the iframe on `ui/notifications/size-changed`; the SDK sends it via ResizeObserver by default. `containerDimensions` replaced `viewport` in SDK 0.3.0.
9. **Display modes** (apps.mdx#display-modes): `inline` (default, in the content flow), `fullscreen` (takes the screen/window), `pip` (floating overlay). The view declares `appCapabilities.availableDisplayModes`; the host declares its own; the view requests with `ui/request-display-mode` and MUST handle getting a different mode back. Pattern: remove the container's border radius in fullscreen (`border-radius: var(--border-radius-lg)` → `0`) (patterns.md#entering--exiting-fullscreen).
10. **Theming: exactly 76 standard CSS variables** (apps.mdx#current-standardized-variables; same list in draft): background ×10 (`primary, secondary, tertiary, inverse, ghost, info, danger, success, warning, disabled`), text ×10 (same roles), border ×10, ring ×7 (`primary, secondary, inverse, info, danger, success, warning`), `--font-sans`, `--font-mono`, weights ×4 (`normal, medium, semibold, bold`), `--font-text-{xs,sm,md,lg}-size` and `-line-height`, `--font-heading-{xs,sm,md,lg,xl,2xl,3xl}-size` and `-line-height`, `--border-radius-{xs,sm,md,lg,xl,full}`, `--border-width-regular`, `--shadow-{hairline,sm,md,lg}`. Colour names follow `--color-{background|text|border|ring}-{role}`.
11. **Theming rules**: hosts may pass any subset (partial colour sets can clash); hosts should express values with CSS **`light-dark()`**; views "should set default fallback values" for every variable they use (SHOULD-level, not MUST) and can apply host values with `applyHostStyleVariables` / `applyDocumentTheme`. **Spacing is intentionally not themed** ("layouts break when spacing varies"), and there is **no shared component library** (apps.mdx#4-host-theming-via-css-variables). Custom host fonts arrive as `@font-face`/`@import` text in `styles.css.fonts` (e.g. Claude's example `--font-sans: "Anthropic Sans, sans-serif"`).
12. **Safe areas and input**: apply `safeAreaInsets` as padding (notches, rounded corners, system UI overlays) (patterns.md#adapting-to-host-context). The spec exposes `deviceCapabilities` {`touch`, `hover`} but gives no guidance on using it; switching off hover-only affordances when `hover` is false is this digest's inference.
13. **Messages that create interaction states** (apps.mdx#requests-view--host): `ui/message` (post a user-role message; host MAY ask consent), `ui/open-link` (may be denied: "Link opening denied by user"), `ui/update-model-context` (silent context for later turns; each call overwrites the last), `tools/call` via host (host MAY require user approval). Host→view: `tool-input-partial` (0..n, "healed" partial JSON — use only for preview/skeleton UI), `tool-input` (once), `tool-result`, **`tool-cancelled`** (user action, sampling error, classifier intervention), `ui/resource-teardown` (a request, not a notification: host SHOULD wait for the view's response "to prevent data loss", so the view saves before it goes). Draft adds view-initiated `ui/notifications/request-teardown` (e.g. a "Done" button) and sampling.
14. **Security UX duty on hosts**: "UI can still display misleading content. Hosts should clearly indicate sandboxed UI boundaries"; hosts SHOULD warn when a UI needs external domains (apps.mdx#other-risks, #4-content-security-policy-enforcement).
15. **Client support** (client matrix, community-maintained, read 2026-09-27): Claude (web), Claude Desktop, VS Code GitHub Copilot, Microsoft 365 Copilot, Goose, Postman, MCPJam, ChatGPT, Cursor, Archestra.AI, PostHog Code.
16. **Performance patterns** (patterns.md): pause animation/WebGL/polling offscreen with IntersectionObserver; stream partial input into skeletons; persist recoverable view state (page, camera) keyed by a server-issued `viewUUID`.
17. **MCP-UI today** (README@2b10490): `@mcp-ui/*` packages implement the MCP Apps standard; "`@mcp-ui/client` is the recommended SDK for MCP Apps Hosts" and renders MCP Apps views with `AppRenderer`; `UIResourceRenderer` remains for legacy MCP-UI hosts that embed resources in tool results, and the README still documents raw HTML, external URL and remote-DOM resources on that legacy path. The MCP Apps MVP itself supports only raw HTML (`text/html;profile=mcp-app`); external URLs and other content types are explicitly deferred (apps.mdx#3-support-raw-html-content-type, #extensibility).

## What it changes for the skills
- skills/design-studio/references/platforms/embedded-hosts.md: "MCP Apps host" posture: design every widget for three dimension modes (fixed / max / unbounded) and three display modes; set `prefersBorder` deliberately (bordered card vs borderless bleed); honour `safeAreaInsets`, `platform`, `hover/touch`; fullscreen drops the outer radius; external assets only from declared origins; show host-drawn boundary.
- skills/design-studio/references/process/system.md: a hosted widget's tokens map onto the 76 host variables (bg/text/border/ring × roles, type sizes, radii, shadows) with local fallbacks in `light-dark()`; spacing stays the app's own. Provide a mapping table from DESIGN.md roles to `--color-*` names.
- skills/design-studio/references/disciplines/ai-experience.md: state matrix for hosted UI = preloading → streaming input (skeleton from partial args) → result → cancelled → approval pending/denied → teardown; model-context updates are invisible to the user, so any consequential selection should also be visible.
- skills/design-studio/templates/tokens.css: optional block of host-variable fallbacks for embedded targets.
- skills/critique-design/references/heuristics.md: check widget at host width, with host dark theme, with missing variables (fallback path), in fullscreen and pip.
- skills/implement-design/references/stacks.md: MCP Apps SDK (`@modelcontextprotocol/ext-apps`, `App`, `applyHostStyleVariables`, `applyHostFonts`), `@mcp-ui/client` for hosts.
