## Key facts
1. **Keyboard and focus** (README § Interactions): all flows keyboard-operable per WAI-ARIA APG; visible, unobscured focus rings, `:focus-visible` over `:focus`, `:focus-within` for groups; sticky headers/footers/overlays never cover the focused element; manage focus (trap, move, return).
2. **Targets**: hit target matches the visual target; visuals < 24 px get a hit area ≥ **24 px**; on mobile the minimum is **44 px**. Checkbox/radio label and control share one hit target (§ Forms).
3. **Inputs**: mobile `<input>` font ≥ **16 px** to stop iOS Safari zoom; never disable zoom; never block paste; inputs keep focus and value after hydration.
4. **Loading**: loading buttons keep their label and add an indicator; spinners/skeletons get a show-delay of **~150-300 ms** and a minimum visible time of **~300-500 ms** (React `<Suspense>` does this); skeletons mirror final layout.
5. **State and navigation**: persist state in the URL (filters, tabs, pagination, expanded panels - "anytime `useState` is used"); Back/Forward restores scroll; links are `<a>`/`<Link>`, never buttons or divs; optimistic updates with rollback or Undo; destructive actions need confirmation or an Undo window.
6. **Small interaction rules**: ellipsis on menu items that open a follow-up ("Rename…") and on in-progress states ("Saving…"); `touch-action: manipulation`; deliberate `-webkit-tap-highlight-color`; `overscroll-behavior: contain` in modals/drawers; first tooltip in a group delayed, peers instant; autofocus the single primary input on desktop, rarely on mobile; no dead zones; while dragging disable selection and apply `inert`; every drag/swipe/pinch has a click and keyboard alternative unless essential; polite `aria-live` for toasts and validation; locale-aware shortcuts with platform symbols.
7. **Animation** (§ Animations): honour `prefers-reduced-motion`; prefer CSS > WAAPI > JS libraries; animate `transform`/`opacity`, avoid `width/height/top/left`; animate only to clarify cause and effect or for deliberate delight; easing fits what changes; interruptible; no autoplay beyond muted non-essential loops, and motion > **5 s** beside content needs pause/stop/hide; correct `transform-origin`; never `transition: all`; SVG transforms on a `<g>` with `transform-box: fill-box; transform-origin: center`.
8. **Layout**: optical alignment (±1 px); everything aligns deliberately; balance icon/text weight in lockups; verify mobile, laptop, ultra-wide (zoom to 50 %); safe-area insets; no accidental scrollbars (test with macOS "show scroll bars: always"); let flex/grid size things, not JS measurement.
9. **Content and accessibility**: inline help before tooltips; accurate `<title>`; no dead ends; design empty, sparse, dense and error states; curly quotes; avoid widows/orphans; `tabular-nums` for comparisons; status never by colour alone; icon-only buttons named; "don't ship the schema" (visual layouts may omit labels, accessible names stay); native semantics before ARIA; hierarchical headings and a skip link; `scroll-margin-top` on anchors; captions/transcripts for meaningful media; layouts survive short, average and very long user content; locale-aware formats; language from `Accept-Language` / `navigator.languages`, never IP/GPS; `translate="no"` on brand names and code tokens; non-breaking spaces in `10 MB`, `⌘ + K`, product names.
10. **Forms** (§ Forms): Enter submits a single-control form; in `<textarea>` ⌘/Ctrl+Enter submits; every control labelled and label-activatable; submit stays enabled until the request starts, then disabled with spinner and an idempotency key; don't pre-disable submit, don't block keystrokes - accept and validate; errors inline, focus the first on submit; `autocomplete`, meaningful `name`, correct `type`/`inputmode`; spellcheck off for emails, codes, usernames; placeholders are example values ending with `…`; warn on unsaved changes; password-manager and one-time-code friendly, but don't trigger password managers on non-auth fields; trim trailing whitespace from text replacements; set `background-color` and `color` on native `<select>` (Windows dark-mode bug).
11. **Performance** (§ Performance): test iOS Low Power Mode and macOS Safari; profile with CPU/network throttling and without extensions; mutations (`POST/PATCH/DELETE`) < **500 ms**; virtualise large lists (command.md: > 50 items; `virtua` or `content-visibility: auto`); no layout reads in render; preload only above-the-fold images, explicit image dimensions; preconnect asset origins; preload critical fonts and subset them (`unicode-range`, limit variable axes); move long tasks to workers; `<video autoplay muted loop playsinline>` over GIF, with an H.264 MP4 `<picture>` source for Safari gated by reduced motion.
12. **Visual design** (§ Design): shadows ≥ 2 layers (ambient + direct); combine borders and shadows, semi-transparent borders for crisp edges; nested radii concentric, child ≤ parent; on tinted backgrounds tint borders, shadows and text toward that hue; colour-blind-friendly charts; interaction states increase contrast; **"Prefer APCA over WCAG 2"** for perceptual contrast; `theme-color` matches the page background; `color-scheme: dark` on `<html>` in dark themes; animate a wrapper, not text nodes (anti-aliasing shifts); avoid gradient banding from CSS masks.
13. **Vercel-specific** (§ Vercel-specific, "not universal"): Title Case (Chicago) for headings and buttons, sentence case on marketing pages; `&` over "and"; second person; numerals for counts; currency with 0 or 2 decimals consistently; errors say how to fix; specific button labels ("Save API Key", not "Continue").
14. **Agent integration**: `command.md` regroups the rules for review (Accessibility, Focus States, Forms, Animation, Typography, Content Handling, Images, Performance, Navigation & State, Touch & Interaction, Safe Areas & Layout, **Dark Mode & Theming**, **Locale & i18n**, **Hydration Safety**, Hover & Interactive States, Content & Copy) plus an **Anti-patterns** list, and prescribes terse output grouped by file in `file:line - finding` form, "✓ pass" for clean files, no preamble. Extra concrete checks there: `text-wrap: balance`/`pretty` on headings, `min-w-0` on flex children for truncation, `Intl.DateTimeFormat` / `Intl.NumberFormat` instead of hard-coded formats. The `web-design-guidelines` skill fetches `command.md` from `main` **at every review**.

## What it changes for the skills
- skills/critique-design/references/heuristics.md: adopt the command.md categories and anti-pattern list as the web mechanical floor; keep a dated snapshot and follow Vercel's pattern of re-fetching perishable rules at review time when the network allows.
- skills/design-studio/scripts/lint.mjs: `transition: all`, `outline: none` without replacement, `user-scalable=no`/`maximum-scale=1`, images without dimensions, icon buttons without names, inputs without labels, `<div onClick>` navigation, hard-coded date/number formats and GIFs where video fits are detectable (all from the command.md anti-pattern list).
- skills/design-studio/references/disciplines/product-ui.md: loading timing (150-300 ms delay, 300-500 ms minimum), URL-as-state, optimistic UI + Undo, form submission rules, "design empty/sparse/dense/error states".
- skills/design-studio/references/fundamentals/accessibility.md: 24 px / 44 px targets, focus visibility, reduced motion, 5-s autoplay limit; report WCAG 2 ratios as the legal reference and APCA alongside, not instead (see `wcag-22`, `accessibility-law`).
- skills/implement-design/references/stacks.md: hydration safety, `Intl.*`, `color-scheme`, native `<select>` colours, video-over-GIF.
