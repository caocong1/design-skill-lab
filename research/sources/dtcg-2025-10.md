## Key facts
**Status**
1. TR list: **2025.10 "Stable", published 2025-10-28**. Earlier editors' drafts are dated 2025-07-21, 2022-06-14 and 2021-09-23, and a "Preview" row is marked Experimental. There is no newer stable release as of 2026-11-01. The preview at `/TR/drafts/` is still headed "Draft Community Group Report, **08 September 2026**". It has the same module structure and says not to implement it or cite it as authoritative.
2. Every module header reads "Final Community Group Report, 28 October 2025". The Status section says it is **not a W3C Standard nor on the Standards Track** and that it was "published by the DTCG as a Candidate Recommendation". It also says: "This specification is considered stable. Further updates will be provided in superseding specifications." The release has three modules: Format, Color and Resolver (`/tr/2025.10/#x1-modules`).
3. The announcement (w3.org/community/design-tokens, 2025-10-28) names **Style Dictionary, Tokens Studio and Terrazzo** as reference implementations. It says "more than 10" tools already support or are implementing the spec, including Penpot, Figma, Sketch, Framer, Knapsack, Supernova and zeroheight. A CG post of 2026-06-17 ("Thank you, Jina and Val") names Figma, Penpot, Sketch, Tokens Studio, Style Dictionary and Terrazzo as supporting the spec, and the designtokens.org homepage lists 23 "Trusted by leading design tools" names (Adobe, Figma, Framer, Penpot, Sketch, Style Dictionary, Supernova, Terrazzo, Tokens Studio, Zeplin, zeroheight among them). There is no implementation-report page; the CG README says tools "can use the date as a version number to signify compliance".

**Format module** (https://www.designtokens.org/tr/2025.10/format/)
4. A token file is JSON. Its media type SHOULD be `application/design-tokens+json` and MAY be `application/json`; tools MUST accept both (`#x4-1`). The recommended extensions are `.tokens` and `.tokens.json` (`#x4-2`).
5. **A token is any object that has `$value`**, and its key is the token's name. Names are case-sensitive, and tools MAY warn about names that differ only in case. Names MUST NOT start with `$` or contain `{`, `}` or `.` (`#x5-1-1`). An object that has both `$value` and children is an error (`#x6-1`).
6. Token properties: `$value` (required); `$type`; `$description` (plain string); `$extensions`; `$deprecated` (`#x5-2`). `$extensions` holds vendor-keyed data, with reverse-domain keys recommended. Tools MUST preserve extension data they do not understand when they save, and teams SHOULD keep that data to non-essential metadata. `$deprecated` takes `true`, a reason string, or `false` (which overrides a deprecated group).
7. **Type resolution** runs in this order: an explicit `$type`; else, if the value is an alias, the type of the referenced token; else the nearest ancestor group's `$type`; else the token is **invalid**. Tools MUST NOT guess a type from the value (`#x5-2-2`). Section 6.7.3 restates the precedence without the alias step and adds the `$type` of a group after `$extends` has been resolved, before the parent groups (`#x6-7-3`).
8. Group properties are `$description`, `$type` (the default for descendants), `$extends`, `$deprecated` (cascades to children) and `$extensions`. Groups carry no meaning, and tools SHOULD NOT infer a type or purpose from a group. Empty groups are allowed (`#x6`, `#x6-3`, `#x6-5`).
9. **`$root`** is a reserved token name that gives a group a base value next to its variants. It is referenced as `{color.accent.$root}`; `{color.accent}` is invalid because it points at a group (`#x6-2`, `#x6-7-2`).
10. **`$extends`** makes a group inherit another group, e.g. `"$extends": "{button}"`. It MUST NOT target a token and is sugar for JSON Schema 2020-12 `$ref`. The merge is deep: a local token at the same path replaces the inherited token **whole**, not property by property. Circular chains are errors (`#x6-4`, `#x6-4-3`, `#x6-4-4`). Inside a group, tokens resolve in this order: local tokens, then `$root`, then extended tokens, then nested groups (`#x6-7-1`).
11. **References.** Curly braces `{group.token}` target complete tokens only and always resolve to `$value`; this is the primary syntax. JSON Pointer through `$ref` (RFC 6901) is **required support** for tools (`#x7-1-2`). `{"$ref":"#/colors/blue/$value"}` is equivalent to `{colors.blue}`, and `#/colors/blue/$value/components/0` reaches a single colour component. Escape `~` as `~0` and `/` as `~1`. Curly braces cannot index arrays (`#x7-4-1`, `#x7-5-2`). Section 6.6 still says tools "MAY" support JSON Pointer, which contradicts 6.6.2 and 7.1.2 ("MUST").
12. **Property-level references work only with JSON Pointer**: a colour component, a dimension's `value` or `unit`, or a typography sub-property such as a shared `fontFamily` or `lineHeight` (`#x7-3-1`..`#x7-3-3`).
13. Chained aliases are allowed. A cycle makes every token in the chain an error. Section 7.2 says tools SHOULD keep references, resolve them only when a value is needed, and propagate changes to aliases; the tool-author checklist in 7.5.1 lists the same three behaviours under MUST (`#x7-2-2`, `#x7-2-3`, `#x7-5-1`).
14. **Types.** The schema's tokenType enum has 13 values. Simple types: `color`, `dimension`, `fontFamily`, `fontWeight`, `duration`, `cubicBezier`, `number`. Composite types: `strokeStyle`, `border`, `transition`, `shadow`, `gradient`, `typography` (`#x8`, `#x9`).
15. **`dimension`** is `{value, unit}`, where unit is only `"px"` or `"rem"` and is required even when the value is 0. `px` corresponds to Android dp and iOS pt. `1rem` is 100% of the default font size, or 16sp on Android. On platforms without rem, tools may do a lossy conversion, usually assuming 16px (`#x8-2-1`).
16. **`fontFamily`** is a string or an ordered array, most to least preferred (`#x8-3`). **`fontWeight`** is a number from 1 to 1000 or one of these aliases (`#x8-4`):
    - 100: thin, hairline
    - 200: extra-light, ultra-light
    - 300: light
    - 400: normal, regular, book
    - 500: medium
    - 600: semi-bold, demi-bold
    - 700: bold
    - 800: extra-bold, ultra-bold
    - 900: black, heavy
    - 950: extra-black, ultra-black

    Any other string, including a different letter case, MUST be rejected.
17. **`duration`** is `{value, unit}` with unit `ms` or `s` (`#x8-5`). **`cubicBezier`** is `[P1x, P1y, P2x, P2y]`, with x values in [0, 1] and y values unbounded (`#x8-6`). **`number`** is a plain JSON number, used for things like unitless line height or gradient stop positions (`#x8-7`).
18. **Composite types** (`#x9-3`..`#x9-8`). All listed fields are required unless marked optional.
    - `strokeStyle`: either a keyword (solid, dashed, dotted, double, groove, ridge, outset, inset) or `{dashArray, lineCap: round|butt|square}`.
    - `border`: `{color, width, style}`.
    - `transition`: `{duration, delay, timingFunction}`.
    - `shadow`: an object `{color, offsetX, offsetY, blur, spread, inset?}`, or an **array** of them for layered shadows. References inside the array resolve to single shadows and are never flattened.
    - `gradient`: an array of `{color, position}`, with position clamped to [0, 1]. The gradient kind (linear, radial, conic) is **unspecified** (Issue 101).
    - `typography`: `{fontFamily, fontSize, fontWeight, letterSpacing, lineHeight}`. The schema requires **all five**, and `lineHeight` is a number that multiplies `fontSize`.
19. **The spec does not define these** (`#x8-8` lists them only as likely future types): font style, percentage or ratio (e.g. opacity), and file or asset. It also has **no spring, string or boolean type**. `transition` cannot say which property animates or what the start and end states are (Issue 103).
20. **`$schema` in a token file is not part of the Format spec.** The official schema does allow the property, but its own comment says "$schema is not part of the official DTCG specification", and the spec's editor's note in `#x4-2` says the group is "currently exploring the addition of a JSON Schema". The older digest (`dtcg-design-tokens-format`) presented it as spec. In a resolver file, by contrast, `$schema` is defined as optional (`resolver/#x4-4`).

**Color module** (https://www.designtokens.org/tr/2025.10/color/)
21. The `$value` object has these fields (`#x4-1`); the schema forbids any others:
    - `colorSpace` (required).
    - `components` (required): an array of numbers or `"none"`.
    - `alpha` (optional): 0 to 1, default 1.
    - `hex` (optional): a fallback that MUST be **6-digit** CSS hex; transparency lives in `alpha`.
22. There are **14 colour spaces**, with these component ranges (`#x4-2`):
    - `srgb`, `srgb-linear`, `display-p3`, `a98-rgb`, `prophoto-rgb`, `rec2020`: R, G and B each in [0, 1].
    - `xyz-d65`, `xyz-d50`: X, Y and Z each in [0, 1].
    - `hsl`: H in [0, 360), S and L in [0, 100]. `hwb`: H in [0, 360), W and B in [0, 100].
    - `lab`: L in [0, 100]; a and b unbounded, in practice ±160.
    - `lch`: L in [0, 100]; C unbounded, in practice ≤ 230; H in [0, 360).
    - `oklab`: **L in [0, 1]**; a and b unbounded, in practice ±0.5.
    - `oklch`: **L in [0, 1]** (not a percentage); C unbounded, in practice ≤ 0.5; H in [0, 360).

    Where CSS Color 4 allows both a plain number and a percentage, the spec uses the plain number.
23. `"none"` marks a missing component, for example the hue of white. Interpolation treats `none` differently from 0 (`#x4-1-1`).
24. Gamut mapping and interpolation are **non-normative**, and translation tools MAY choose their own algorithms. Authors are told to check converted output (`#x5`, `#x6`). CSS Color 4 is the conceptual reference, but the spec says this is "not an endorsement of CSS as a default implementation".
25. Naming guidance (non-normative, `#x7`):
    - Use three tiers: base, alias and component tokens.
    - Number ordered scales in steps of 100 rather than 1, 2, 3; neutrals may use steps of 25 at the light end.
    - Name alias tokens category-first, e.g. `color.background.error`, and avoid abbreviations ("background", not "bg").
    - Component tokens start with the component's name.

**Resolver module** (https://www.designtokens.org/tr/2025.10/resolver/)
26. The module expresses alternate values for different contexts without combinatorial explosion (`#x1`). Its examples are theming (light, dark, high contrast), sizing (mobile, tablet, desktop) and accessibility modes (reduced motion, colour-blindness).
27. A resolver file is standard JSON; tools MAY accept JSONC or JSON5 if it converts losslessly. Its extension SHOULD be **`.resolver.json`**, and over HTTP it SHOULD be sent as **`application/json`**. Users SHOULD NOT use a custom or unexpected MIME type, which differs from token files (`#x3`).
28. Root keys (`#x4-1`; the schema sets `additionalProperties: false` and requires `version` and `resolutionOrder`):
    - `name` (optional).
    - **`version` (required, MUST be `"2025.10"`)**. This is the resolver schema version, not your design system's version.
    - `description` (optional).
    - `sets` and `modifiers` (both optional).
    - **`resolutionOrder` (required)**.
    - `$schema` (optional): `https://www.designtokens.org/schemas/2025.10/resolver.json`.
    - The schema also permits a root `$defs` (see fact 34); the spec's root table does not list it.
29. A **set** is `{sources: [...], description?}`. Sources are `{"$ref": "file.json"}` objects, inline token trees, or a mix. When the same token appears more than once, the later source wins, and tools MUST respect array order (`#x4-1-4`).
30. A **modifier** is `{contexts: {<name>: [sources]}, description?, default?}` (`#x4-1-5`).
    - It SHOULD have at least 2 contexts. Tools SHOULD error when there is only 1 and MUST error when there are none.
    - `default` MUST be one of the context keys.
    - A context may reference a set, but MUST NOT reference a modifier.
    - An empty context array is legal, e.g. `"false": []` for a debug flag.
    - The spec's example `theme` modifier has the contexts light, lightHighContrast, dark and darkHighContrast.
31. The number of permutations is the product of all context counts: 2 × 2 = 4, and 4 × 3 × 2 = 24 (`#x4-1-5-4`).
32. **`resolutionOrder`** is an array of `{"$ref":"#/sets/x"}` or `{"$ref":"#/modifiers/y"}`, or of inline items that carry `name` and `type: "set" | "modifier"`. Later items override earlier ones, and names must be unique within the array. Only `resolutionOrder` may reference a modifier, and nothing may point into `#/resolutionOrder/…` (`#x4-1-6`, `#x4-2-1`).
33. A reference object is a `$ref` holding a JSON Pointer. Tools MUST support same-document pointers. Relative files, `file.json#fragment` and remote URLs are optional for each tool. Keys placed next to a `$ref` override its target shallowly (`#x4-2`, `#x4-2-2`).
34. Sets and modifiers may carry `$extensions` (`#x4-3`). **`$defs` is undefined behaviour**: tools MAY support it, MUST NOT error on it, and must ignore it otherwise (`#x4-5`).
35. **Inputs** are a JSON object that maps each modifier to a context string, e.g. `{"theme":"dark","size":"large"}` (`#x5`, `#x6-1`).
    - Values MUST be strings; `{"beta": true}` is an error.
    - Inputs SHOULD be case-insensitive.
    - A missing modifier that has no default is an error, and so are unknown modifiers and invalid contexts.
36. **Resolution runs in four stages, in this order** (`#x6`):
    1. Validate the input.
    2. Walk `resolutionOrder`: flatten each set and, for each modifier, only the selected context, with the last occurrence winning.
    3. Resolve aliases. Aliases MUST NOT be resolved before this point, so a theme file may alias tokens defined in another file.
    4. Produce the result.

    Conforming tools must keep token properties such as `$extensions` through the whole process (`#x8`).
37. **Orthogonality** (non-normative, `#x2-1`, `#x4-1-6-2`): modifiers should touch disjoint tokens, so their order does not matter. A `theme` and a `brand` modifier that both set `color.button` is the spec's example of non-orthogonal modifiers. Needing many sets after the modifiers is described as a smell.
38. Bundling into one file (non-normative, `#x7`) can be done by inlining files, which duplicates their contents, or by using `$defs` with `/` in file names escaped as `~1`.
39. **Errata in the spec's examples** (do not copy):
    - Resolver Examples 14 and 17 write `"context"`, but the normative key is **`contexts`**.
    - The table under Resolver Example 6 lists `theme/light-high-contrast.json`, a file the resolver never declares.
    - Format Example 12 uses `"$type": "string"`, which is not a spec type.

**Tool support (perishable; checked 2026-09-27)**
40. **Style Dictionary 5.7.1** (npm latest, 2026-10-24; repo `style-dictionary/style-dictionary` CHANGELOG.md at `3815256`, 2026-10-28):
    - 5.3.0 (2026-02-09) adds DTCG object colours to the colour transforms, covering all 14 spaces, plus new `color/oklch`, `color/oklab`, `color/p3` and `color/lch` transforms; when `hex` is present it is the fallback for colours outside sRGB. 5.3.2 supports shadow `inset: true`. 5.4.0 (2026-03-22) accepts object dimensions in all built-in transforms.
    - 5.6.0 (2026-10-03) fixes `outputReferences` emitting a raw `{group.$root}` (#1754, reported 2026-09-25); 5.6.1 (2026-10-10) `sortByReference` warnings.
    - **5.7.0 (2026-10-16) adds the 2025.10 `duration` object value**: `time/seconds` matches `duration` tokens and `transition/css/shorthand` stringifies `duration` and `delay` (output changes: `500` → `0.5s`, not `0.50s`; `1000` → `1s`); name transforms ignore a trailing `$root` segment (`--color-text-warning`, not `-root`). 5.7.1 (2026-10-24) is a prototype-pollution fix.
    - **Still no resolver support.** Tracking issue #1590 "Support for DTCG v2025.10" is open (last update 2026-10-12): a 2026-09-29 comment picks up Duration and says "Not touching gradient or resolver"; the 2026-08-28 and 2026-09-18 resolver-config proposals have not shipped. The docs still say the 2025.10 format "does not have full support yet in Style Dictionary". The changelog has no entry for `$extends` or JSON Pointer `$ref`. `@tokens-studio/sd-transforms` stays at 2.0.3.
41. **Terrazzo** (`@terrazzo/cli` 2.10.0, 2026-10-21; repo `terrazzoapp/terrazzo` at `519ee07`):
    - 2.0.0 (2026-03-17): "Full support for the DTCG v2025.10 spec, including resolvers". Object colour, dimension and duration syntax is required by default; older draft syntax errors unless the relevant lint rules are relaxed. Typography needs all five properties. First-class JSON `$ref`, local and remote, and `$deprecated` on groups. Three non-standard types: link, boolean and string.
    - 2.4.0 adds orthogonality detection to the resolver API (except `$extends`); 2.7.0 fixes nested `$root` aliases and 2.7.1 alias merging in resolver permutations; 2.8.0 (2026-10-13) aligns `core/valid-font-weight` with 1–1000 and keeps the Figma variable `key` in `$extensions["figma.com"]`; 2.9.0 (2026-10-14) lets shadow tokens take lists of aliases; 2.10.0 adds token-set operations.
    - The CSS plugin takes `permutations: [{input: {theme: "dark"}, prepare: (css) => …}]`. Legacy `$extensions.mode` maps onto a pseudo-modifier called `tzMode`. The resolver guide says `version` "has only one possible value: `2025.10`" and recommends **one modifier per token-type family** to keep modifiers orthogonal: colour with gradient and shadow; dimension with typography; duration with cubicBezier and transition.
    - `tz import <figma-url> --output x.resolver.json` imports Figma Variables and Styles; Variables need a Figma Enterprise plan and the scope `file_variables:read`.
    - The docs homepage still says resolver support is "coming in 2.0!", which its own 2.0.0 changelog contradicts; trust the changelog.
42. **Tokens Studio for Figma** (plugin 2.13.2, 2026-10-23):
    - The `$`-prefixed DTCG format has been opt-in since 2.0.0 (2024-08-13) and, per the release notes, the default since 2.11.0 (2026-02-04). The docs page "Token format" still describes the legacy format as the default and the DTCG types as coming "in future releases"; which is current was not resolved from the plugin (the docs page is probably stale).
    - Open issue #3236 (last update 2025-03-18) lists gaps: DTCG mode still writes Tokens Studio types (`spacing`, `sizing`, `borderRadius`, `boxShadow`, plural font types) and **string dimensions**.
    - `duration`, `cubicBezier` and `transition` shipped in 2.12.1 (PR #3969, merged 2026-09-21); its `transition` adds a non-spec optional `property` and makes `delay` optional, where the spec requires `delay`. 2.13.0 (2026-10-06): extended collections, variable opacity via composed colours, a free plan. **2.13.1 (2026-10-22) imports Figma TIMING and EASING variables as `duration` and `cubicBezier`** and keeps font weights unitless.
    - No resolver support appears in any release note. `@tokens-studio/sd-transforms` 2.0.3 (2025-12-10) remains the bridge into Style Dictionary.
43. **Figma native variables** (Help Center "Modes for variables", article 15343816063383, updated 2026-10-30; re-read 2026-11-01, content as below):
    - Import requires DTCG JSON, and each imported file becomes one mode. Import only creates variables for tokens present in every file with the same supported type.
    - Supported type mappings:
      - `color`: sRGB and HSL spaces only, becomes a Color variable.
      - `dimension`: **px only**, becomes a Number.
      - `fontFamily`: a single string only (no arrays), becomes a String.
      - `duration`: **s only**, becomes a Number.
      - `number`: becomes a Number, or a Boolean when `$extensions` contains `{"com.figma.type":"boolean"}`.
      - A non-standard `$type: "string"` is also accepted (the example file uses it).
    - Cross-collection aliases use `com.figma.aliasData` with targetVariableID, targetVariableSetID, targetVariableSetName and targetVariableName.
    - Names are normalised from `a.b.c` to `a/b/c`, and when two collide, the first one wins.
    - Export: "Export mode" on one mode, or "Export modes" on a collection, writes a JSON file.
    - Modes are available on the Professional, Education, Organization, Government and Enterprise plans. No resolver file and no composite types are listed.

## What it changes for the skills
- skills/design-studio/references/process/system.md:
  - State that DTCG 2025.10 is stable and consists of Format, Color and Resolver, and that **theme families and modes are expressed as a `.resolver.json`**, not in `$extensions`.
  - Teach sets versus modifiers, the `default` key, string inputs, the four resolution stages, and orthogonality (one modifier per concern or type family).
  - Add `$root`, `$extends` and JSON-Pointer property references, the `.tokens.json` extension and the media type.
  - Include a toolchain table with dated versions: Terrazzo ≥ 2.0 for resolvers; Style Dictionary ≥ 5.3 for colours and ≥ 5.4 for dimensions, with no resolver support (resolve outside SD, one run per permutation); Figma import takes one file per mode, px and s only, and no composite types.
- skills/design-studio/templates/tokens.resolver.json:
  - It must validate against the resolver schema: `version: "2025.10"`, `resolutionOrder` present, `contexts` (plural), `default` equal to a context key, and no root keys beyond name, version, description, sets, modifiers, resolutionOrder and `$schema` (the schema also tolerates `$defs`, but its behaviour is undefined, so leave it out).
  - Model a `theme` modifier (light, dark and the high-contrast pairs) and a separate `density` modifier, both orthogonal.
- skills/design-studio/references/fundamentals/color.md:
  - Colour tokens use `colorSpace`, `components` and `alpha`, plus an optional 6-digit `hex` fallback.
  - OKLCH L runs from 0 to 1, not as a percentage. Exporters choose their own gamut mapping, so check the sRGB fallbacks.
- skills/design-studio/references/disciplines/motion-tokens.md:
  - DTCG has `duration`, `cubicBezier` and `transition` (duration, delay and timingFunction are all required) but **no spring type**.
  - Springs go in `$extensions`, under a reverse-domain key, or in paired number tokens. Say that `transition` cannot name the property or the states.
- skills/design-studio/references/process/handoff.md: A handoff ships `*.tokens.json` together with `*.resolver.json`, and states which spec version and which toolchain versions the files target.
- skills/design-studio/references/platforms/README.md: A DTCG `px` means dp on Android and pt on iOS, and `rem` means 16sp on Android. Converting rem to px where the platform lacks rem is lossy (16px assumed).
- skills/implement-design/references/stacks.md: Name the build path: Terrazzo resolver plus permutations; or Style Dictionary 5.5 plus an external resolver step; or sd-transforms when the source is Tokens Studio.
