## Key facts — Office Add-ins
1. Design language: "Consider using Fluent UI for the web"; React → Fluent UI React ("we recommend migrating to Fluent UI v9"); non-React → Fabric Core 11.0.0 CSS; "Favor content over chrome"; "An add-in is not a destination".
2. **Task pane sizes** "with the Office app ribbon at a 1366x768 resolution": Excel 350×378 px, PowerPoint 348×391, Word 329×445, Outlook on the web 320×570; "Task panes range from 320 px (Outlook on the web) to 350 px (Excel)".
3. Personality menu: Windows 12×32 px; Mac 26×26 px placed 8 px from the right and 6 px from the top; "Reserve the top-right 40x40 px space"; "Position right-aligned commands at least 40 px from the top-right corner".
4. Layout: "Use 20 pixels as the default margin for HTML containers"; "Keep padding between elements at multiples of 4 pixels. Office interfaces use a 4 px grid." Navigation: a command bar from ≥ 4 sections with "44x44 px touch targets"; a tab bar for 2–4 sections ("Two tabs: ~160-185px each. Three tabs: ~106-123px each. Four tabs: ~80-92px each", "20x20px icons", labels "up to twelve characters"); back button "at least 32x32px, but 44x44px is recommended"; ≥ 8 sections → "Reconsider information architecture".
5. **Dialogs**: "By default, the dialog box occupies 80% of the height and width of the device screen"; "The effective maximum is 99.5%"; HTTPS and the same full domain; `displayInIframe: true` on the web; "Don't use window.open"; one dialog per host page.
6. **Commands**: icons "You must provide image files for 16, 32, and 80 pixels, while five other sizes are also supported (20, 24, 40, 48, and 64 pixels)"; labels max 64 characters (≤ 16 recommended); ribbon limits "Seven visible tabs", "Six groups", "Seven commands", "70 visible commands"; a function command's runtime closes "when either the function completes or 5 minutes have passed"; contextual tabs are Excel-only (RibbonApi 1.2 + SharedRuntime 1.1).
7. Icons: Monoline ribbon icons at 16, 20, 24, 32, 40, 48, 64, 80, 96 px ("absolutely required sizes are 16 px, 20 px, and 32 px"; 1 px line up to 32 px, 2 px for 40–80, 3 px at 96; "Orange is intentionally not included"); the Microsoft 365 acquisition icon is 192 × 192 px "within the 120 x 120 safe area", no rounded corners (added at runtime), 4.5:1; outline icon 32 × 32.
8. Type, colour, motion: Fabric classes Hero 28 px, Title 21 px Light ("matches the task pane title"), Subtitle 17, Body 14, Caption 11, Annotation 10 px Semibold; "4.5:1 contrast ratio"; "test it with all four Office themes, including the Use system setting option"; motion: no "anticipations, bounces, rubber band, or other effects that emulate natural world physics".
9. **Theme API** `Office.context.officeTheme`: `bodyBackgroundColor`, `bodyForegroundColor`, `controlBackgroundColor`, `controlForegroundColor`, `isDarkTheme`, `themeId`, `fluentThemeData` ("only supported on the Excel, PowerPoint, and Word desktop clients for Windows"); Outlook "starting in Mailbox requirement set 1.14", where `isDarkTheme` / `themeId` "isn't supported"; `OfficeThemeChanged` "can only be handled in a task pane". **No dedicated dark-mode design page exists** (every guessed URL returned 404).
10. Outlook: "maximum of five notifications per message" (one on mobile), key ≤ 32 characters; mobile margins Android 16 px / iOS "15px (8% of screen)"; palette `#0075DA` actions, `#E63237` errors; "Stack a maximum of two actions". Accessibility: WCAG 2.2; test Windows contrast themes "Aquatic, Desert, Dusk, and Night sky". Keyboard shortcuts must include a modifier, recommended "Ctrl+Shift+Alt+x".

## Key facts — VS Code UX Guidelines (1.144)
11. **Webviews**: "webviews should only be used if you absolutely need them". Do: "Only use webviews when absolutely necessary", "Activate your extension only when contextually appropriate", "Open webviews only for the active window", "Ensure all elements in the view are themeable", "Use command actions in the toolbar and in the view". Don't: "Use for promotions (upgrades, sponsors, etc.)", "Use for wizards", "Open on every window", "Open on extension updates (ask via a Notification instead)", "Add functionality that is unrelated to the editor or workspace", "Repeat existing functionality (Welcome page, Settings, configuration, etc.)". API: `webview.html` "should always be a complete HTML document"; scripts off by default; `localResourceRoots` / `asWebviewUri`; CSP `default-src 'none'` plus `${webview.cspSource}`; `acquireVsCodeApi` "can only be invoked once per session"; prefer `getState` / `setState` over `retainContextWhenHidden` ("high memory overhead").
12. **Theming**: body classes `vscode-light`, `vscode-dark`, `vscode-high-contrast`; colours as `--vscode-*` variables ("replace the `.` with `-`", e.g. `var(--vscode-editor-foreground)`); fonts `--vscode-editor-font-family/-weight/-size`; `body[data-vscode-theme-id]`; `vscode-using-screen-reader` and `vscode-reduce-motion` classes.
13. **Icons**: view-container icons "Icons should be 24x24 and centered", single colour, SVG; state opacity Default 60 % / Hover 100 % / Active 100 %; command icons "16x16 with a 1 pixel padding (image is 14x14) and centered"; Codicons via `$(iconId)`.
14. **Containers**: sidebar "3-5 is a comfortable max for most screen sizes" views, "A single View Container … is generally enough"; the Secondary Sidebar: "extensions cannot contribute Views directly to it by default, users can drag Views"; the Panel is for views that "benefit from more horizontal space", not for always-visible views; Activity Bar: don't "Use an Activity Bar item to open a Webview Panel"; Views: "Add an icon to every View"; tree items: don't "Add more than three actions to an item".
15. **Notifications, status bar, quick picks, settings**: "Add a **Do not show again** option for every notification", "Show one notification at a time", no promotion, no first-install feedback asks; progress notification "as a last resort"; modal dialogs only for immediate user interaction; status bar: left is workspace-wide, right is contextual, no custom colours, warning and error backgrounds "only as a last resort"; quick picks "aren't well suited to function as a wizard"; command names without emojis; settings: don't "Create your own settings page/webview". The Webview UI Toolkit repo is archived (last push 2024-09-24), "deprecated on January 1, 2025".

## Key facts — Chrome extensions
16. **Side panel**: "Chrome 114+ · browser.* since Chrome 148 · MV3+"; permission `"sidePanel"`; manifest `"side_panel": {"default_path": "sidepanel.html"}`; per-tab `sidePanel.setOptions({tabId, path, enabled})`; `setPanelBehavior({ openPanelOnActionClick: true })` "Defaults to false"; `sidePanel.open()` (116+) "may only be called in response to a user action"; `close()` 141+, `getLayout()` → `"left"|"right"` 140+, `onOpened` 141+, `onClosed` 142+; "users can specify which side the panel should be displayed on"; "Users will see Chrome's built-in side panels first… If no icons are included, it will show a placeholder icon with the first letter of the extension's name." **No page states a side-panel width or minimum width.**
17. **Popup and icons**: "The popup's size must be between 25x25 and 800x600 pixels"; "Popups automatically close when the user focuses on some portion of the browser outside of the popup. There is no way to keep the popup open". The action icon "must be 16 device-independent pixels (DIPs) wide and tall" (`default_icon` 16 / 24 / 32); manifest icons 16 / 32 / 48 / 128 ("SVG files are not supported for any icons declared in the manifest"); the store icon is a 128 px PNG with "96x96" artwork and "16 pixels per side … transparent padding"; uploads without alpha get a "12-pixel corner radius"; quality guideline: persistent UIs must "actively enhance the user's current task while causing minimal distractions".

## What it changes for the skills
- skills/design-studio/references/platforms/embedded-hosts.md: the Office pane row gets the real pane widths (320–350 px), the 20 px margin and 4 px grid, the 40 × 40 px personality-menu reserve, the dialog 80 % default and the theme-API fields (four colours plus `isDarkTheme`, no dark-mode design page); the IDE-panel row gets VS Code's webview do/don't list, the `--vscode-*` theming contract, 24 px / 16 px icon sizes and the notification rules; a new browser-side-panel row says width is the user's and the panel opens only on a user gesture, with the popup 25 × 25–800 × 600 px limit.
- skills/design-studio/references/disciplines/icons.md and app-icons.md: ribbon icons 16 / 20 / 32 px required with 1 px lines; VS Code command icons 16 px with 1 px padding; Chrome store icon 128 px with 96 px artwork.
- skills/critique-design/references/heuristics.md: an add-in that puts a control in the top-right 40 px, a webview used for a wizard or a promotion, or a notification without "Do not show again" is a finding on those hosts.
