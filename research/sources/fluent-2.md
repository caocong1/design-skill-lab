## Key facts
**Materials** (fluent2.microsoft.design/material; Learn materials, mica, acrylic, develop/ui/materials)
1. Fluent names four materials: **Solid** (opaque; the most common; hierarchy comes from colour and elevation), **Acrylic** (semi-transparent frosted glass for "transient, light-dismiss surfaces such as popovers and menus"), **Mica** (opaque, "subtly tinted with someone's desktop background color" on the active window, neutral when inactive), **Smoke** (dims what is beneath a modal such as a dialog; "always translucent black", not mode-aware). Solid, Acrylic and Mica are light/dark aware. Types: solid, occluding (Mica, Acrylic, used as base layers under controls), transparent (Smoke).
2. Mica paints the backdrop of long-lived windows (apps, settings). It samples the wallpaper only once, for performance. Apply it once, as the app's base layer, and keep it visible in the title bar by extending content into the non-client area. **Mica Alt** tints the wallpaper colour more strongly and is meant for apps with a tabbed title bar (Windows App SDK ≥ 1.1, Windows 11 build ≥ 22000) (style/mica).
3. Layering with Mica: Mica base + a content layer painted with `LayerFillColorDefaultBrush`, either a "standard" contiguous area or "card" segments. With Mica Alt: base + a commanding layer (`LayerOnMicaBaseAltFillColorDefaultBrush`: menu bar, navigation) + a content layer (`LayerFillColorDefaultBrush`). "Don't apply backdrop material more than once"; layers must be transparent for Mica to show through.
4. Acrylic comes in two blends. **Background (desktop) acrylic** shows the wallpaper and other windows: use it for flyouts, context menus, light-dismiss panes. **In-app acrylic** blurs only the app's own content: use it for panes that overlap content, such as NavigationView in Compact or Minimal mode. Don'ts: no desktop acrylic on large backgrounds; no stacked acrylic layers; no acrylic panes edge to edge (visible seam); no accent-coloured text or hyperlinks on acrylic. Recipe: background → blur → exclusion blend → colour/tint overlay → noise (style/acrylic).
5. Fallback to solid colour happens automatically, with no detection needed (develop/ui/materials). Mica falls back to `SolidBackgroundFillColorBase` (Mica Alt: `…BaseAlt`) when transparency is off, on low-end hardware, when the window is inactive, or below build 22000 (style/mica). All materials drop out in high contrast, and `SystemBackdrop` materials fall back over Remote Desktop and in VMs. Battery Saver turns acrylic solid (style/acrylic, develop/ui/materials). **Whether Battery Saver also affects Mica is disputed.** style/mica (2026-07-22) lists it as a Mica fallback, while develop/ui/materials (2026-08-19) says "Mica is not affected" (see Not verified). Background acrylic, but not in-app acrylic, also turns solid when the window deactivates and on Xbox, on HoloLens and in tablet mode.
6. WinUI APIs: `Window.SystemBackdrop = new MicaBackdrop()` (`MicaKind.Base` / `BaseAlt`), `new DesktopAcrylicBackdrop()` (`DesktopAcrylicKind.Base` more opaque / `Thin` more transparent; Windows 10 17763+), `SystemBackdrop` on `FlyoutBase`/`Popup`, `SystemBackdropElement` for one panel (Windows App SDK 2.0), in-app `AcrylicInAppFillColorDefaultBrush` or a custom `AcrylicBrush` (TintColor, TintOpacity, TintLuminosityOpacity, FallbackColor). In WinUI, `AcrylicBrush` is in-app only.

**Typography** (fluent2 typography tabs; Learn signature-experiences/typography)
7. Fluent web ramp (Segoe UI), px size / line height: Caption 2 10/14 (Regular, Strong = Semibold); Caption 1 12/16 (Regular, Strong, Stronger = Bold); Body 1 14/20 (Regular, Strong, Stronger); Subtitle 2 16/22 (Semibold, Stronger); Subtitle 1 20/26 (Semibold); Title 3 24/32; Title 2 28/36; Title 1 32/40; Large Title 40/52; Display 68/92 (all Semibold).
8. Windows ramp (Segoe UI Variable), epx: Caption 12/16 Regular (small optical size); Body 14/20 Regular; Body Strong 14/20 Semibold; Body Large 18/24 Regular; Subtitle 20/28, Title 28/36, Large Title 40/52, Display 68/92 (Semibold, display optical size). Bold and italic are not in the Windows ramp: "use Semibold instead of Bold". Learn's Windows 11 table (signature-experiences/typography) has one row the Fluent site lacks: 18/24 epx Semibold, i.e. a Body Large Strong.
9. Segoe UI Variable has two axes: `wght` 100–700 (Light 300, Semilight 350, Regular 400, Semibold 600, Bold 700) and `opsz`, which is automatic and scales optically from 8 to 36 pt. Windows 11 rules: Regular for most text and Semibold for titles; minimum sizes 14 px Semibold / 12 px Regular; sentence case everywhere; left-aligned; ellipsis for truncation; 50–60 characters per line (never below 20 or above 60).
10. Windows UI fonts for other scripts: Microsoft YaHei UI (Simplified Chinese), Microsoft JhengHei UI (Traditional Chinese), Yu Gothic UI (Japanese), Malgun Gothic (Korean); SimSun is a legacy Chinese UI font. Selawik is an open-source font metrically compatible with Segoe UI, for non-Windows platforms.
11. Fluent also publishes ramps for macOS (SF Pro; Body 1 13/16 pt … Display 30/40 pt Bold), iOS (SF Pro; Body 1 17/22 pt, Large Title 34/41 pt Bold, Display 60/70 pt Bold) and Android (Roboto; Caption 2 12/16 sp, Body 1 16/24 sp, Title 1 24/32 sp Bold, Large Title 34/44 sp, Display 60/72 sp Regular). Text contrast: 4.5:1, or 3:1 for large text (above 18.5 px bold or 24 px regular).
12. Code differs from the site. In `@fluentui/tokens` (React v9), `subtitle1` = 20/**28** px (the site says 20/26), and there is a `body2` 16/22 that the site's web ramp does not list. Font sizes are 10, 12, 14, 16, 20, 24, 28, 32, 40, 68 px. `fontFamilyBase` = 'Segoe UI', 'Segoe UI Web (West European)', -apple-system, BlinkMacSystemFont, Roboto, 'Helvetica Neue', sans-serif. `fontFamilyNumeric` starts with Bahnschrift.

**Spacing, grid, breakpoints**
13. Fluent global spacing ramp, 4 px base (layout#global-spacing-ramp): sizeNone 0, size20 2, size40 4, size60 6, size80 8, size100 10, size120 12, size160 16, size200 20, size240 24, size280 28, size320 32, size360 36, size400 40, size480 48, size520 52, size560 56. The values 2, 6 and 10 exist to align icon padding. React v9 spacing tokens: XXS 2, XS 4, SNudge 6, S 8, MNudge 10, M 12, L 16, XL 20, XXL 24, XXXL 32 (horizontal and vertical sets). Minimum touch targets: iOS and web 44×44, Android 48×48.
14. Fluent web breakpoints: small 320–479, medium 480–639, large 640–1023, x-large 1024–1365, xx-large 1366–1919, xxx-large ≥ 1920. The 12-column grid is the common default. Responsive techniques: reposition, resize, reflow, show/hide, re-architect.
15. Windows: design in effective pixels (epx); sizes, margins and positions in multiples of 4 epx, because scale plateaus are 100–400% (4 × 125% = 5). Window breakpoints: small ≤ 640, medium 641–1007, large ≥ 1008 epx (TVs count as small). For mockups: 72 DPI at the effective resolution.
16. Windows spacing (content-basics, 2026-09-11): 8 epx between buttons, between a button and its flyout, and between a control and its header; 12 epx between a control and its label and between content areas; 16 epx from surface edge to text; 16 epx between a control and an expander button; indent controls inside an expander by 48 epx; multi-line lists use Body + Caption with 32 epx icons; Body Strong for section headers.
17. App silhouettes: top navigation (Photos), menu bar (Notepad), left navigation (Settings), tab view (Terminal). "Content margins can vary". The examples use 56 epx for media and settings content (Photos, Settings) and 12 epx for editors (Notepad, Terminal).

**Shape and stroke**
18. Fluent site (shapes#corner-radius): default 4 px; shapes smaller than 32 px use 2 px; large and extra-large components use 8 px and 12 px. Tokens: None 0 (nav bars, tab bars), Small 2 (small badges), Medium 4 (buttons, dropdowns), Large 8 (large buttons), X-Large 12 ("button sheets" [sic, likely bottom sheets], popovers), Circle 50% (personas). No rounding where parts meet (split button) or at the screen edge. Forms: rectangle, circle, pill, beak (callouts).
19. React v9 code tokens differ: borderRadiusSmall 2, Medium 4, **Large 6**, **XLarge 8**, 2XLarge 12, 3XLarge 16, 4XLarge 24, 5XLarge 32, 6XLarge 40, Circular 10000px.
20. Windows 11 geometry: 8 px for top-level containers (windows, flyouts, dialogs, TeachingTip); 4 px for in-page controls (Button, CheckBox, ComboBox, TextBox, ListView backplates), bar shapes (ProgressBar, ScrollBar, Slider) and ToolTip; 0 px where straight edges meet and when a window is snapped or maximized. Resources `ControlCornerRadius` 4 and `OverlayCornerRadius` 8.
21. Stroke widths: thin 1, thick 2, thicker 3 (mobile 4), thickest 4 (mobile 6) px.

**Elevation and layering**
22. Fluent shadows pair an ambient (diffuse) shadow with a key (directional) shadow; token n = blur. Code: shadow2/4/8/16 = `0 0 2px ambient, 0 n/2 n key`; shadow28 = `0 0 8px, 0 14px 28px`; shadow64 = `0 0 8px, 0 32px 64px`. Site opacities: low ramp light 14%/14% (dark 28%/14%); high ramp light 24%/20% (dark 28%/20%). Example uses (light/dark lists merged): 2 edgeless cards, pressed FABs, ribbon; 4 cards, grid and list items; 8 FABs, raised cards and app bars, command bars, tooltips; 16 callouts and hover cards; 28 bottom sheets, side navigation, raised tab bars; 64 dialogs and panels. On brand-coloured surfaces, shadow opacity comes from luminosity: shadow 1 = round(42 − 0.116 × L), shadow 2 = round(34 − 0.09 × L).
23. "Windows uses strokes instead of key shadows to outline an object." Windows 11 elevation values: window and dialog 128, flyout 32, tooltip 16, card 8, control 2 (1 when pressed), layer 1, each with a 1 px stroke. Two-layer app model: base layer (menus, commands, navigation) + content layer (contiguous or cards). In both themes, darker = less important surface, lighter = more important.

**Colour, states, motion**
24. Palettes: neutral, shared (cross-M365 accents; semantic subset for status only), brand (per product). Interaction states darken as the user interacts: rest is lightest, hover is darker and selected is darkest; "Windows interaction states currently treat color in reverse; controls will get lighter". Focus changes the stroke (thicker), not the fill. Windows accent colour values are generated for contrast in both modes.
25. Windows motion table: direct entrance `cubic-bezier(0,0,0,1)` 167/250/333 ms; point-to-point `(0.55,0.55,0,1)` 167/250/333 ms; direct exit `(0,0,0,1)` 167 ms, always combined with a fade; gentle exit `(1,0,1,1)` 167 ms; fade linear 83 ms; strong entrance = 3 keyframes. Prefer the built-in page transitions, connected animation and AnimatedIcon (Lottie). React v9: durations 50/100/150/200/250/300/400/500 ms; curves such as decelerateMid `(0,0,0,1)`, accelerateMid `(1,0,1,1)`, easyEase `(0.33,0,0.67,1)`. Fluent motion asks for a "no motion" setting.

**Iconography**
26. Fluent System Icons (MIT) come in Regular (wayfinding) and Filled (selected states, small emphasis). 12 px icons are informational only, never interactive. Modifiers always use the filled theme and sit bottom-right. Name icons for the object, not the function ("Shield, not security"). Use one solid colour at most on system icons, and never recolour product icons. Product (app) icons scale by factors of 4 above 48 px; file-type icons look best at 16 / 48 / 96 px.
27. Windows system icons: **Segoe Fluent Icons** replaced Segoe MDL2 Assets in Windows 11. Monoline, 1 epx stroke; a square-em footprint (a 16 px glyph = a 16×16 icon); mapped to the Private Use Area; glyphs E0xx–E5xx are legacy and deprecated. Crisp sizes: 16, 20, 24, 32, 40, 48, 64. The font may be used for design on other platforms but not shipped there. Modifiers go in a bottom quadrant; layer glyphs for states.
28. Windows app icons: design on a 48×48 grid; corner radius 2 px on exterior curves and 1 px on interior curves (at 48 px); at most two metaphors; avoid letters or words unless essential; gradients subtle, default angle 120°; at least half of the icon must reach 3:1 contrast on both light and dark themes; Windows 11 no longer needs high-contrast icon assets.

**Windows 11 title bar and platform status**
29. Title bar (titlebar-design): 32 px high by default, **48 px when it holds a search box (centred) or a person picture**. Default background is Mica, and it should blend with the window. Elements turn semi-transparent when the window is inactive. Window icon 16×16, 16 px from the edge; title in Caption style, 16 px after the icon or back button. Caption glyphs: E921 minimize, E922 maximize, E923 restore, E8BB close; back E830. Tabs may occupy the title bar, with the caption controls kept at the right.
30. Status (whats-new, ms.date 2026-09-19): Windows App SDK **2.4.0** stable (2026-08-13); 2.4.1-experimental adds InkCanvas/InkToolbar. April 2026: "WinUI 3" is now just "WinUI" and "WinUI 2" is "WinUI for UWP"; new Materials docs; the iconography hub; the Segoe Fluent Icons update. May 2026: WinUI agent plugin for GitHub Copilot and Claude Code (8 skills, `/plugin install winui@awesome-copilot`), and `dotnet new` WinUI templates "built around Windows app silhouettes". June 2026 (Build): Windows Development Skills for agents. Windows App SDK 2.0 added TitleBar custom drag regions. Web implementation: `@fluentui/react-components` 9.74.9.

## Not verified / open
- Design site vs code: corner radius Large (8 px on the site, 6 px in React v9) and Subtitle 1 line height (26 on the site, 28 in code). Not resolved; the code is what ships.
- Mica Alt: the design page calls it "stronger tinting", while the developer page calls `MicaKind.BaseAlt` "lighter, for secondary surfaces". The wording conflicts; the usage (tabbed title bars) agrees.
- Exact Acrylic tint/luminosity opacities for the theme brushes (in the microsoft-ui-xaml resource files) and Smoke's opacity were not read.
- Battery Saver and Mica: the two Microsoft Learn pages disagree (fact 5). A skill should not promise either behaviour. Design so the solid fallback reads well in every case.
- The iOS, macOS and Android ramps are summarised here, not listed in full. The fact-check re-captured all three tabs, and the values quoted in fact 11 match.
- The Fluent 2 site shows no revision dates. Several Windows signature-experience pages still carry 2021–2024 `ms.date` values but describe Windows 11 as current.
