## Key facts
**What it is**
1. Announced 2025-05-13. "M3 Expressive isn't a new version of the system. We're not deprecating M3, and this isn't 'M4'." Backed by 46 studies with 18,000+ participants; key UI elements spotted up to 4x faster on expressive screens (blog#the-power-of-expressive-design).
2. 14 new or updated components: app bars, **button groups (new)**, common buttons, extended FAB, **FAB menu (new)**, FABs, icon buttons, **loading indicator (new)**, navigation bar, navigation rail, progress indicators, sliders, **split button (new)**, **toolbars (new)** (blog#whats-in-the-update).
3. Seven tactics: variety of shapes; rich colour contrast between roles; emphasized type; containment; fluid motion; component flexibility; combine them into "hero moments", and "stick to one or two hero moments in your product" (blog#expressive-tactics).

**Motion physics** (styles/motion/overview/how-it-works, "May 2025")
4. "The physics system is replacing the previous system based on easing and duration." The old easing/duration tokens remain as a fallback and "are currently used for animating transitions" (motion/specs#easing-and-duration).
5. Two preset schemes. **Expressive** = "Material's opinionated motion scheme, and should be used for most situations, particularly hero moments and key interactions"; it overshoots. **Standard** = "more functional with minimal bounce… for utilitarian products". Custom schemes allowed; products may swap scheme per element (the page says: Compose, override the CompositionLocal; in code `LocalMotionScheme` was removed in 1.5.0-alpha27, so wrap the subtree in `MaterialTheme(motionScheme = …)` instead).
6. A spring = stiffness + damping + initial velocity. Tokens `md.sys.motion.spring.{fast|default|slow}.{spatial|effects}`; the scheme is chosen at product level and is not part of the token name.
7. Spatial springs (x/y, rotation, size, corner radius) overshoot; effects springs (colour, opacity) never overshoot. Speed: default = partial-screen motion (bottom sheet, expanded rail); fast = small components (switches, buttons); slow = full-screen.
8. Values (identical in the m3 token DB and androidx `ExpressiveMotionTokens`/`StandardMotionTokens`, damping ratio / stiffness):

| token | expressive | standard |
| --- | --- | --- |
| fast.spatial | 0.6 / 800 | 0.9 / 1400 |
| default.spatial | 0.8 / 380 | 0.9 / 700 |
| slow.spatial | 0.8 / 200 | 0.9 / 300 |
| fast / default / slow .effects | 1.0 / 3800, 1600, 800 | same |

9. Derived by the lab (mass 1; period 2π/√k; bounce = 1 − ζ; not stated by Material): expressive spatial fast 222 ms / bounce 0.4 / ~9.5% overshoot, default 322 ms / 0.2 / ~1.5%, slow 444 ms / 0.2 / ~1.5%; standard spatial 168 / 237 / 363 ms, bounce 0.1, ~0.15%; effects 102 / 157 / 222 ms, no overshoot.
10. Web: "Compatible. Use springs when possible, otherwise use curves that mimic the springs for animations without interruptions or gestures" (motion/specs#web-convert-springs-to-curves). Material's own table (cubic-bezier, duration): expressive fast spatial `0.42,1.67,0.21,0.90` 350 ms; expressive default spatial `0.38,1.21,0.22,1.00` 500 ms; expressive slow spatial `0.39,1.29,0.35,0.98` 650 ms; standard spatial (all speeds) `0.27,1.06,0.18,1.00` at 350 / 500 / 750 ms; effects (both schemes) fast `0.31,0.94,0.34,1.00` 150 ms, default `0.34,0.80,0.34,1.00` 200 ms, slow `0.34,0.88,0.34,1.00` 300 ms.
11. The page says exact values differ by device class (wearable / phone / tablet); the public token DB snapshot holds one value per scheme only.
12. Compose: 21 Material components use physics by default. Code default: `MaterialTheme(motionScheme = standard())`; `MaterialExpressiveTheme` defaults to `MotionScheme.expressive()` (MaterialTheme.kt at `23327507`). Legacy easing tokens still exist: standard `cubic-bezier(0.2,0,0,1)`, emphasized decelerate `(0.05,0.7,0.1,1)`, emphasized accelerate `(0.3,0,0.8,0.15)`; durations short1–4 50–200, medium1–4 250–400, long1–4 450–600, extra-long1–4 700–1000 ms.

**Shape** (styles/shape/*)
13. 35 library shapes plus built-in shape morph (May 2025): Circle, Square, Slanted, Arch, Fan, Arrow, SemiCircle, Oval, Pill, Triangle, Diamond, ClamShell, Pentagon, Gem, Sunny, VerySunny, Cookie4/6/7/9/12Sided, Ghostish, Clover4Leaf, Clover8Leaf, Burst, SoftBurst, Boom, SoftBoom, Flower, Puffy, PuffyDiamond, PixelCircle, PixelTriangle, Bun, Heart (`MaterialShapes.kt`). Use them for "mostly visual elements" (image crops, avatars), sparingly; avoid them on text-heavy containers; "shape is versatile, not semantic".
14. Corner scale, 10 steps (`md.sys.shape.corner.*`): none 0, extra-small 4, small 8, medium 12, large 16, **large-increased 20**, extra-large 28, **extra-large-increased 32**, **extra-extra-large 48** (the three bold ones added May 2025), full (now a "full" token; before, 50% of component size). Asymmetric "inner corners" are used in grouped items (menus, split buttons).
15. Optical roundness for nesting: outer radius − padding = inner radius (example 48 − 14 = 34 dp) (corner-radius-scale#adjust-for-optical-roundness).
16. Shape morph is used by the standard button group and the loading indicator; it uses the expressive motion scheme by default; "Web is not currently available" (shape-morph).

**Typography** (styles/typography/*)
17. 30 styles: 15 baseline + 15 emphasized (May 2025). Sizes/line heights are unchanged between the two; emphasized raises weight: display/headline/title-large 400 → 500; title-medium/small and label-large/medium/small 500 → 700 (the weight token is `weight-bold` = 700, as in Compose `TypeScaleTokens`; the variable-font `wght` axis value for these five is 600); body 400 → 500.
18. Baseline scale (size/line height, sp): display L/M/S 57/64, 45/52, 36/44; headline 32/40, 28/36, 24/32; title 22/28, 16/24 (500), 14/20 (500); body 16/24, 14/20, 12/16; label 14/20, 12/16, 11/16 (all 500). Third-party tracking (Roboto): display-large −0.25, title-medium 0.15, title-small 0.1, body-large 0.5, body-medium 0.25, body-small 0.4, label-large 0.1, label-medium/small 0.5 (token DB `3p` context).
19. Fonts: static Roboto is the default for all M3 components; "Roboto Flex… isn't yet part of the M3 typescale"; fallback order Roboto Flex → Roboto → Noto Sans (typography/fonts). The DB default context names Google Sans / Google Sans Text / Google Sans Flex, which are Google's own (1p) faces; the `3p` context maps to Roboto / Roboto Flex.
20. Aug 2026: "language script height support": line heights adapt to script height category small / medium / large / extra large (e.g. display-large line height 64 → 73 / 89 / 120) (typography/overview#updates).
21. Guidance: line height ~1.2× size for title/headline/display, ~1.5× for body/label; tabular figures where values change; text contrast 4.5:1 small, 3:1 large; links in primary (or tertiary) and underlined (typography/applying-type).

**Colour** (styles/color/overview)
22. May 2025: every colour role supports three tokenised contrast levels: standard, medium, high. 26+ colour roles; dynamic colour optional; the baseline scheme is static.

**Navigation** (components/*; heights from the token DB)
23. Navigation bar: the **flexible navigation bar** replaces the baseline bar ("no longer recommended"). Container height **64 dp** (`md.comp.nav-bar.container.height`; baseline `md.comp.navigation-bar.container.height` 80 dp). Compact and medium windows; 3–5 destinations; vertical items in compact, **horizontal items in medium** windows. Container `surface-container`; active indicator `secondary-container`, 56×32 dp (vertical) or 40 dp high (horizontal); active label changed from on-surface-variant to `secondary`; icons 24 dp; label = label-medium.
24. Navigation rail: **collapsed** rail (replaces baseline rail) and **expanded** rail ("meant to replace the navigation drawer"). Collapsed width 96 dp (narrow variant 80 dp); expanded width 220–360 dp; top space 44 dp; item height 64 dp (short 56). Expanded rail can be standard (non-modal) or modal (`surface-container`, corner large 16 dp, elevation level2); expanded can collapse to the rail or hide. 3–7 destinations plus optional FAB; collapsed ↔ expanded can transition on any device.
25. Navigation drawer: "no longer recommended in the Material 3 Expressive update… use an expanded navigation rail" (May 2025). Baseline drawer width was 360 dp.
26. Breakpoints (renamed from "window size classes" in May 2026): compact < 600 dp, medium 600–839, expanded 840–1199, large 1200–1599, extra-large ≥ 1600. Navigation: compact/medium → navigation bar or modal expanded rail; expanded and up → modal or standard expanded rail. Panes: 1; 1 (rec.) or 2; 1 or 2 (rec.); 1 or 2 (rec.); 1–3 (rec.). Keep text 40–60 characters per line. May 2026 also introduced the layout scaffold: bars, rails, panes (foundations/layout/*).

**Bars and actions**
27. Toolbars: **docked toolbar** replaces the bottom app bar (which "is no longer recommended"); **floating toolbar** is new, horizontal or vertical, can pair with a FAB. Both come in **standard** (`surface-container`) or **vibrant** (`primary-container`) colour. All toolbars are 64 dp high, centre-aligned, equal item spacing, minimum outside padding 16 dp. Floating: fully rounded, elevation level3, 16 dp external padding (vertical variant 24 dp). "Don't show at the same time as a navigation bar." Web: unavailable.
28. App bars ("top app bar" renamed "app bar"): search app bar (new), small (64 dp; centre-aligned merged into it), **medium flexible** (112 dp; 136 with subtitle) and **large flexible** (120 dp; 152 with subtitle) replace medium (112) and large (152), which are no longer recommended. Flexible bars add subtitles, centred text, wrapping, images, a filled trailing icon button. Titles: small = title-large, medium flexible = headline-medium, large flexible = display-small. On scroll the container fills with `surface-container` (no shadow).
29. Buttons: five sizes XS / S / M / L / XL = 32 / 40 / 56 / 96 / 136 dp high; icons 20 / 20 / 24 / 32 / 40 dp; round (full) or square (corner 12 / 12 / 16 / 28 / 28); corners morph when pressed (8 / 8 / 12 / 16 / 16) and toggle between round and square when selected. Small-button side padding 16 dp recommended (24 dp no longer). Icon buttons use the same five heights plus narrow / default / wide widths.
30. Button groups (new): standard and connected. Standard group padding XS 18, S 12, M 8, L 8, XL 8 dp (keeps 48 dp targets); pressing widens the pressed button (width multiplier 15%, fast spatial spring) and squeezes its neighbours. Connected group: 2 dp gaps; inner corners XS 4, S 8, M 8, L 16, XL 20 dp (page text); selected inner corner becomes 50%. **Connected button group replaces the segmented button**, which is no longer recommended.
31. Split button (new): leading button + trailing menu button, sizes XS–XL, elevated / filled / tonal / outlined; 2 dp gap; inner corners XS–M 4, L 8, XL 12 dp; outer corners fully round; the menu icon spins and becomes centred and round when selected; colour does not change on selection.
32. FAB menu (new): opens from a FAB to show **2–6** related actions; one menu size for every FAB size; not used with extended FABs; primary / secondary / tertiary colour sets; close button 56 dp; items use medium-button metrics (56 dp); 16 dp FAB margins; anchored at the FAB's top trailing corner. Replaces the speed dial and stacked small FABs.
33. FABs: FAB 56 dp (corner 16), **medium FAB 80 dp (corner 20, new)**, large 96 dp (corner 28); small FAB (40 dp) and surface-colour FABs no longer recommended. Extended FAB: small 56 / medium 80 / large 96 dp replace the baseline 56 dp extended FAB.
34. Loading indicator (new): for waits under five seconds; replaces most uses of the indeterminate circular progress indicator; used for pull-to-refresh; contained or uncontained; 48 dp container, 38 dp indicator; morphs between shapes. Progress indicators gained a wavy option and configurable track height; sliders gained XS–XL sizes, vertical orientation and an inset icon.

**Code availability (as of 2026-09-27)**
35. Compose Material 3 stable is **1.4.0 (2025-09-24)**; its beta01 (2025-07-30) removed every `ExperimentalMaterial3ExpressiveApi` API ("switch to 1.5.0-alpha"). Latest is **1.5.0-alpha29 (2026-09-23)**; no 1.5 beta or RC yet.
36. What stable 1.4.0 does ship (verified in the 1.4.0 sources jar): `ShortNavigationBar` (the 64 dp flexible bar) and `WideNavigationRail` / `ModalWideNavigationRail` (collapsed and expanded rails) as public, non-experimental APIs (graduated in 1.4.0-alpha18). Components use motion springs internally, always the standard scheme. What it lacks: the whole motion-scheme API is `internal` in 1.4.0 (`interface MotionScheme`, `standard()`/`expressive()`, the `MaterialTheme(motionScheme = …)` overload, `MaterialTheme.motionScheme`, `MaterialExpressiveTheme`), so apps cannot switch to expressive; none of it is in `api/1.4.0-beta03.txt`, the frozen 1.4 API. The emphasized type styles are also `internal`; no toolbars, button groups, split button, FAB menu, medium FAB, loading indicator, `MaterialShapes` or flexible app bars.
37. Graduations inside the 1.5.0-alpha line: toggle buttons, expressive buttons and menus, FAB and FAB menu (alpha19, 2026-05-06); split button (alpha20, 2026-05-19); floating toolbar and button group (alpha22, 2026-06-17); `TopAppBar`, `MediumFlexibleTopAppBar`, `LargeFlexibleTopAppBar`, `FlexibleBottomAppBar` and expressive list items (alpha23, 2026-07-01); `BottomAppBar` stable (alpha26). alpha19 **reverted** the promotion of `MaterialShapes` and `LoadingIndicator`; both are still `@ExperimentalMaterial3ExpressiveApi` in `api/current.txt`. alpha27 removed `LocalMotionScheme` (use `MaterialTheme.motionScheme`).
38. Android Views: MDC-Android **1.13.0 (2025-09-03)** added `DockedToolbarLayout`, `FloatingToolbarLayout`, `LoadingIndicator`, `MaterialSplitButton`, `MaterialButtonGroup`; **1.14.0 (2026-05-13, stable)** adds the Material3Expressive themes and styles for buttons, icon buttons, button groups, FABs, top app bars, navigation bar, navigation rail, search, progress, sliders and the emphasized typescale. The FAB menu is "Unavailable" for Views; motion springs exist as tokens but are "not added to components".
39. Web: for all the expressive components above, the availability tables say "Web: Expressive – Unavailable"; shape morph is unavailable on web. Wear OS uses its own Wear Compose Material 3 library.
40. Icons: 1.4.0 stopped recommending `androidx.compose.material.icons`; use Material Symbols (variable font: outlined / rounded / sharp; axes weight, fill, optical size, grade) from fonts.google.com/icons.

## What it changes for the skills
- skills/design-studio/references/platforms/android.md: "Native Android" posture = flexible 64 dp nav bar (horizontal items at medium), collapsed/expanded rail instead of the drawer, docked/floating toolbar instead of the bottom app bar (never together with a nav bar), flexible app bars, button groups instead of segmented buttons, split button, FAB menu (2–6), medium FAB, loading indicator, emphasized type for one or two hero moments. State the breakpoint table (fact 26) using the new word "breakpoints".
- skills/design-studio/references/disciplines/motion-tokens.md: Both schemes with values (fact 8), marked expressive vs standard; the derived duration/bounce row marked "lab-derived"; Material's own web cubic-bezier table (fact 10) as the web fallback; "spatial overshoots, effects never"; note Compose defaults to standard unless `MaterialExpressiveTheme`.
- skills/design-studio/references/disciplines/motion.md: Under Native Android, expressive is the platform default for most UI and standard for utilitarian products; the lab's brand-neutral "little or no bounce" default applies to custom/web targets only.
- skills/design-studio/references/fundamentals/typography.md: M3 baseline + emphasized scale (facts 17–18), the 3p tracking values, Roboto default, script-height line heights (fact 20).
- skills/design-studio/references/fundamentals/layout-and-spacing.md: M3 corner scale with the three new steps; optical-roundness rule (fact 15).
- skills/design-studio/references/fundamentals/materials.md: M3 has no glass; hierarchy by tonal surfaces (`surface`, `surface-container`…), toolbars/app bars fill with surface-container on scroll; three contrast levels.
- skills/design-studio/assets/mockup-kit/kit.css + kit.json: M3 nav bar 80 → 64 dp; add docked (64 dp) and floating (64 dp, pill, 16 dp inset) toolbars, collapsed rail 96 dp and expanded rail 220–360 dp, button sizes 32/40/56/96/136, FAB 56/80/96. Cite this id in kit.json.
- skills/design-studio/references/process/handoff.md: When an Android handoff uses toolbars, button groups, split button, FAB menu, loading indicator, shapes or the expressive scheme, flag "Compose needs material3 1.5.0-alpha (stable 1.4.0 lacks it); Views needs MDC 1.14.0".
- skills/implement-design/references/stacks.md: Compose `MaterialExpressiveTheme` / `MotionScheme.expressive()`, `ShortNavigationBar`, `WideNavigationRail`, `HorizontalFloatingToolbar`, `FlexibleBottomAppBar`, `ButtonGroup`, `SplitButtonLayout`, `FloatingActionButtonMenu`, `MaterialShapes` (experimental), `LoadingIndicator` (experimental); Material Symbols instead of material-icons; MDC 1.14 Material3Expressive themes; web = springs → Material's curve table.
- skills/design-studio/references/platforms/web.md: Material Web has no Expressive components; use the curve table for motion and do not promise shape morph on web.

## Not verified / open
- Per-device-class spring values (fact 11): not in the public token DB; not found elsewhere.
- Measurement images (padding inside the nav bar, rail, toolbars, app bars) were not read; only token values and page text are used here.
- Connected button group, XS inner corner: page text says 4 dp, `md.comp.button-group.connected.xsmall.inner-corner.corner-size` resolves to 8 dp. Unresolved; prefer the token when building.
- `md.comp.nav-bar.container.elevation` resolves to level2 (3 dp) in the DB while the overview says "no shadow"; not drawn as a shadow here.
- The status of the Material Web library (`@material/web`) itself and any Flutter Expressive plans were not checked.
- The design.google research article (87% preference among 18–24-year-olds and similar figures quoted elsewhere) was not re-read for this digest.
- Fact-check pass (2026-09-27, independent re-render of every cited m3.material.io page, DSDB snapshot `2026-09-23_06-10-05`, androidx at `23327507`, the 1.4.0 sources jar re-downloaded from Google Maven, MDC GitHub releases): all numeric values confirmed. Corrected: fact 36 claimed stable 1.4.0 ships "the MotionScheme plumbing". In fact the motion-scheme API is entirely `internal` there. Added: the code path for per-element scheme swaps (fact 5) and the 600 `wght` axis value (fact 17). Checked and kept: `SplitButtonLayout` is the current split-button API.
