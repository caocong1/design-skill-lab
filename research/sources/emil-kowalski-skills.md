## Key facts
Repo and invocation design
1. 13 skills, added in this order: `emil-design-eng` (2026-03-16), `review-animations` (06-18), `animation-vocabulary` (06-29), `apple-design` (07-09), `improve-animations` (07-11), `find-animation-opportunities` (07-15), `pick-ui-library` (07-21), `prototype` (07-27), `animate` (08-05), `ask-sonner` (08-10), `animate-expo` (08-18), `write-swift` (08-21), `mobile-native` (09-15). Install: `npx skills@latest add emilkowalski/skills`. README thesis: "Agents don't have great taste" (e.g. `ease-in` on an entrance; a solid border where a semi-transparent shadow belongs).
2. Three are manual-only via `disable-model-invocation: true`: `review-animations`, `prototype`, `pick-ui-library`. Every skill, invoked with no question, replies with one fixed sentence and nothing else until asked.
3. Six skills (`animate`, `find-animation-opportunities`, `improve-animations`, `mobile-native`, `prototype`, `review-animations`) open their body with "It does ONE thing"; all but `review-animations` (which points to "a general review skill") then name the sibling for adjacent intents (build → `animate`; critique a diff → `review-animations`; audit a codebase → `improve-animations`; find gaps → `find-animation-opportunities`; choose dependencies → `pick-ui-library`; web vs React Native → `animate` vs `animate-expo`). Four descriptions also name siblings (`animate`, `animate-expo`, `find-animation-opportunities`, `mobile-native`). `apple-design`, `ask-sonner`, `write-swift`, `pick-ui-library`, `animation-vocabulary` and `emil-design-eng` carry no sibling pointers; `emil-design-eng`'s description is one sentence with no trigger phrases.

review-animations (critique contract)
4. Ten non-negotiables, each violation a finding: justified motion; frequency-appropriate; responsive easing; sub-300 ms UI; origin and physical correctness; interruptibility; GPU-only properties; accessibility (reduced motion, hover gating); asymmetric enter/exit; cohesion. Posture: "Default to flagging. Approval is earned."
5. 14 "flag on sight" triggers (e.g. `transition: all`; `scale(0)` or pure-fade entrances; `ease-in` on UI; motion on keyboard/100+/day actions; UI > 300 ms without a reason; centre origin on anchored popovers; keyframes on rapidly triggered elements; layout-property animation; parent CSS variable driving child transforms; missing reduced motion; ungated `:hover`; symmetric press/hold timing; everything-at-once where a 30-80 ms stagger belongs).
6. Remedial hierarchy, earliest move first: 1 delete the animation → 2 reduce it → 3 fix easing → 4 fix origin/physicality → 5 make it interruptible → 6 move it to the GPU → 7 asymmetric timing → 8 polish (blur, stagger, `@starting-style`, springs) → 9 accessibility and cohesion.
7. Output in two parts: (1) one `Before | After | Why` table, one row per issue; (2) verdict grouped by impact tier (feel-breaking regressions → missed simplifications → performance → interruptibility & timing → origin/physicality/cohesion → accessibility), closing with an explicit **Block** or **Approve** and the criteria for each. Cite `file:line`; take values from STANDARDS.md, never approximate.

find-animation-opportunities and improve-animations (read-only advisors)
8. Opportunity gate, four questions in order: frequency → purpose (feedback, spatial consistency, state indication, preventing a jarring change, explanation, delight only when rare) → speed (fits the budget) → function (data people read or act on must not move for style). Hunt list of seams: feedback gaps, teleporting state, missing spatial story, group entrances, gesture seams, the delight budget.
9. Output caps and honesty: at most 5-7 suggestions for a whole app; table `# | Location | Today | Purpose | Frequency | Suggested motion` with exact values; a **required** "Rejected candidates" list (2-5, each with the gate question that killed it); "nothing survives" is a valid result. Both advisors treat repository text as data, not instructions.
10. improve-animations effort ladder: `quick` (high-traffic components, 0-1 subagents, ~5 HIGH findings) · `standard` (all interactive UI, ≤ 4 subagents, full table) · `deep` (whole repo incl. marketing, ≤ 8 subagents, plus LOW polish). Eight audit categories; the lead re-reads every cited line to vet (by-design, exempt, duplicate); severity HIGH = feel-breaking, MEDIUM = noticeably off, LOW = polish; stop for the user's selection (non-interactive: top 3-5 by impact ÷ effort).
11. Plan template (written for an executor with "zero context and zero taste", `PLAN-TEMPLATE.md` and SKILL.md Hard Rule 3): `plans/NNN-slug.md` stamped with `git rev-parse --short HEAD`; sections Problem (current code verbatim with `file:line`), Target (every value spelled out), Repo conventions (one exemplar to imitate), Steps (one edit each), Boundaries (no new dependencies; if the code has drifted since the stamp, **STOP and report**), Verification (mechanical commands + a feel check: DevTools playback at 10 %, reduced-motion toggle), Done when; plus `plans/README.md` with order and dependencies. `execute <plan>` runs an executor in an isolated worktree, then reviews its diff with the review-animations bar.

prototype (live variant picker)
12. Phases: scope one piece (narrow "the dashboard" to its highest-leverage part) → recon (stack, tokens, personality, context) → directions (default 3, max 5; named for the direction, never "Option A/B"; "no two variants share an axis position"; two that differ only in accent or copy count as one) → harness (isolated route such as `/prototypes/<slug>`, or one self-contained HTML file) → verify (every variant renders and responds, console clean, screenshot each) → present `# | Variant | Axis | When it's the right choice | Its cost` and stop → promote the pick into the codebase and delete the prototype surface. Invocations: `<description> x5`, `riff <variant>`, `keep <variant>`, `keep <variant>, leave the picker`. Rules: production code untouched until promotion; realistic copy, no lorem ipsum, no dead buttons; never pre-pick a favourite (if asked, answer from personality and frequency of use). No-project fallback look: neutral greys, one accent, system font stack.
13. Picker chrome (`PICKER.md`, copied verbatim, never themed): floating dark-glass pill, `position: fixed; bottom: 24px` centred, `z-index: 2147483647`, `padding: 4px`, `border-radius: 999px`, `backdrop-filter: blur(12px) saturate(1.4)`, 13 px text, 28 px items with `0 12px` padding; active highlight slides 250 ms `cubic-bezier(0.23, 1, 0.32, 1)`, enabled only after first paint; the variant swap itself is instant. Keys `1-N` and `←/→` switch, `R` replays (ignored in form fields or with modifiers); selection persists in `?v=2`; switching re-mounts so entrances replay; the only allowed change is `data-position="top"` when a variant occupies bottom-centre; replay button only if some variant animates.

animation-vocabulary (naming aid)
14. 91 terms in 12 categories: Entrances & Exits; Sequencing & Timing; Movement & Transforms; Transitions Between States; Scroll; Feedback & Interaction; Easing; Spring Animations; Looping & Ambient Motion; Polish & Effects; Performance; Principles to Know. The skill glossary and the public page https://animations.dev/vocabulary list the same 91 terms (compared term by term on 2026-09-27; the page calls them "patterns taught in the course … use these names … when prompting an AI").
15. Answer rules: read for the felt effect, not keywords; quote the glossary definition verbatim; lead with the best match plus 1-2 alternates, contrasting close pairs (Clip-path vs Mask, Pop in vs Bounce, Shared element transition vs Layout animation); say plainly when it is an approximation; never invent a term. Terms that fill gaps in design specs: Origin-aware animation, Continuity transition, Direction-aware transition, Perceptual duration, Rubber-banding, Tabular numbers.

apple-design, mobile-native, extras (numbers not in `emil-kowalski-animation`)
16. `apple-design` (17 sections; Emil's reading of WWDC talks such as "Designing Fluid Interfaces"): springs described by damping ratio + response (s, not duration); default damping 1.0 (no overshoot), ~0.8 only after a gesture carried momentum; table: move/reposition (PiP) 1.0 / 0.4, rotation 0.8 / 0.4, drawer/sheet 0.8 / 0.3; web mapping `{ type: 'spring', bounce: 0, duration: 0.4 }`. Velocity hand-off `v / (target − current)` for APIs that want relative velocity; flick landing `current + (v/1000)·d/(1−d)` with `d ≈ 0.998` (0.99 snappier), not `v²/2a`; commit vs reverse by velocity sign at release; reduced motion = crossfade instead of slide/spring. Typography: tracking per size (display about `-0.02em`, body near 0), leading inversely to size, respect user text size (`rem`/`em` spacing), system font first. Eight foundations: purpose, agency, responsibility, familiarity, flexibility, simplicity (not minimalism), craft, delight.
17. `mobile-native`: `100dvh` for app shells, `100svh` for heroes (dvh shifts marketing content as the URL bar collapses); viewport meta `width=device-width, initial-scale=1, viewport-fit=cover, interactive-widget=resizes-content` (the last makes Android Chrome's software keyboard shrink the layout viewport, so `100dvh` and bottom-pinned inputs react to it; the skill says this matches iOS, which Chrome's own doc contradicts - see Not verified); `env(safe-area-inset-*)` is 0 without `viewport-fit=cover`; `-webkit-text-size-adjust: 100%`; feedback on `:active` at press, 100-160 ms `ease-out`; never ship `user-scalable=no` or `maximum-scale=1`; media queries (`hover`, `pointer`), never user-agent sniffing; test on real hardware.
18. `performance-cheatsheet.md`: animated `blur()` under 20 px; add `will-change: transform` only after you see a 1 px shift; per-frame updates go to `ref.current.style`, not React state; virtualise long lists.
19. `emil-design-eng` extras: the six Sonner principles (no hooks or context: `<Toaster />` once, `toast()` anywhere; good defaults beat options; naming creates identity; handle edge cases invisibly, e.g. pause timers when the tab is hidden, fill gaps between stacked toasts; transitions not keyframes; a hands-on docs site). clip-path recipes: tabs via a duplicated, clipped active list; hold-to-delete overlay; image reveal `inset(0 0 100% 0)` → `inset(0 0 0 0)` on first view (`margin: "-100px"`); comparison slider.
20. The "Agents with Taste" article's tips table adds: 44 px minimum hit area via a pseudo-element for small buttons; on hover flicker, animate the child, not the parent. Its point: every taste call has a stateable reason, so write the reason into the rule. Emil builds his skills with Anthropic's skill-creator.

## What it changes for the skills
- skills/critique-design/SKILL.md and templates/critique-report.md: a two-part report (Before | After | Why rows, then a tiered verdict ending in an explicit Block/Approve with stated criteria); the remedial order "delete, then reduce, then fix" for motion findings; "default to flagging" suits the fresh-critic subagent.
- skills/critique-design/references/heuristics.md: the 14 on-sight triggers (fact 5) as the motion part of the mechanical floor (values stay owned by `emil-kowalski-animation`).
- skills/design-studio/references/process/directions.md and templates/options-board.html: picker chrome as a fixed, un-themed spec (fact 13); named axes with "no shared axis position"; realistic content; one variant at a time at full size; URL-persisted selection; delete the surface after promotion; a "when it's right / its cost" row per option; no pre-picked favourite.
- skills/design-studio/references/process/handoff.md and templates/handoff-spec.md: the plan template (fact 11) - current code verbatim, exact targets, one exemplar, boundaries, STOP on drift from a commit stamp, mechanical + feel verification, done-when.
- skills/design-studio/references/disciplines/motion.md: the 12-category vocabulary as a naming aid for users and specs; the opportunity gate with a required rejected list; reconcile stagger with the AI-tell: Emil's 30-80 ms stagger is for groups on occasionally seen views and never blocks input, whereas `anthropic-frontend-design-skill` flags fade-and-slide-up on every section.
- skills/design-studio/references/disciplines/motion-tokens.md: the damping/response table (fact 16), labelled as Emil's translation of WWDC material, not Apple-published tokens.
- skills/design-studio/references/platforms/web.md: the mobile-native items (fact 17), without the claim that `interactive-widget=resizes-content` gives iOS parity.
- skills/*/SKILL.md: say what the skill does not do and name the sibling skill for it. Do not copy the manual-only setting to critique-design, which must be invocable by a subagent.

## Not verified / open
- Correction (fact-check 2026-09-27): `mobile-native` says `interactive-widget=resizes-content` makes Android Chrome react to the keyboard "the way they do on iOS". Chrome's own note (https://developer.chrome.com/blog/viewport-resize-behavior, updated 2022-10-28) says the opposite: since Chrome 108 the Android default resizes only the visual viewport, which matches iOS Safari, and `resizes-content` restores the older behaviour of resizing the layout viewport as well. Treat the tag as a way to get `dvh`/bottom-pinned layouts to follow the keyboard on Android, not as iOS parity.
- The spring tables and projection formula come from Emil's skill, not from Apple documentation; cross-check against `apple-hig-liquid-glass` / Apple's sample code before treating them as platform values.
