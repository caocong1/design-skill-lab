## Key facts
1. **Scope.** "These instructions target GPT-5.5, but many of the patterns apply to other model versions as well." The page is one copy-paste prompt block, "Frontend guidance", in two parts: "Build with empathy" and "Design instructions". OpenAI's API changelog lists GPT-6.x models by 2026-11; this page still names GPT-5.5.
2. **Fit to the domain.** SaaS, CRM and other operational tools "should feel quiet, utilitarian, and work-focused rather than illustrative or editorial": no oversized hero sections, decorative card-heavy layouts or marketing-style composition; dense but organised information, restrained styling, predictable navigation, "built for scanning, comparison, and repeated action". A game may be illustrative, expressive, animated and playful. Existing designs and frameworks in context are followed.
3. **Controls by job.** Icons in buttons for tools, swatches for colour, segmented controls for modes, toggles or checkboxes for binary settings, sliders, steppers or inputs for numbers, menus for option sets, tabs for views; text buttons only for clear commands. Familiar symbols instead of text pills (undo and redo arrows, B / I); tooltips name unfamiliar icons; lucide icons when one exists, or the app's icon library.
4. **Named bans.** No in-app text that explains features, shortcuts or how to use the app; no landing page unless required ("build the actual usable experience as the first screen"); no card inside a card; page sections are not floating cards but "full-width bands or unframed layouts with constrained inner content"; cards only for repeated items, modals and framed tools, at **8 px radius or less** unless a design system says otherwise; no gradient orbs or bokeh blobs; no font size scaled with viewport width; "Letter spacing must be 0, not negative".
5. **One-note palettes.** "avoid UIs dominated by variations of a single hue family, and limit dominant purple/purple-blue gradients, beige/cream/sand/tan, dark blue/slate, and brown/orange/espresso palettes; scan CSS colors before finalizing and revise if the page reads as one of these themes."
6. **Heroes.** A relevant image, generated bitmap or full-bleed interactive scene as the background with text over it, not in a card; never a split layout with a card on one side; never a gradient or SVG hero page, nor an SVG illustration when a real or generated image can carry the subject. On branded, product, venue or portfolio pages the brand, product, place or object is "a first-viewport signal"; the H1 is the name or a literal offer, value props go in supporting copy; every viewport shows a hint of the next section.
7. **Assets and fit.** Websites and games "must use visual assets" (image search, known images, generated bitmaps); primary media show the actual product, place or state, not "dark, blurred, cropped, stock-like, or purely atmospheric" media; text fits its container on every viewport and never overlaps; hero-scale type only for true heroes; stable dimensions (aspect-ratio, grid tracks, min / max) so hover and loading states cannot shift layout; 3D in Three.js, full-bleed, verified with Playwright screenshots and canvas-pixel checks on desktop and mobile.
8. **GPT-5.4 guide (blog).** States the mechanism: underspecified prompts make models "fall back to high-frequency patterns from the training data", many of them "simply overrepresented habits". Tips: ask the model to generate a mood board or several visual options before choosing assets; give reference screenshots; define constraints up front, for example "one H1 headline, no more than six sections, two typefaces maximum, one accent color, and one primary CTA above the fold".
9. **GPT-5.4 guide rules.** "One composition: The first viewport must read as one composition, not a dashboard (unless it's a dashboard)"; **brand test**: "If the first viewport could belong to another brand after removing the nav, the branding is too weak"; typography: expressive fonts, "avoid default stacks (Inter, Roboto, Arial, system)"; **hero budget**: brand, one headline, one short sentence, one CTA group, one dominant image, and no stats, schedules, promos or metadata rows in the first viewport; cards "Default: no cards… If removing a border, shadow, background, or radius does not hurt interaction or understanding, it should not be a card". Hard rules include no hero cards, one dominant idea per section, no more than two typefaces or one accent colour without a reason. Litmus checks include "Would the design still feel premium if all decorative shadows were removed?"
10. **The bundled skill is gone.** The blog tells readers to install `frontend-skill` with Codex's skill installer; `openai/skills` added it on 2026-03-20 (`82d2c5b`) and removed the curated frontend and web-game skills on 2026-04-23 (`11c6438`, "Remove curated frontend and web game skills").
