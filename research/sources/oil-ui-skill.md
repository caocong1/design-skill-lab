## Key facts
1. **Scope.** "只负责设计判断": design, refine and review websites, apps, dashboards and components; not business logic, API work or fully specified small edits ("改文案、调数量、删指定元素", even when the request says "优化"). Host-neutral (Claude Code, Cursor, Codex, Windsurf, Cline, Antigravity, OpenCode); optional scripts need Python 3.10+ or Node 22+ with a local Chrome. Defers to a paid sibling `oil-ui-pro` when installed. Optional update check script (`scripts/check_update.sh`); its output is treated as data.
2. **Main line** (每一步留下明确结果，没过门槛不往后走): product facts (users, brand, task, real content, devices, assets, technical limits; product references and interaction references read separately) → one protagonist and one primary action per screen → material and concept (a new concept comes from a fresh subagent; candidates must not all derive from the same benchmark) → a **grey-scale wireframe of the main viewport**, reviewed by another independent reviewer before colour or type (structure that does not work goes back, not covered with colour) → implement one representative page or core flow with its key states first → review real screenshots at the target viewport.
3. **One direction by default.** Externally it recommends one direction and deepens it; several directions (three by default) only when the user asks to compare. The recommendation is three or four lines (feeling, first viewport, how the core action completes, type, colour, key visual) plus the reason, confirmed once; "你定" or an unattended run means build that one and write why.
4. **Scope routing table.** Small named edits are done directly with no exploration or review; new interfaces run steps 1–5; an existing product's UI optimisation may reset accidental visual defaults while keeping brand assets, whereas flow changes and new features keep the existing visual language; conflicting design documents are listed for the user, never merged or deleted by the agent; a prototype the user approved is a visual standard only (no iframe embedding, no copying its CSS into the product).
5. **Independent visual review** (`references/visual-review.md`): new interfaces and redesigns get a fresh subagent that scores 1–10 against the reviewer manual; polishing an existing interface gets a review against the existing system with no score; small edits get none. The reviewer receives current screenshots (and motion evidence) with viewports, the user's original task, constraints and the one-line north star; **not** source code, the author's defence or earlier scores. The author fixes from the top of the list; a "redo" finding sends the named block back to the direction card; a request to change a user-locked brand colour is declined with a reason; a stalemate of taste ends the loop with the best version kept.
6. **Lightweight UX walkthrough** (`references/ux-review.md`): when a page has a main flow (form submit, multi-step, anything that saves), a second fresh subagent operates the real page **without** the user cases, expected path, source or design notes, infers the goal itself and walks one main path; its findings are sorted into reproducible product problems, test-tool or data problems and unverified guesses. It "不代表真实用户": no success-rate, satisfaction or time claims. Without an operable page it is a static walkthrough and says so.
7. **Evidence rules.** "没看真实画面不算视觉验收"; check Chinese multi-line titles, body and narrow-screen wrapping at reading size; 100 % and 200 % zoom on key areas; saving interfaces are verified by reload and failure; no "示例" or "未接入" notes drawn into the UI (they go in the delivery note); no fabricated business results, testimonials or metrics.
8. **Claims (not reproduced).** The README shows one same-model, same-brief comparison, 83/100 and 5 of 6 checks without the skill against 88/100 and 6 of 6 with it, and links a "15-run blind test" page; both are the author's.

## What it changes for the skills
- research/topics/02: the closest peer to this suite's designer–implementer split and fresh critic, and the only Chinese-first one found. Two differences worth tracking, not adopting yet: one recommended direction by default (this suite shows an options board in `options` mode and lets the user choose), and splitting the visual reviewer from a UX walkthrough agent that is denied the expected path (critique-design walks the primary task itself, with the task stated in the brief).
- skills/critique-design/templates/critic-brief.md: its "do not give" list (source, the author's defence, earlier scores) matches ours; no change.
