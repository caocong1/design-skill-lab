## Key facts
Provenance
1. The six skills ship in the `example-skills` plugin of the `anthropic-agent-skills` marketplace (`.claude-plugin/marketplace.json`: 12 skills incl. frontend-design, skill-creator, webapp-testing). README: "provided for demonstration and educational purposes only"; product behaviour may differ.
2. Freshness: canvas-design, algorithmic-art, brand-guidelines, theme-factory and web-artifacts-builder have had no content change since the 2025-12-01 folder move (`ef74077`; only a LICENSE copyright fill on 2026-04-20). skill-creator last changed functionally on 2026-03-06 (`b0cbd3d`, optimiser no longer needs an API key). Only frontend-design moves (2026-09-03).
3. frontend-design exists in three byte-identical copies: `anthropics/skills`, `claude-plugins-official/plugins/frontend-design`, and `anthropics/claude-code/plugins/frontend-design` (the path Anthropic's prompting docs link to). Content: see `anthropic-frontend-design-skill`.

canvas-design (posters, art, static pieces → PNG/PDF)
4. Two artefacts in order: a "design philosophy" `.md` (movement named in 1-2 words, 4-6 paragraphs on space/form, colour/material, scale/rhythm, composition/balance, hierarchy, written generically without naming the subject), then the canvas: one page unless more are asked, "90% visual design, 10% essential text".
5. The brief's subject enters only as a "subtle reference" woven into form ("a jazz musician quoting another song").
6. Hard layout floor (§ Canvas creation): nothing overlaps, nothing falls off the page, every element inside the canvas with proper margins - "non-negotiable". Built-in house style: limited palette, "most of the time, font should be thin", systematic diagram language (dense repeated marks, reference markers, clinical type, "a diagram from an imaginary discipline").
7. Final pass (§ Final step): assume the user already said "It isn't perfect enough"; refine, do not add - if the instinct is to draw a new shape or call a new function, stop and make what exists more cohesive. Multi-page: pages as a coffee-table-book sequence.
8. `canvas-fonts/` bundles 29 families (54 font files, 27 OFL texts); no separate licence file for IBM Plex Serif or Instrument Serif. Overlap with Impeccable's lists (`impeccable`): Instrument Sans/Serif and Geist Mono are on its overused-font detector; IBM Plex, Crimson, Lora, Outfit on its training-data-default faces.
9. Tone: CAPS "CRITICAL", "Emphasize craftsmanship REPEATEDLY". Anthropic's own current guidance cuts against this: best-practices § Tool usage says Opus 4.5/4.6 may overtrigger on "CRITICAL: You MUST…" language; skill-creator calls all-caps ALWAYS/NEVER "a yellow flag".

algorithmic-art (p5.js generative art)
10. Philosophy `.md` → one self-contained HTML built from `templates/viewer.html` (598 lines). FIXED: header/sidebar layout, Anthropic branding (Poppins + Lora, `#141413` / `#faf9f5` / `#d97757` …), seed section (display, Prev/Next, Random, jump-to-seed), actions (Regenerate, Reset, Download PNG). VARIABLE: the algorithm, the `params` object, its controls, optional colour pickers.
11. Seeded randomness "Art Blocks pattern": `randomSeed(seed); noiseSeed(seed)`; the same seed must always give identical output; "100 variations" = seeds 1-100; optional seed presets and a Gallery Mode of thumbnails in the same file. p5.js 1.7.0 from cdnjs, canvas 1200×1200. Parameters are framed as quantities, scales, probabilities, ratios, angles, thresholds - "properties the system needs to be tunable", not pattern types.

brand-guidelines and theme-factory (lookup-table pattern)
12. brand-guidelines = Anthropic's brand as tokens + application rules: Dark `#141413`, Light `#faf9f5`, Mid Gray `#b0aea5`, Light Gray `#e8e6dc`; accents Orange `#d97757`, Blue `#6a9bcc`, Green `#788c5d`; headings ≥ 24 pt in Poppins (Arial fallback), body Lora (Georgia fallback); non-text shapes cycle orange → blue → green; applied through python-pptx `RGBColor`. The same `#D97757` is the accent frontend-design names as a tell ("Anthropic's own Claude-interaction accent").
13. theme-factory: 10 fixed themes, each 4 named hex + a header/body pair of system fonts (DejaVu Sans/Serif, FreeSans/FreeSerif). Flow: show `theme-showcase.pdf` unmodified → ask → wait for explicit confirmation → apply; if none fits, generate a theme and show it for review first. Example "Tech Innovation": `#0066ff`, `#00ffff`, `#1e1e1e`, `#ffffff`, DejaVu Sans. Names are not checked against values ("Sunset Boulevard" calls `#264653`, a dark blue-teal, "Deep Purple"); "ensure proper contrast" carries no threshold.

web-artifacts-builder (multi-component claude.ai artifacts)
14. `init-artifact.sh`: `pnpm create vite --template react-ts` (Vite latest on Node ≥ 20, 5.4.11 on Node 18; the SKILL.md "React 18" stack line is stale - today's `create-vite` 9.2.1 `template-react-ts/package.json` pins `react ^19.2.8`, `vite ^8.3.0`, `typescript ~6.0.2`, npm registry checked 2026-09-27), Tailwind 3.4.1 + tailwindcss-animate, shadcn theming (stock neutral theme, `--radius: 0.5rem`), 43 shadcn component files from a bundled tarball (SKILL says "40+"), lucide-react, next-themes. `bundle-artifact.sh`: Parcel build without source maps → `html-inline` → one `bundle.html`.
15. Design guidance is a single line: avoid excessive centred layouts, purple gradients, uniform rounded corners and Inter. Testing is optional and deferred: "avoid testing the artifact upfront as it adds latency".

skill-creator (the eval loop)
16. Loop: capture intent → interview → draft → 2-3 realistic prompts in `evals/evals.json` (assertions drafted while runs execute) → spawn with-skill and baseline runs in the same turn (baseline = no skill for a new skill; a snapshot copy of the old skill when improving) → `<skill>-workspace/iteration-N/<eval-name>/{with_skill,without_skill|old_skill}/outputs/`.
17. Timing: `total_tokens` and `duration_ms` arrive only in the subagent completion notice - write `timing.json` immediately. `scripts/aggregate_benchmark.py` → `benchmark.json/.md` with pass rate, time and tokens as mean ± sample stddev (n − 1) plus the with/without delta; `eval-viewer/generate_review.py` serves a two-tab viewer (Outputs with a feedback box and the previous iteration; Benchmark) or `--static` HTML; feedback lands in `feedback.json`; empty feedback = fine.
18. Subjective work: skills with subjective outputs (writing style, art) "often don't need" test cases; "Subjective skills (writing style, design quality) are better evaluated qualitatively - don't force assertions onto things that need human judgment". Checkable assertions should be scripts, not eyeballing.
19. Grader (`agents/grader.md`): PASS needs evidence of genuine completion, not surface compliance (right filename, wrong content = FAIL); "the burden of proof to pass is on the expectation"; also extracts and verifies the output's own claims and critiques the evals (flag assertions a wrong output would also pass). Fields `text`, `passed`, `evidence` are required by the viewer.
20. Blind comparator (`agents/comparator.md`): judges A vs B without knowing which skill made which; builds a task-specific rubric - content (correctness, completeness, accuracy) and structure (organization, formatting, usability), each 1-5, overall 1-10; assertions are secondary evidence; "ties should be rare". The analyzer then unblinds: reads both skills and transcripts, scores instruction-following 1-10, lists prioritised fixes. Benchmark analysis flags assertions that always pass (or always fail) in both arms as non-discriminating, and high variance as flaky.
21. Improving: generalise from feedback instead of overfitting to the test prompts; keep the prompt lean and read transcripts, not only outputs; explain the why; if every run wrote the same helper script, bundle it in `scripts/`.
22. Description optimisation: 20 realistic queries (8-10 should-trigger, 8-10 should-not, near-misses preferred over obviously irrelevant ones), reviewed by the user in `assets/eval_review.html`. `run_loop.py` defaults: stratified 60/40 train/test split (`--holdout 0.4`, seed 42), 3 runs per query, trigger threshold 0.5, 30 s timeout, 10 workers, up to 5 iterations; best description chosen by test score. Triggering is measured by writing the description to a temporary `.claude/commands/<name>-skill-<uuid>.md` and running `claude -p` with stream-json. Claude "only consults skills for tasks it can't easily handle on its own", so one-step queries are poor tests.
23. Description rules (`improve_description.py`, `quick_validate.py`, agentskills.io spec): ~100-200 words, hard limit 1024 characters, no `<` or `>`; imperative ("Use this skill for…"), about user intent, distinctive; categories of intent, not lists of queries. Skill-creator also says make descriptions "a little bit pushy" because Claude tends to undertrigger. Spec: `name` ≤ 64, kebab-case, matches the folder; `compatibility` ≤ 500; allowed keys `name, description, license, allowed-tools, metadata, compatibility`; `metadata` maps string → string; metadata ~100 tokens, body < 5000 tokens, SKILL.md < 500 lines. The "reference files > 300 lines get a table of contents" rule is skill-creator's (SKILL.md § Progressive Disclosure), not the spec's. `disable-model-invocation` is not in the spec's key set (quick_validate rejects it).

playground plugin (claude-plugins-official)
24. A single HTML file: controls on one side, live preview updating on every change (no Apply button), a prompt at the bottom written as a natural instruction that mentions only non-default choices (qualitative words alongside numbers), a copy button, 3-5 named presets, dark UI chrome. The design template maps decisions to controls: slider for sizes/spacing/radius (e.g. radius 0-24 px), toggle, dropdown (font, easing), HSL sliders for colour, clickable cards for layout structure, viewport-width slider for responsive; preview on light and dark.

Published prompting guidance on design defaults
25. Best practices § Frontend design: a `<frontend_aesthetics>` snippet identical to the cookbook's distilled prompt (typography, colour/theme with CSS variables and "dominant colors with sharp accents", motion with one staggered page load, layered backgrounds; avoid Inter/Roboto/Arial/system fonts and purple-on-white; "You still tend to converge on common choices (Space Grotesk, for example)").
26. Opus 4.8 guide names its house style: warm cream/off-white (~`#F4F1EA`), serif display (Georgia, Fraunces, Playfair), italic word-accents, terracotta/amber accent - in slide decks and web UIs; fine for editorial, hospitality, portfolio; off for dashboards, dev tools, fintech, healthcare, enterprise. Generic instructions ("don't use cream") shift to another fixed palette. Two reliable levers: a concrete spec, or options before building ("propose 4 distinct visual directions … bg hex / accent hex / typeface - one-line rationale … implement only that direction").
27. Sonnet 5 guide: same levers; its diagnosis says only that the model "may settle into a consistent default visual style" and does not name that style (no cream/serif description as in the Opus 4.8 guide). Non-default `temperature`/`top_p`/`top_k` return HTTP 400 on Sonnet 5, so options-first is "the recommended way to produce meaningfully different design directions across runs". The concrete-spec example (the same "AEFRM" prompt appears in both the Opus 4.8 and Sonnet 5 guides) fixes a 5-value tonal range (`#E9ECEC, #C9D2D4, #8C9A9E, #44545B, #11171B`), a 4 px radius on cards, buttons, inputs and media frames, typeface character, section order and hover timing. Same guide: finding-stage review prompts should ask for coverage and leave filtering to a later step.
28. Opus 5.5 guide § Frontend design defaults: without direction it falls back on "a few default styles"; "avoid a generic AI look" mostly swaps one default for another; it "responds well to instructions that name specific patterns to avoid"; work iteratively - see which style the first result used and extend the list. Example list: cream/off-white background, italic accent words in headlines, numbered "01/02/03" section labels, monospace labels, pill-shaped buttons.
29. Cookbook: three strategies (guide specific dimensions; reference inspirations such as IDE themes or cultural aesthetics; call out defaults) plus isolated prompts: typography-only (never Inter, Roboto, Open Sans, Lato, system fonts; picks by mood incl. "Startup: Clash Display, Satoshi, Cabinet Grotesk"; weights 100/200 vs 800/900; size jumps 3x+; one distinctive font, name it before coding) and a theme lock (Solarpunk). Model in code: `claude-sonnet-4-6`.
30. Claude Design (Anthropic Labs, research preview, 2026-04-17, Opus 4.7): builds a team design system from the codebase and design files at onboarding (more than one per team allowed); inputs text, images, DOCX/PPTX/XLSX, codebase, web capture; refine by inline comments, direct text edits, Claude-made adjustment knobs for spacing, colour, layout; exports Canva, PDF, PPTX, standalone HTML; a handoff bundle for Claude Code; off by default on Enterprise.

## What it changes for the skills
- skills/design-studio/references/fundamentals/anti-slop.md: the vendor now publishes per-model defaults (facts 26, 28). Keep "generic avoid-instructions swap one default for another" and add the Opus 5.5 method: name concrete patterns, check the first render against them, extend the list. Date every list by model.
- skills/design-studio/references/process/directions.md: options before building is Anthropic's own variety lever (sampling is fixed on Sonnet 5). A direction card carries at least bg hex, accent hex, typeface and a one-line rationale. Philosophy-before-pixels (fact 4) and seed-as-exploration-unit (fact 11) back the direction thesis and `scripts/seed.py`.
- skills/design-studio/references/process/system.md: theme-factory is the anti-pattern (subject-free lookup table, unverified names, no contrast numbers). brand-guidelines shows the useful shape: token table + application rules keyed to element and size + fallback fonts.
- skills/design-studio/references/disciplines/graphics.md: two artefacts (thesis, then canvas); containment floor (fact 6); one refine-not-add pass; for generative work, a fixed viewer chrome with seed navigation. Do not ship a bundled font folder as a default set.
- skills/design-studio/references/fundamentals/licensing.md: any bundled font ships with its licence file; audit bundles (fact 8).
- skills/design-studio/references/process/render-and-look.md: web-artifacts-builder defers testing for speed; this suite renders before delivery. Keep that and say why (the designer's output is the rendered image).
- skills/critique-design/templates/critic-brief.md and references/rubric.md: the critic gets outputs without author identity or reasoning; surface compliance fails; the burden of proof sits on the criterion; pairwise verdicts are decisive (ties rare).
- skills/*/SKILL.md frontmatter: keep `description` ≤ 1024 characters (spec and validator; Claude Code's 1536 is host-specific), no angle brackets, quote `metadata.version` as a string; `disable-model-invocation` is a Claude Code extension, so only iterate-design-lab uses it.
- skills/implement-design/references/stacks.md: the single-file bundle recipe for artifact hosts (Vite + Parcel + html-inline); the stock shadcn theme is itself a default that tokens must override.
- evals/ (EVALS stream): with-skill vs baseline in the same turn, a 0.7.0 snapshot as the old-skill arm, timing captured from completion notices, non-discriminating assertion review, trigger eval with 3 runs per query, 0.5 threshold, held-out selection; judge design quality qualitatively and pairwise, not with forced assertions.
