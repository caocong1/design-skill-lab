# 实战记录：用套件给自己做实验室页面（2026-09-21 至 09-23，三轮）

> 类型：field evidence（实战记录，不是评测）· 事件时间：2026-09-21 至 2026-09-23 · 整理：2026-09-27 · 证据等级：作者自评 + 2026-09-27 独立审计复测
> 前身：0.8.0 之前的第 12 篇分析（1.2 版，已随旧分析目录删除，全文可在 git 提交 `f5c0421` 中查看）。本篇保留其中经得起复测的现场教训，并把审计证伪的说法逐条更正（见"2026-09-27 审计更正"）。

## 这是什么

用户要求用套件自己的方法，给仓库做一个页面，至少能切换九种风格。这是套件第一次用在真实任务上。它没有对照组，评审就是作者本人。它的价值在于留下了一条可以核对的过程链：看图发现问题，查到原因，再写成规则。2026-09-27 的独立审计同时说明了自评漏掉了什么。

## 第一轮（2026-09-21）：十个方向，同一份 DOM

**Design read**：一个常被打开的工作索引，用来快速找到某个设计资源，再附一段套件导览。读者是维护者本人和来访的开发者、设计师。密集列表优先于卡片，所有风格的内容完全相同。

**硬约束**：静态页面、不需要构建、离线可用；不用 Web 字体（维护者的网络访问字体 CDN 不可靠）；约 600 行的列表在每种风格下都要能用；文字对比度达到 WCAG AA。

**选轴**：字体气质、色彩策略、版式语法、密度、形状、层次。刻意不把"配色"单列成一条轴，因为只换配色就是套件自己禁止的换皮方案。

**取材**：方向不从"流行风格列表"里挑，而从主题本身的世界里找。一个设计参考资料馆会让人想到色卡本、瑞士海报、目录学书目、终端、工程蓝图、图书馆卡片柜、美术馆展签、机房控制台、贴纸墙，还有"什么都不设计"的素页。

每个方向都带一张说明卡：一句话概念、各轴取值，以及**它会在哪里失败**。实现方式是一套 DOM，在 `html[data-style]` 作用域下重写 token 并重排布局，所有版式差异都用 CSS 完成。

**看图抓到、只读 CSS 很难发现的问题**：贴纸风格的"全部"按钮白底白字（选择器优先级压过了按下态）；卡片柜的重复渐变线穿过卡片标题；半透明切换器让下面的下拉框透出来，像一个"幽灵按钮"；说明卡把页眉网格行撑得忽高忽低；授权信息里的长字符串不换行。还有两个截图工具陷阱：无头 Chrome 会继承系统深色模式；窗口宽度下限是 500 px。

**缩略图测试**：把十张截图缩到约 640 px 宽拼在一起看，分不清的两张就是同一个方向。这一轮十张都能一眼分开，差异来自版式和字体，而不只是颜色。

## 第二轮（2026-09-22）：两个线上 bug，五个新方向，在线字体，WebGPU 小岛

**入场动画"播两遍"。** 数 `animationstart` 次数，每个元素只有一次。改用 rAF 逐帧记录一张贴纸的计算不透明度，才看到 0 → 1 → 0 → 1：关键帧最后一帧没写 `opacity`，浏览器把它插值回等待态类上的 `opacity: 0`；脚本在 `animationend` 里摘掉类名后，元素又跳回 1。同一处还有两个同源问题：关键帧在 `transform` 里旋转，元素又设了 `rotate`，两者叠加；hover 抖动用第二个类顶掉了 `animation` 简写，抖完后入场动画从头重播。教训：要看被动画属性每一帧的值，数事件看不出插值问题。

**中文字形、粗细、基线不一致。** 圆体字体栈把日文圆体 Hiragino Maru Gothic ProN 放在所有中文字体前面。字体是按字符回落的：它收录的汉字全用日文字形排出来，而且单一字重被合成加粗；它没有的简体字（设、认、这……）才漏给下一款中文字体。结果一行字里出现两种字形、两种粗细、两条基线。这个栈正是套件自己字体参考表里给的，所以是 dogfooding 抓到了套件本身的错误。

**五个新方向**（后台、画板、对话、字样、线路图）。取材换成了套件自己要做的事。后台是唯一"按要求做常规样子"的方向：brief 要熟悉的东西时，就交出它最好的版本。每个新方向的失败点都写在说明卡上。看图又抓到几处问题：`overflow-x: auto` 包裹层里的粘性表头压住第一行；纵向 flex 的直接子项被拉成整行；样字和度量线标签互相遮挡；SMIL 列车在动画开始前停在 SVG 原点。

**在线字体。** 用户后来要求改用公用在线字体。做法不是推翻"不用 Web 字体"这条约束，而是把它降级成回落：托管字体（jsDelivr 上的 npm 包，中文用只下载所需 unicode 区段的分包字体）放在最前，系统栈留在后面。CDN 不通时，页面回到上一轮的样子。

**第十六个方向：WebGPU 小岛。** 设计负责的部分是美术指导、HUD、动效人格，以及那个记忆点（十二座小屋就是十二个域）。引擎代码属于实现，只是这一页恰好也自己实现了。无头 Chrome 截不到 WebGPU 画布，所以模块加了离屏渲染、回读像素的 `snapshot()`。还有一个环境陷阱：无头 Chrome 的软件 WebGPU 会在第一帧后报 `device.lost`（reason 为 `destroyed`），但设备其实还在渲染。

## 第三轮（2026-09-23）：把过程收成规则

- **看图要量，不要信转述。** 线路图的站标在几何上离线路不到 2 px，但在竖向路线里它们对齐的是"站名 + 说明"整行的中点，比站名低约 30 px，看起来就像点掉到了线下面。只看总览截图或听一句"看起来都在线上"，都会放过这个问题。对齐问题要比较标记的盒子和笔画、和标签的第一行；动效问题要看被动画属性每一帧的值。
- **图上的点是标注。** 站标对齐它命名的那一行字；线要盖住首尾站标的全身；所有点画在所有线之后；点和线同粗同色时，点会消失在线里。
- **换一个整页视图，滚动必须回到起点。** `overflow: hidden` 藏起了滚动条，但 `scrollY` 还留着；View Transitions 结束时还会把旧的滚动位置写回来。
- **约束降级，不翻转。**
- **沿路径运动用 `offset-path`**，让第一帧就在线上，不要把 SMIL 当唯一手段。
- **方向数量不要写死。** 数字键只能覆盖十个方向，`n % 10` 的标签在第十一个方向上会显示成 1。

审计还发现了自评范围之外的问题：禁用 JS 时页面是空白（`innerText` 长度为 0）；三个方向在 `main#app` 里又渲染了一个 `<main>`；没有跳转链接；十三个方向的切换器会让键盘用户先 Tab 过最多 16 个链接；声明了 `color-scheme: light dark`，却没有任何深色配色。

**这次更正本身的教训：**

1. **对比度要在渲染后的页面上量，不能按 token 表手工列举。** 层叠、透明度、继承产生的颜色对不在 token 表里。0.8.0 的 `skills/design-studio/scripts/lint.mjs` 按渲染结果计算文字对比度，文字下方的背景是采样得到的。
2. **一句"已核验"只对它当时测的那个版本成立。** 页面一重建，结论就要重跑；结论里应该写上测的是哪个提交。
3. **自评的局限真的应验了。** 第一轮就写下的"评审者就是作者"这个局限，这次被独立审计坐实：问题都是新眼光找到的。

## 仍然成立的现场教训

- **缩略图测试**和**说明卡上写"会在哪里失败"**：审计把它们列为应当保留的做法。
- **看图要量**：比较盒子和笔画、逐帧读属性值；截图的文字转述不能代替测量。
- **约束降级，不翻转**：托管字体放在最前，系统栈留作回落；只下载用到的 unicode 区段；单字重的中文字体要关闭合成加粗。
- **日文字体不能排在中文伴随字体之前**（按字符回落）。
- **关键帧每一帧都要写全被动画的属性**；`transform` 与 `rotate` 会叠加；第二个动画类会顶掉正在进行的入场动画。
- **同一份内容可以换一种器具单独挂载**，但要有共享的外壳和数据层。否则就会像 `e09b19b` 之后那样，每个方向各复制一遍整页，改一处要改十六遍。
