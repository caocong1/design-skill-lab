# Motion tokens and springs

Springs first: they retarget from the current position and velocity when interrupted, and one pair
of numbers means the same thing on every platform. Durations and curves remain for CSS moments
nobody interrupts and for systems that are curve-based. Decisions (whether to move, which posture,
reduced motion): [motion](motion.md). Copy the structure; take the values from the posture and the
chosen direction, never because they are listed here.

## 1. One spring, four notations

| Notation | Parameters | Conversion |
| --- | --- | --- |
| physics (Material, Compose, ArkUI) | damping ratio ζ, stiffness k, mass 1 | k = (2π / d)², ζ = 1 - bounce |
| perceptual (SwiftUI, UIKit, Flutter) | duration d, bounce | d = 2π / √k, bounce = 1 - ζ (ζ ≤ 1; overdamped ζ > 1 gives bounce = 1/ζ - 1) |
| peak overshoot | - | e^(-ζπ / √(1 - ζ²)); none at ζ = 1 |
| CSS | `<T> linear(...)` | the spring sampled over its settle time T (within 0.1% of travel for good); T is 1.3-1.7 x d |

The perceptual d is how long the motion feels; T is how long CSS must run to land without a jump.
The curve's shape depends only on ζ, so one `linear()` per damping ratio serves every stiffness;
only T changes.

```text
Compose      spring(dampingRatio = ζ, stiffness = k); in Material apps read MaterialTheme.motionScheme
SwiftUI      .spring(duration: d, bounce: b); presets .smooth / .snappy / .bouncy
UIKit        UIView.animate(springDuration: d, bounce: b) { ... }
Flutter      SpringDescription.withDurationAndBounce(duration: d, bounce: b)
             (older SDKs: SpringDescription(mass: 1, stiffness: k, damping: 2ζ√k))
ArkUI        curves.springMotion(response: d, dampingFraction: ζ)
Motion (JS)  { type: "spring", stiffness: k, damping: 2ζ√k, mass: 1 }. Its visualDuration is scaled
             by 1.2 internally (visualDuration = d / 1.2) and its default bounce is not 0.
CSS          transition: transform <T> linear(...); a retarget restarts the curve (no velocity hand-off)
DTCG         no spring type: see §6
```

Library defaults were read in their current sources on 2026-09-27 (SwiftUI docs, Flutter API, Motion
`main`); check the installed version before relying on them.

## 2. The springs

| M3 expressive, fast spatial | 0.6 | 800 | 222 ms | 0.4 | 9.5% | 360 ms |

| M3 effects (both schemes), fast / default / slow | 1.0 | 3800 / 1600 / 800 | 102 / 157 / 222 ms | 0 | 0 | 150 / 231 / 327 ms |
| SwiftUI `.smooth` (d 0.5 s) | 1.0 | 158 | 500 ms | 0 | 0 | 735 ms |
| SwiftUI `.snappy` (d 0.5 s) | 0.85 | 158 | 500 ms | 0.15 | 0.6% | 697 ms |
| SwiftUI `.bouncy` (d 0.5 s) | 0.7 | 158 | 500 ms | 0.3 | 4.6% | 819 ms |

- Material ζ and k are data from the Compose token files; d, bounce, overshoot and T are derived
  here. Material says values vary by device class (wearable, phone, tablet); only phone values are
  public. The scheme is chosen per product, never written into the token name.
- **Spatial** springs (position, size, rotation, corner radius) may overshoot. **Effects** springs
  (colour, opacity) never do. A pressed button uses fast spatial for its shape and fast effects for
  its colour.
- **Speed by coverage**: fast for small components (switch, button, chip), default for partial-screen
  motion (menu, sheet, rail), slow for full screen.
- SwiftUI presets take a duration (`.snappy(duration: 0.3)`); scale T by the same factor.

`linear()` is Baseline widely available (since 2026-06-11). A host system that keeps duration and
easing apart ([tokens.css](../../templates/tokens.css)) splits each token into `--duration-*` and
`--ease-*`. Material also publishes cubic-bezier stand-ins for its springs; `linear()` is closer.

### 2a. Any other spring

```js
// "<T> linear(...)" for a CSS transition or animation. Mass 1, from rest, 0 <= zeta <= 1.
function springCSS(zeta, stiffness, eps = 0.001, tol = 0.0025) {
  const w = Math.sqrt(stiffness), wd = w * Math.sqrt(1 - zeta * zeta);
  const x = t => zeta < 1
    ? 1 - Math.exp(-zeta * w * t) * (Math.cos(wd * t) + (zeta * w / wd) * Math.sin(wd * t))
    : 1 - (1 + w * t) * Math.exp(-w * t);
  let T = 0;
  for (let t = 0; t < 5; t += 5e-4) if (Math.abs(x(t) - 1) >= eps) T = t;
  T += 5e-4;
  const pts = Array.from({ length: 1001 }, (_, i) => [i / 1000, i === 1000 ? 1 : x((T * i) / 1000)]);
  const keep = (a, b) => { // Ramer-Douglas-Peucker on the progress error
    let worst = 0, k = -1;
    for (let i = a + 1; i < b; i++) {
      const [p, v] = pts[i], [p0, v0] = pts[a], [p1, v1] = pts[b];
      const d = Math.abs(v - (v0 + ((v1 - v0) * (p - p0)) / (p1 - p0)));
      if (d > worst) { worst = d; k = i; }
    }
    return worst > tol ? [...keep(a, k), ...keep(k, b).slice(1)] : [a, b];
  };
  const idx = keep(0, 1000);
  const stops = idx.map((i, n) => n === 0 ? "0" : n === idx.length - 1 ? "1"
    : `${+pts[i][1].toFixed(3)} ${+(pts[i][0] * 100).toFixed(1)}%`);
  return `${Math.round(T * 1000)}ms linear(${stops.join(", ")})`;
}
// springCSS(0.8, 380) -> "435ms linear(0, 0.007 1.4%, ...)"; from (d, bounce): springCSS(1 - bounce, (2 * Math.PI / d) ** 2)
```

Run it with `node -e` or in the browser console.

## 3. Durations and curves

For CSS moments that are not springs, and for curve-based systems.

| Token | Range | For |
| --- | --- | --- |
| `instant` | 0-50 ms | selection highlight; the press state itself appears within a frame |
| `fast` | 100-160 ms | press scale, hover colour, toggle, tooltip (125-200) |
| `base` | 150-250 ms | dropdown and select, popover, toast, small expand |
| `slow` | 250-400 ms | dialog, drawer, sheet (up to 500 for a large drawer) |
| `deliberate` | 450-700 ms | a full-screen or explanatory transition the user chose to watch |

Exits take 70-80% of the entrance. Most UI motion stays under 300 ms.

```css
:root {
  --ease-out:      cubic-bezier(0.23, 1, 0.32, 1);  /* enter, open, respond (Emil Kowalski) */
  --ease-in-out:   cubic-bezier(0.77, 0, 0.175, 1); /* move from A to B on screen */
  --ease-drawer:   cubic-bezier(0.32, 0.72, 0, 1);  /* iOS-like sheet and drawer */
  --ease-standard: cubic-bezier(0.2, 0, 0, 1);      /* M3 legacy standard */
  --ease-decel:    cubic-bezier(0.05, 0.7, 0.1, 1); /* M3 legacy emphasized enter */
  --ease-accel:    cubic-bezier(0.3, 0, 0.8, 0.15); /* M3 legacy emphasized exit, leaving for good */
}
```

- `linear` only for constant processes (spinner, progress, marquee, hold-to-confirm) and for opacity
  paired with an eased transform. The keyword `ease-in` and `ease-in-out` curves are too weak for UI.
- `cubic-bezier(0.16, 1, 0.3, 1)` is the expo-out that ships in most AI-built pages; choose a curve
  from the personality, not by habit.
- **Material legacy durations**: short 50-200, medium 250-400, long 450-600, extra long 700-1000 ms;
  duration grows with area and travel. Material now treats curves as the fallback to springs.
- **Windows (Fluent)**: direct entrance `cubic-bezier(0,0,0,1)` at 167 / 250 / 333 ms; point to point
  `(0.55,0.55,0,1)` at the same durations; direct exit `(0,0,0,1)` 167 ms, always with a fade; gentle
  exit `(1,0,1,1)` 167 ms; fade 83 ms linear. Fluent web (React v9) durations: 50, 100, 150, 200, 250,
  300, 400, 500 ms.

## 4. Patterns

| Pattern | Spec |
| --- | --- |
| Press | `scale(0.97)` on `:active`, `fast`, ease-out; colour on an effects spring |
| Menu, popover | opacity 0 > 1 and scale 0.95-0.97 > 1 from the trigger, spatial-fast + effects-fast (or <= 150 ms ease-out); usable at once; exit faster, no overshoot |
| Tooltip group | first after a hover delay; neighbours instant with no transition while the group is active |
| Dialog | scrim fade `base`; panel opacity + scale 0.96 > 1 or an 8-16 px rise, `slow` or spatial default; centred, no origin |
| Sheet, drawer | translate from its edge, spatial default or slow, or `--ease-drawer`; draggable ones follow the finger and settle on a spring with the release velocity |
| Toast | 8-16 px from its edge + fade, `base`; stack reflow animated; leaves by the same edge; auto-dismiss pauses on hover and focus |
| Collapse, expand | `grid-template-rows: 0fr > 1fr` or `::details-content`, `base`; content fades in slightly after |
| List insert, remove, reorder | FLIP or a view transition, spatial default; stagger 30-50 ms capped near 300 ms: `sibling-index()` for a list that enters as a whole, the index within the batch for inserts |
| Skeleton to content | cross-fade `fast`; shimmer slow and faint, or none |
| Page, view | fade-through, or shared axis 8-24 px, spatial slow; a shared element when one object continues |
| Number change | cross-fade or roll the digits, `base`, tabular figures |
| Streaming AI text | lines or chunks fade in over `fast`; nothing moves sideways; scroll stays anchored |

## 6. Tokens in JSON

DTCG 2025.10 has `duration`, `cubicBezier` and `transition` (duration, delay and timing function all
required), but no spring type and no `linear()`. Keep springs as numbers under `$extensions` with a
reverse-domain key, and the CSS form alongside. Format, resolver and modes:
[system](../process/system.md).

```json
{
  "motion": {
    "spatial-default": {
      "$type": "duration",
      "$value": { "value": 317, "unit": "ms" },
      "$description": "M3 standard default spatial spring; CSS curve --p-spring-z09",
      "$extensions": { "com.example.spring": { "dampingRatio": 0.9, "stiffness": 700 } }
    }
  }
}
```
